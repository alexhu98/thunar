PR #79: Drop on a tab, double-click a tab to go up

Branch 19-tab-bar-actions → main, closes #19 and #24. Once merged, files dropped on a tab's label land in that tab's folder, as in Nemo, and a double-click on a tab opens its parent folder. Two new Preferences checkboxes control the tab bar.

Part 1

What this PR adds

Each tab's label becomes a drop target for files, and the tab bar of each pane reacts to a left double-click by running the existing Open Parent action. All of it lives in thunar-window.c, plus two checkboxes in Preferences.

added by this PR existing Thunar code, reused you

The big picture

Nemo lets you drop files straight onto a tab, and Thunar made you hover until the tab opened, then drop in the view. Separately, once a list view's rows fill the pane, there's no blank space left for the double-click to go up from #3. Every pane has a tab bar, so it becomes the place for that double-click. Both changes reuse what Thunar already has: the path bar's drop code and the Open Parent action.

The tab label only takes file drags. A tab you drag to reorder, or to move into the other split-view pane, is a different kind of drag, so the label turns it down and the tab bar handles it as before.

Step by step (numbers match the diagram)

① #19 Drop files on a tab label
  1. Drag files. Any drag that carries a list of files (text/uri-list) counts: from a Thunar view, the desktop or another app.
  2. Label checks. thunar_window_notebook_insert_page makes each tab's label box a drop target. While the drag moves over it, the label fetches the file list, highlights itself and asks thunar_file_accepts_drop which actions the tab's folder allows. A 500 ms timer switches to the tab, because the label now gets the drag before the tab bar's own hover switch would.
  3. Drop. On release the label asks for the files again (GTK clears them just before the drop), shows the Copy / Move / Link menu for a middle-button drag via thunar_dnd_ask, and runs thunar_dnd_perform. These are the same calls the path-bar buttons use in thunar-location-button.c.
  4. Tab's folder. The target is the folder the tab currently shows. The folder and the label are held while the ask menu is open, so closing the tab meanwhile can't crash Thunar.
② #24 Double-click the tab bar
  1. Double-click. The first press already makes the clicked pane active and the clicked tab current, as before. The double-click arrives as an extra "2-button press" event.
  2. Tab bar checks. thunar_window_notebook_button_press_event already swallowed that event so the divider wouldn't recentre. It now goes on only if misc-double-click-tab-go-up is on, no Ctrl, Shift or Alt is held, and the press landed on the tab bar itself, not on the close button or inside the folder view. It finds the tab under the pointer the same way middle- and right-click do.
  3. Open Parent. The tab under the pointer is made current, or on the empty bar the current tab stays, and the existing Open Parent action runs on it. Only that pane changes. At / the action finds no parent and does nothing.
  4. Preferences. Preferences → Behavior → Tabs and Windows gets "Double-click on a tab to open the parent folder" (default on) and "Always show tabs, even with only one open", the hidden misc-always-show-tabs setting. The window now listens for that setting, so tab bars appear and hide at once.

Code review

Before the first code push, a fresh general-purpose agent in this session, given only the diff and the two issues, reviewed it at high effort: 0 high, 2 medium and 3 low findings. Both mediums and one low are fixed; the build and verify/19.sh were run again after the fixes.

  • Fixed, medium: a quick double-click on the tab bar's scroll arrows, or on the spot of a tab scrolled out of view, could take a tab up. Hidden tabs are now skipped, and the empty-bar case only counts when every tab is in view.
  • Fixed, medium (test): with #3's blank-space double-click on, a click that missed the tab bar could still go up and pass. verify/19.sh now turns that setting off first.
  • Fixed, low: a file list that arrives after the pointer left a tab could linger into the next drag's cursor. Late replies are now dropped.
  • Kept, low: the always-show-tabs listener is released the same way as the split-pane listener next to it, and one shot's wording credits the switch to the double-click, though the first press already does it.

CI's review of dc098a0 found 10 lows, R1 to R10. It fixed R1 itself: the label now lights up only when the folder accepts the drop. The next push fixes R2, R3, R4, R6 and R7. It requests the file list once per hover, shares one tab lookup, which now skips hidden tabs, between double-, middle- and right-click, drops a dead check, skips the drop if the tab closed during the ask menu, and releases the always-show-tabs listener earlier. R5 (the copied drop code, as #19 asked), R8 (default on, as #24 asked), R9 (no empty tab bar to test while tabs fill the bar) and R10 (the standard property doc block) were accepted by the owner. CI's review of that push found two more lows and fixed them itself: R11 (the tab lookup now returns the page) and R12 (a flatter motion handler). Its next review found seven more lows, none confirmed: R13 to R16 stay as reported, and R17, R18 and R19, style points in the new tab lookup whose callers already check for no tab, are accepted. The full list is in the code review PR comment.

Glossary

Tab label
The part of a tab with the folder name, spinner and close button.
text/uri-list
The drag format for a list of files.
Ask menu
The Copy / Move / Link Here menu a middle-button drop opens.
Split view
Two folder panes side by side in one window (F3), each with its own tabs.
2-button press
The extra event GTK sends on the second press of a double-click.
xfconf
Xfce's settings store; Thunar's preferences live in its thunar channel.
Xvfb
A virtual X display with no screen, used to run Thunar in tests.
xdotool
A tool that moves the pointer, clicks and types into X windows from a script.
