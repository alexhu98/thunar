PR #107: Split view opens at 50/50, and --split PERCENT

Branch 40-split-ratio → main, closes #40 and #41. Every new split view now opens centered instead of at the last dragged pixel position, and thunar --split 60 opens a new window split 60/40.

Part 1

What this PR adds

A new split view starts at a ratio of the pane's real size, 50/50 by default or the percentage given with --split, set in thunar-window.c and thunar-application.c.

every new split (#40) the --split option (#41) you

The big picture

Split view shows two folders side by side, with a divider between them. Until now Thunar saved the divider's position in pixels after every drag and reused it for every new split, whatever the window's size, so after one drag in a wide window every later split opened lopsided. Now each new split opens in the middle, a drag only affects its own window, and --split asks for an uneven split for one new window.

The ratio is set when the split pane gets its size, not straight away. GTK rescales a divider set earlier by the new size over its last size, and that last size can be left over from an earlier split, which would put the divider in the wrong place.

Step by step (numbers match the diagram)

① #40 A new split view opens at 50/50
  1. Split turns on. F3, the toolbar button, a window that opens with split view already on, and restored tabs all go through thunar_window_split_view_add in thunar-window.c.
  2. Pick the start. It reads the new hidden setting misc-remember-split-position, off by default. Off, it queues a 50/50 split. On, it uses the saved last-splitview-separator-position in pixels, as upstream Thunar does.
  3. Apply on resize. thunar_window_paned_notebooks_queue_split waits for the split pane's next size-allocate; then _apply_split sets the divider to the pane's width times the percentage, or its height in vertical split, and stops listening.
  4. You drag it. The divider stays where you put it for that window's life, also after you add or close tabs. It's saved only with the setting on, checked at each drag, and only when you let go of the divider itself or move it with the keyboard, so turning the setting on or off takes effect with a split already open. Closing split view drops any ratio still waiting. Double-clicking the divider still centers it.
② #41 thunar --split PERCENT
  1. Read the value. thunar_application_parse_split accepts a whole number from 10 to 90. Anything else prints “Thunar: --split takes a percentage from 10 to 90”, exits with an error and opens nothing. --help lists --split=PERCENT.
  2. Always a new window. --split forces a new window, even with Thunar running and Open new windows as tabs on, one window per folder. The value travels with that launch or tabs request, never on the application, so other windows and later commands don't see it.
  3. Split that window. thunar_window_open_split stores the percentage on that window and turns split view on, with the same folder in both panes, so step 3 applies it. It never changes a saved setting.

The cases, one by one

F3 by default

Opens at 50/50, even when a pixel position is saved. The saved value is left alone.

Hidden setting on

misc-remember-split-position true brings back upstream: F3 opens at the saved pixels, and a drag saves the new spot.

Vertical split

With misc-vertical-split-pane on, the same rules apply by height: 50% by default, the top pane's share with --split.

With -t and -T

-T turns split on, at --split's percentage. With -t alone, the right pane opens on the first tab.

Restored tabs

With --split, the first window skips restoring the last session's tabs, which would have turned its split off again.

A value after -T

The early command-line pass treats --split VALUE like --geometry, so the 60 after -T isn't taken as a right-pane folder.

  g_object_get (G_OBJECT (window->preferences),
                "misc-remember-split-position", &remember_split_position,
                "last-splitview-separator-position", &last_splitview_separator_position,
                NULL);
  if (remember_split_position && window->split_percent == 0 && last_splitview_separator_position > 0)
    gtk_paned_set_position (GTK_PANED (window->paned_notebooks), last_splitview_separator_position);
  else
    thunar_window_paned_notebooks_queue_split (window);
To get the old behaviour back without reverting, turn the hidden setting on: xfconf-query -c thunar -p /misc-remember-split-position -n -t bool -s true. Reverting the PR removes the setting and --split; no other setting is written.

Code review

  • Fixed, the test's colours: it measured the panes by white pixels, but CI uses a dark theme; it now measures runs of one colour.
  • Fixed, a stale width: the ratio was set right away, and GTK could rescale it from an earlier split's width; it's now applied on the next size-allocate.
  • Fixed, restored tabs: on a cold start, restoring tabs turned a --split window's split off; it's now skipped with --split.

Glossary

Split view
Thunar showing two folder panes side by side (F3), or one above the other in vertical split.
Divider
The bar between the two panes; drag it to resize them, double-click it to center it.
GtkPaned
The GTK widget that holds the two panes and the divider's position in pixels.
size-allocate
The signal GTK sends when a widget gets its actual size on screen.
Hidden setting
A Thunar preference with no checkbox, set only with xfconf-query.
xfconf-query
The command that reads and sets Xfce settings, such as the saved divider position.
-t and -T
Options that open the following folders as tabs in the left (-t) or right (-T) pane.
Open new windows as tabs
A Thunar setting that opens a new folder as a tab in the existing window instead.
Restore tabs
Thunar reopening the tabs of the last session when it starts.
Xvfb
A virtual screen with no monitor, where the tests run Thunar and take screenshots.
Shot pair
A before and an after screenshot that CI joins into one image in its verify comment.
