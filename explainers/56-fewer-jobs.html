PR #70: Fewer CI jobs, fewer comment edits, no rebuild after a merge

Branch 56-fewer-jobs → main, closes #56, #66 and #58. GitHub bills each job as at least a whole minute, so CI now runs fewer short jobs, edits its PR comments only when they change, and releases a merged PR's own debs.

Part 1

What this PR adds

Two jobs folded into others, one re-run job dropped, a skip for unchanged comments, and debs reused on a push to main. No Thunar code changes.

same as before new in this PR

The big picture

Actions ran out of minutes on 7 November. GitHub rounds every job up to a whole minute, and the short jobs billed 345 minutes for 136 real ones. Pushes to main billed 95 more to rebuild what the PR had just built and verified. And every edit of CI's PR comments woke the watching session with the whole comment, even when nothing in it had changed.

A job that runs for 10 seconds bills a full minute. Folding it into a job that already runs saves that minute, as long as the two together stay under the next whole minute.

Step by step (numbers match the diagram)

① On a PR
  1. Review reports. The review-report job is now the review job's last steps. After the model's review step has ended, a second checkout into .review-push, with the push token, commits and pushes the fix, posts the suggestions and writes the review comment. The model never ran in that folder or saw the token. The review job's concurrency group already ran one review at a time per branch, so the 20-minute wait for an earlier run's report is gone.
  2. Same body? pr-comment.sh put reads the comment first and skips the edit when the new body is identical, link for link. Most of the summary's rewrites, such as the summary job's final one, no longer reach the watching session.
  3. Audit posted. A /visual-verify comment used to make pr-summary.yml re-run the build run's summary job, a second billed job. It now runs pr-summary.py itself, from main's scripts, once the head's build run has finished.
  4. Same checks. A PR still shows build, verify, explainer, review and summary, with the changes step, the No code changed steps and ccache as before. Only review-report is gone, so the merge rule in CLAUDE.md drops it.
② On a push to main
  1. Find PR debs. reuse-debs.sh find looks up the PR merged as this commit and its newest build run whose build and verify passed, verify having run its tests, with a debs artifact not yet expired.
  2. Same tree? PR builds now stamp the version the next release would get, and save the git tree they built in built-tree. The push reuses the debs only when that tree is this commit's tree and their version is the one it releases now. Otherwise it builds as before.
  3. Release in build. The release job's two steps, publish and keep the newest 10, run at the end of build on a push, so build has write access to the repo's contents.
  4. Verify skipped. When the debs were reused, verify doesn't start on the push: the PR's run already tested those exact debs.

The version stamp (#58's blocker)

Before

Only a push stamped debian/changelog, so a PR deb said +local0 and could never be released as is.

Now

A PR build stamps next-version.sh's version too, the one its dry run already printed, with "CI build of PR #n at" its head.

Guard

A release in between raises the number, and a moved main changes the tree. Either makes the push build its own debs.

What comes later

No open issue depends on this one. This PR closes the last of the minute-saving issues opened on 8 November.

What to watch after the merge

  1. The merge's own run. It should reuse this PR's debs, publish the release from build and skip verify.
  2. The explainer job. It stays its own job: its check is part of the merge rule and must not hold up verify. Folding it is a separate decision.

Glossary

Billed minute
GitHub charges each job's run time rounded up to a whole minute.
Job
One part of a workflow run on its own fresh machine, shown as one check on the PR.
Step
One command or action inside a job; steps share the job's machine.
Tree
Git's ID for the exact files of a commit; two commits with the same files share it.
Artifact
Files a run keeps for 14 days, such as the built .deb packages.
Push token
The secret that lets CI's review push its fix commit to the PR branch.
