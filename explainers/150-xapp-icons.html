PR #153: Nemo's XApp icons in the toolbar, location bar and side pane

Branch 150-xapp-icons → main, closes #150. Where Thunar already shows symbolic (one-colour) icons, it now uses Nemo's XApp version of each icon when it is installed, and the theme's own icon when it isn't.

Part 1

What this PR adds

One helper in thunar-util.c turns an icon name into its XApp name, xsi-<name>-symbolic. The toolbar, the location bar and the side pane try that name first, behind a new hidden setting that is on by default.

code this PR adds or changes what you see with XApp icons installed what you see without them (unchanged)

The big picture

Nemo, Cinnamon's file manager, draws its toolbar and side pane icons from the XApp symbolic set (package xapp-symbolic-icons), whose icons are named xsi-<name>-symbolic. Thunar used the icon theme's <name>-symbolic, for example ZorinBlue-Dark's, so the two apps looked different side by side. This PR makes Thunar ask for the XApp name first.

It only changes places that already show symbolic icons, which the existing settings misc-symbolic-icons-in-toolbar and misc-symbolic-icons-in-sidepane turn on. The main file view keeps its colour icons.

Step by step (numbers match the diagram)

① Each icon draw: pick the name
  1. Toolbar, path bar. Every built-in toolbar button gets its icon from thunar_window_toolbar_get_icon_name in thunar-window.c, which now asks the helper first. The location bar does the same in thunar-location-buttons.c (the scroll arrows and the edit button), thunar-location-button.c (each folder button) and thunar-path-entry.c (the entry's search and error icons).
  2. Side pane. Devices and named places go through thunar-shortcuts-icon-renderer.c, which first looks up an icon holding only the XApp names, then the original. Files and bookmarks go through thunar-icon-factory.c, which tries the XApp name only when it is drawing a symbolic icon, so the main view is untouched.
  3. XApp name. thunar_util_get_xapp_icon_name returns nothing if the hidden setting misc-xapp-icons is off. Otherwise it strips -symbolic, maps system-search to edit-find (XApp has no search icon; Nemo uses edit-find), and builds xsi-<name>-symbolic.
  4. Installed? The helper asks the icon theme whether it has that name (gtk_icon_theme_has_icon). XApp installs its icons in the hicolor theme, which every theme falls back to.
  5. Nemo's look. If it does, that icon is drawn, loaded the same symbolic way as before, so it takes the theme's text colour on dark and light themes.
  6. Fallback. If it doesn't, Thunar draws the theme's own <name>-symbolic, exactly as before this PR. The location bar's scroll arrows, edit button and home, desktop or root path button, and the path entry's search and error icons, list both names, so they fall back too if the XApp icons are removed later.
② When to look again
  1. Setting toggled. misc-xapp-icons is a new hidden setting in thunar-preferences.c, on by default, with no switch in the Preferences dialog.
  2. Full refresh. Changing it refreshes the toolbar buttons and redraws the side pane and tree (thunar-shortcuts-view.c, thunar-tree-view.c). It also rebuilds the location bar, as the symbolic-icons setting does, unless a search is running or you are typing in the location entry; then the bar is left alone, so the text stays, and it is refreshed once the search ends or focus leaves it.
  3. Theme changed. The window also listens for the icon theme's changed signal, which fires when the theme is switched or icons are installed or removed.
  4. Buttons only. That signal refreshes the toolbar buttons and the view switcher at once. The location bar isn't rebuilt, so a search or a path you are typing is never wiped. Only toggling a setting rebuilds it: misc-xapp-icons once no search or typing is under way, and misc-symbolic-icons-in-toolbar as upstream already does.
One known limit, accepted by the owner: after an icon theme change, the location bar keeps its old icons until a setting is toggled or a new window opens. Toggling misc-symbolic-icons-in-toolbar during a search still drops the search entry, as it does upstream.

Which icons change

Have an XApp version

Per the issue's list, from a Zorin machine with xapp-symbolic-icons 1.0.9: Back, Forward, Up, Home, New tab, New window, zoom, Reload, Find, Terminal, Edit, the scroll arrows, drives, Computer, the home and user folders, Recent, Trash, Network, Eject.

Search

XApp has no system-search, so the Search button and the search entry use xsi-edit-find-symbolic, as Nemo does. Turning the setting off maps it back to the theme's search icon.

Likely fallbacks

Icons missing from the issue's list keep the theme's symbolic icon, so the two styles can mix. The view mode icons (grid, list, compact) aren't in the list, so they likely fall back. Not checked here.

Not in this PR, because existing settings cover them: the symlink arrows on side pane entries (hidden setting shortcuts-icon-emblems) and custom action toolbar buttons, which keep the icon set in the custom action.

The key change: the toolbar's icon name

thunar_window_toolbar_get_icon_name (ThunarWindow *window, const gchar *icon_name)
{
  ...
  plain_icon_name = thunar_util_get_icon_name_from_xapp (icon_name);
  if (plain_icon_name != NULL)
    {
      xapp_icon_name = thunar_window_toolbar_get_icon_name (window, plain_icon_name);
      g_free (plain_icon_name);
      return xapp_icon_name;
    }
  g_object_get (..., "misc-symbolic-icons-in-toolbar", &use_symbolic_icons, NULL);
  if (use_symbolic_icons)
    {
      xapp_icon_name = thunar_util_get_xapp_icon_name (gtk_icon_theme_get_for_screen (...), icon_name);
      if (xapp_icon_name != NULL)
        return xapp_icon_name;
    }
  /* otherwise the theme's <name>-symbolic, as before */

Code review

Before the first push, a fresh agent ran /code-review at high on the branch against origin/main. It found 7: 3 fixed, 3 skipped for now, and 1 was this missing page. The fixes came after build 3, so they were compiled but not re-run under verify.

  • Fixed, Search icon: turning XApp icons off left the Search button on edit-find. The toolbar now maps xsi-edit-find-symbolic back to system-search.
  • Fixed, typed path: an icon theme change rebuilt the whole location bar and wiped a path being typed. Now only the toolbar buttons and the view switcher refresh.
  • Fixed, comments: two “why” sentences were trimmed from the helpers' doc comments.
  • Skipped, device icons: a drive may show a generic xsi icon such as xsi-drive-harddisk where the theme has a more specific one. Kept for a consistent Nemo look.
  • Skipped, speed: each icon draw reads the setting and asks the theme once more. A small cost.
  • Skipped, screen: the location bar's arrows use the default icon theme rather than the window's screen's. The same on a single screen.

Glossary

Symbolic icon
A one-colour outline icon, named …-symbolic, that GTK tints with the theme's text colour.
XApp
Linux Mint's shared library and assets for its apps, including Nemo's icon set.
xsi-
The prefix of XApp's symbolic icons, e.g. xsi-go-home-symbolic.
Nemo
Cinnamon's file manager, which Zorin also ships; the look this PR matches.
hicolor
The base icon theme every theme falls back to; XApp installs its icons there.
Hidden setting
A Thunar setting with no switch in Preferences, changed with xfconf-query.
xfconf-query
Xfce's command for reading and writing settings, such as Thunar's.
Side pane
The left column with Places, Devices, Network and Bookmarks (or the tree).
Location bar
The path area in the toolbar: folder buttons or a typed path entry.
GThemedIcon
An icon given as a list of names; GTK uses the first the theme has.
Fixture
A stand-in file a test creates, here solid squares named like XApp icons.
Pixbuf loader
A GTK plug-in that reads one image format; without the SVG one, SVG icons don't load.
visual-verify
This repo's audit of a PR's screenshots against what each one should prove.
CSD
Client-side decorations: the window draws its own title bar and margins.
gtk-doc
The tool that builds API docs from code comments during the build.
