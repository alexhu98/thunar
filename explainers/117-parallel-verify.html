Part 1

What this PR adds

verify-proof.sh run now keeps up to two tests running at once and checks the budget against wall-clock time, and the build-verify agent runs the suite in the background.

a step that runs what it produces

The big picture

Every feature PR adds a test script, and CI's verify job runs all of them on every code PR. On PR #116 the smoke test and 17 scripts took about 13 minutes one after another, and the shared 25-minute budget would fill again at about 30 scripts. A local run was worse off: the Bash tool stops a command after 10 minutes, so the full suite was killed before it wrote its results.

Each test already ran in its own sandbox (its own virtual screen, D-Bus session, home folder and output folder), so running several at once needed only a pool in the runner script, not changes to the tests.

Step by step (numbers match the diagram)

① verify-proof.sh run (CI and local)
  1. List the tests. The smoke test comes first, then each verify/<digits>.sh in name order. A script with any other name is recorded as misnamed right away and never started.
  2. Start up to 2. While fewer than $JOBS tests run (default 2, the owner's choice over 3 in R6), the next one starts in the background. Before it starts, a script that could end after the 1500 s budget, counted in wall-clock time from the start of the run, is recorded as not run (time budget). The smoke test skips that check.
  3. Each test alone. test_one is unchanged in what it gives a test: its own Xvfb display, xfwm4, D-Bus session, HOME, XDG folders and shot folder, with a 120 s limit. It now writes its result to its own row file and its process id to a pid file.
  4. Results in order. Each time a test ends, its console output is printed and results.tsv is rewritten from the row files in the serial order, so shot numbering and the verify comment come out as before. A run cut short keeps the rows of the tests that finished.
② build-verify agent (cloud container)
  1. Run in background. Step 4 of .claude/agents/build-verify.md starts verify-proof.sh run with run_in_background and a 35-minute timeout, writing its log and exit code under $LOGS. /visual-verify run: uses this agent, so it gets the same.
  2. Report the result. The agent waits for the background completion notice, never a foreground sleep, then reports the exit code and each test's result line, as before.

A closer look

Same order as a serial run

Tests finish in any order, but results.tsv lists smoke, then the scripts in name order, then misnamed ones, so the shot numbers don't move.

Stopped partway

An exit trap kills every running test through its pid file. A stop exits 143, Ctrl-C exits 130, and finished rows stay in results.tsv.

One setting

JOBS must be a positive number, or the run stops with exit 2. JOBS=1 runs the tests one at a time, as before.

Code review

Before the first push, a fresh agent reviewed the branch at the high level: 5 findings, 3 fixed, 2 skipped.

  • Fixed: the background run got a timeout; the smoke test skips the budget check, with its launch code merged; the header comment was re-wrapped.
  • S1, fixed after: nothing stopped running tests if run was killed. The building session added the exit trap and pid files.
  • S2, left to CI: 3 workers on a 4-vCPU runner might make fixed waits in the scripts flaky. CI's runs showed none; the owner chose 2 workers (R6).

CI's review of d101039 (high) found R1–R5 confirmed and R6–R10 plausible and low; all but R6 were fixed in 7ced01e, and R6 in 9defda7. See the code review comment on PR #121.

  • Results kept (R1, R9): results.tsv is rewritten after each test ends, and misnamed scripts and runnable tests are kept in separate lists.
  • Clean stop (R2, R5, R7): the exit trap no longer stops at a failing kill and also kills the test subshells; Ctrl-C exits 130.
  • Agent run (R3, R10): build-verify sets LOGS in the command and waits on the completion notice with a 35-minute timeout.
  • Small ones (R4, R8): a new explanatory comment removed; JOBS must be a positive number.
  • R6, decided by the owner: the same worry as S2, three workers on four vCPUs. The owner chose two at a time, the default since 9defda7.

CI's second review, of 7ced01e, found R11–R18. All were fixed in 473f58f except R17, which counts as accepted.

  • R11 (medium, confirmed): the exit trap dropped tests that had finished but weren't reaped. Now results.tsv is collected on exit, with unfinished tests marked “cut short”.
  • R12–R16, R18: JOBS is checked before old results are wiped, results.tsv is written atomically, and build-verify sets LOGS, may wait with Monitor and reports a missing exit file.
  • R17, accepted: a pid-file race lasting microseconds, there before this PR.

CI's third review, of 473f58f, found R19–R26, all low.

  • R19 (confirmed), fixed in cfe7965: a cut-short test with no log showed an empty log block. The verify comment now says “No log: the test did not start.”
  • R20–R26, not confirmed, accepted: R20 can't happen on bash 5.2; R21's cut-short rows still reach the verify comment; R22's Monitor wait is only a fallback to the completion notice; R23 is wording only; R24 is R17's race; R25's subshells die on TERM before writing a row; the review itself disproved R26.

CI's next three reviews found R27–R38, all low.

  • R27, R28, R30 (confirmed), fixed in 41526ba: the verify comment tells a test with no log (“did not start”) from one with an empty log, and closes the log file. R29 (not confirmed) counts as accepted.
  • R31 (confirmed), fixed in 9defda7: the whole log was read to keep 30 lines. A bounded deque now keeps them and drops trailing blank lines. R32 and R33 count as accepted.
  • R34–R38, from the review of 9defda7, not confirmed, accepted: R34's time is bounded by the test's timeout; R35's simpler form would undo R31 and change the output; R36's whitespace-only log carries no information; the old [-30:] behaved the same (R37); R38's difference doesn't show in the rendered block.

Glossary

Worker pool
A fixed number of jobs running at once; a new one starts when one ends.
JOBS
How many tests verify-proof.sh run keeps running at once; default 2.
BUDGET
The 1500 s (25 minutes) the whole run may take; a test that could end later isn't started.
Wall-clock time
Real time since the run began, not the sum of each test's time.
Smoke test
Checks that Thunar is still running 10 s after launch.
results.tsv
One row per test: name, status, seconds. Shot numbers and the verify comment are built from it.
Xvfb
A virtual X screen in memory, so a test can run Thunar with no monitor.
Exit trap
Shell code that runs when the script exits, here to kill tests still running.
run_in_background
Runs a Bash tool command detached, so it isn't stopped at 10 minutes.
vCPU
A virtual processor core; GitHub's ubuntu-24.04 runners have 4.
