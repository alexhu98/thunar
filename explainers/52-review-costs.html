PR #62: CI's code review skips its own fixes and replaced pushes, and runs lighter

Branch 52-review-costs → main, closes #52, #53 and #54. The review job billed 899 of the 2,019 minutes used from 2 to 7 November. Once merged, it stops reviewing work that another review already covers, and every review is cheaper and capped.

Part 1

What this PR adds

Two new reasons to skip a review in review-proof.sh plan, and a lighter, capped review in build.yml.

same as before new in this PR

The big picture

Actions stopped on 7 November when the account ran out of minutes. The review job alone billed 899 of 2,019 minutes. 274 of them went to reviewing claude[bot]'s own fix commits, and 327 to reviews whose head a newer push had already replaced.

A skipped review leaves the "last reviewed" commit where it was. So the next review diffs from there, and still covers whatever was skipped.

Step by step (numbers match the diagram)

① Plan the review
  1. Newer run? plan asks GitHub's runs API whether a newer run of build.yml exists for this branch, with another head. A newer push always starts one, so if it exists the review is skipped straight away, without waiting, and the newer run reviews the same changes. This run's review-report is skipped too, so it can't queue behind and cancel an earlier run's report.
  2. Wait, ask again. Otherwise it waits for earlier runs to record their reviews, now for up to 20 minutes instead of 30, then asks once more, since a push may have come in meanwhile.
  3. CI's own fix? A head that the review state records as the commit that fixed a finding, with the last reviewed commit as its parent, is skipped. The author or subject alone doesn't count, since anyone with push access could copy them.
  4. Other rules. Already reviewed, already part of a reviewed head, or only explainers/ changed: skipped as before. Anything else is reviewed.
② Review and report
  1. Review at high. REVIEW_LEVEL is high instead of xhigh. The Review step gets 30 minutes of its own, and the whole job 55 instead of 90. The longest review so far took 20. A review that runs out of time fails its step, so review-report still runs and records it.
  2. Record the state. Unchanged: a skipped review doesn't move the recorded commit, so the next push's review takes in the bot's fix.
  3. Summary row. When the review job is cancelled or runs past its 55 minutes, the summary's Code review row now says "stopped: the review job was cancelled or ran past its time limit". A head that is CI's own fix shows ⏳ "not reviewed yet", and the summary waits for a review of the fix instead of going green.

The merge rule

The agent merges only once a review has covered the head, and a head that is CI's own fix is now skipped, so the agent never merges on one. The agent's next push is reviewed from before the fix, so the fix gets its review then. With nothing left to push, the agent asks you instead.

Code review

A fresh agent, given only the diff and the three issues, reviewed the first version: 0 high, 0 medium, 2 low findings and 1 hardening point, all fixed. CI's first review, at high in 5 minutes, then found 7 more, 1 high, 3 medium and 3 low, all unconfirmed. All 7 are fixed, which reshaped both new skips.

  • Newer push, by its run: after a force-push, GitHub can briefly report the old head, which looked like a newer push and could skip the real one's review (R1). The skip now needs a newer run of the workflow, which only a push creates.
  • No stray report: a skipped, replaced run's review-report could queue behind an earlier run's and cancel it, losing that run's findings (R2). A replaced run now has no review-report.
  • CI's own fix: it showed green though unreviewed (R3), and was spotted by author and subject, which can be copied (R4). It now shows "not reviewed yet", and must be recorded in the review state as a fix commit.
  • Smaller ones: the wait for earlier runs is 20 minutes, not 10 (R5); CLAUDE.md says the fix commit's trailer doesn't force a review (R6); a review that overruns says so (R7).

CI's own review of this push is in the code review comment on PR #62. It is the first run at high.

Part 3

What comes later: build and job costs

This is the second of four PRs for the CI minutes issues. Each opens after the one before it merges.

built not built yet

Build costs: #55, #57 (next)

  1. Skip what isn't code. Build and verify skip PRs that change only explainers, skills or Markdown (#55).
  2. Cache the compiler. ccache keeps the last build's objects, so a small change compiles in seconds (#57).

Fewer jobs: #56, then maybe #58

  1. Fold small jobs. review-report into review and release into build, since each job is rounded up to a whole minute (#56).
  2. Reuse the PR's debs. A push to main reuses its merged PR's build, if the version stamp allows it (#58).

Glossary

claude[bot]
The account CI's review uses to push its fixes to a PR branch.
Head
The newest commit on a PR's branch; each push makes a new one.
Replaced push
A head that a newer push has already replaced while its run was still going.
high / xhigh
How hard the review digs: xhigh is deeper and slower, high is lighter.
Review state
What CI records in the review comment: the last reviewed commit and every finding.
Trailer
A Key: value line at the end of a commit message, such as Review: auto-fix.
