PR #69: Skip the build on PRs with no code, and cache the compiler with ccache

Branch 55-build-costs → main, closes #55 and #57. PRs that change only explainers, skills or docs no longer build and verify Thunar, and every other build reuses the last build's compiler output.

Part 1

What this PR adds

A changed-files check at the start of the build job, a ccache restore and save around the build, and a summary that says why build and verify were skipped. All in build.yml and pr-summary.py.

same as before new in this PR

The big picture

GitHub Actions ran out of minutes on 7 November, after about 2,019 billed minutes in six days. Build and verify billed 541 of them on PRs that changed no Thunar code, and the build job spent most of its 4 minutes compiling the same files as the run before.

A skipped step keeps its job green, while a skipped job may not satisfy a required check. So build and verify still run on every PR; on a docs-only PR each finishes in seconds with its heavy steps skipped.

Step by step (numbers match the diagram)

① No code changed: skip (#55)
  1. List the files. On a pull request, the checkout is GitHub's merge commit of the PR into main. With two commits of history, git diff --no-renames --name-only HEAD^1 HEAD lists what the PR changes on top of the current main, both sides of a rename included. Pushes to main always build.
  2. Docs only? If every file is under explainers/ or .claude/, or ends in .md or .narration.json, the step sets skip=true. Anything else builds as before: source, .github/, anything under debian/ or verify/, even a .md file there, and the root README.md, which the thunar-data package installs.
  3. Steps skipped. The build job's PPA, build-deps, dry-run, ccache, build and upload steps skip, and so does every step of verify, through the job output needs.build.outputs.skip. In their place, each job runs one step named No code changed. Both jobs still finish green, with no debs, no shots and no verify comment.
  4. Summary says why. pr-summary.py reads each job's steps from the GitHub jobs list. A green build or verify job that ran No code changed shows as ⏭️ "skipped: the PR changes no code, packaging or CI files", the key result and shots says verify did not run, and the screenshot audit row reads "not needed: verify took no shots".
② Code changed: ccache (#57)
  1. Restore cache. ccache is installed with the build-deps, and actions/cache/restore brings back the newest ~/.ccache whose key starts with ccache-$ImageOS-$ImageVersion-: this branch's own, or else main's.
  2. Build. dpkg-buildpackage runs as before, with /usr/lib/ccache first on PATH, so every gcc call goes through ccache. CCACHE_DIR is an absolute path, because debhelper gives the build a fake HOME. ccache -s prints the hit rate in the log.
  3. Save. The cache is saved under a key ending in the run ID, at most 500 MB. Old entries aren't deleted by the workflow: past the repo's 10 GB, GitHub evicts the least recently used, and it drops any entry unused for 7 days. Deleting them would need actions: write on a job that runs the PR's own scripts.

To undo the skip on one PR, touch any file outside the docs patterns. To start ccache from cold, or to free cache space by hand, delete the ccache-* entries under the repo's Actions → Caches.

Code review

A fresh agent, given only the diff and the two issues, found 6: 2 medium, 4 low. 3 are fixed, 2 were kept on purpose, and 1 was the explainer, which this page adds.

  • Fixed: a compiled Python file from a local test run had been committed; docs-only PRs would have waited forever for a screenshot audit that has no shots to audit, so the summary now marks it not needed; and *.md under debian/ or verify/ no longer skips the build.
  • Kept at first: the build job had actions: write to delete its old cache entry. CI's review flagged that too, and the delete is now gone; see below.

CI's first review, at high in 5 minutes, found 8: R1 to R8. R1, confirmed and medium, says CLAUDE.md's merge rule still needs build and verify to run their steps and a /visual-verify PASS, so a docs-only PR could never be merged by the agent. The owner chose to change the rule in this PR: a PR whose build and verify ran No code changed needs neither, and the Verify section says when they skip. The other 7 are fixed in one push: the root README.md always builds; the build job is back to actions: read, so it no longer deletes old cache entries, which also settles two findings about that delete; the summary finds the skip by a dedicated No code changed step rather than the heavy steps' names; an older head's shots no longer show on a skipped head; and the file patterns are written in one place only. The second review found nothing new. The third, on the CLAUDE.md change, resolved R1 and found 6 more. R9, a medium, said the screenshot rule still asked for an audit after every CI run; it now skips runs that took no shots. R10 to R14, lows nobody confirmed, are accepted: R13 and R14 question the owner's own decision to change the rule here; R12's two jobs share one skip output, so they can't disagree; R10's audit is never posted on a skipped PR, so it can't fail; and R11's file list already matches build.yml. The code review comment on PR #69 has every finding.

Glossary

ccache
A compiler wrapper that reuses an earlier compile's output when the input is the same.
Merge commit
The commit GitHub makes of a PR merged into main, which CI checks out.
Skipped step
A step whose if: is false; its job can still finish green.
Cache key
The name an Actions cache entry is saved under; a prefix finds the newest match.
debhelper
The Debian tool dpkg-buildpackage runs to configure and compile.
