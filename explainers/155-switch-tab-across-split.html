Part 1

What this PR adds

Previous Tab and Next Tab now use the same tab order as Alt+Page Up and Down (#128): the left pane's tabs, then the right pane's, wrapping around at the ends. One new function in thunar/thunar-window.c does it, and verify/155.sh tests it.

new in this PR existing code, now reused you

The big picture

In split view each pane has its own row of tabs. Until now, Ctrl+Page Down and Ctrl+Page Up only cycled through the tabs of the pane you were in, so with tabs alpha and bravo on the left and charlie and delta on the right, Ctrl+Page Down on bravo went back to alpha. Alt+Page Up and Down (#128) already treated both panes as one row. Now tab switching does too: from bravo it goes to charlie, and the right pane becomes the active one.

The two panes are two separate GTK notebooks, and the window only acts on tab changes in the selected one. So the new code shows the target tab first, then hands over to the existing pane switch, which a mouse click in the other pane already uses.

Step by step (numbers match the diagram)

① Every switch: find the tab and show it
  1. You press a key. Ctrl+Page Down or Ctrl+Tab for the next tab, Ctrl+Page Up or Ctrl+Shift+Tab for the previous one, or Next Tab and Previous Tab in a tab's right-click menu. All of them run the same two actions, switch-next-tab and switch-previous-tab, which now both call the new thunar_window_switch_tab.
  2. Find the next tab. It asks thunar_window_neighbour_tab_view, written for #128, for the tab one step over. In split view, the next tab after the left pane's last is the right pane's first, and the reverse for previous.
  3. Wrap at the ends. Past the very last or first tab, that lookup returns nothing (#128's drops don't wrap). Tab switching always wrapped, so it keeps doing so: next goes to the left pane's first tab, previous to the right pane's last. Without split view, it is the one pane's first or last tab, as before.
  4. Show that tab. It finds the notebook that holds the target tab and makes the target its current page. In the same pane, that is the whole job: the window activates the tab as it always did.
② Only when the tab is in the other pane
  1. Switch panes. If the target is in the other notebook, it calls the existing thunar_window_paned_notebooks_switch. That moves the inactive-pane dimming to the pane you left and makes the target's notebook the selected one.
  2. Focus its view. The same pane switch then activates the new pane's current page, which step 4 already made the target. The window title changes to its folder, and its file view gets the keyboard focus, so the next key press, such as another Ctrl+Page Down, starts from there.

Without split view there is only one pane, so nothing changes: the keys cycle through its tabs from left to right, wrapping around, as before.

The key change

static gboolean
thunar_window_switch_tab (ThunarWindow *window, gint direction)
{
  target = thunar_window_neighbour_tab_view (window, direction);
  if (target == NULL)     /* past an end: wrap */
    target = first page of the left notebook (next)
          or last page of the right notebook (previous);
  notebook = the notebook that holds target;
  gtk_notebook_set_current_page (notebook, target's page);
  if (notebook != window->notebook_selected)
    thunar_window_paned_notebooks_switch (window);
}

A sketch of the new function, shortened. The old actions each counted pages in the selected pane only; now both are one line that calls this function with 1 or -1. thunar_window_notebook_set_current_tab, which other actions still use, is unchanged.

Part 2

How it was built and verified

Built, installed and tested in the cloud container by the building session, then reviewed by a fresh agent, which found nothing to fix in the code. CI builds, tests and reviews it again after the push.

Built on 3 known-good references

#128's tab lookup

thunar_window_neighbour_tab_view already finds the tab one step over across the split for Alt+Page Up and Down. It is reused as it is, with the wrap-around added outside it.

The old tab switching

It wrapped around inside the pane. The new code keeps that wrap-around, over both panes, and leaves the window without split view as it was.

A click in the other pane

Clicking a file view calls the same thunar_window_paned_notebooks_switch that crossing now calls, so the dimming and the focus move the same way.

Glossary

Tab
One folder view among several in a pane, picked by its label at the top.
Split view
F3: two panes side by side in one window, each with its own tabs.
Active pane
The pane your keys act on; the other one is dimmed.
Notebook
GTK's name for a row of tabs and the pages behind them; each pane has one.
Selected notebook
The active pane's notebook, which Thunar's window acts on.
Wrap-around
Going from the last tab back to the first, or the first to the last.
Keyboard focus
The one widget that gets key presses, such as a file view or the location bar.
Window shortcut
A key bound to a window action, such as Ctrl+Page Down to Next Tab.
Back (Alt+Left)
Goes to the folder a tab showed before, from that tab's history.
verify/155.sh
The test script CI runs: it drives Thunar with xdotool and takes screenshots.
Pair
A before and after screenshot around one action in a test.
Smoke test
Checks that Thunar is still running 10 s after it starts.
/visual-verify
A check that each screenshot shows what the test says it proves.
Verify: full
A commit trailer that makes CI run every test, not just this PR's.
