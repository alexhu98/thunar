Part 1

What this PR adds

Three numbers go up: the verify run's shared budget from 15 to 25 minutes, and the two GitHub timeouts around it. No Thunar code changes.

how a verify run decides what to run (unchanged) the limits this PR raises, inside out

The big picture

CI's verify job runs the smoke test and every verify/<issue>.sh one after another, each under its own virtual screen. Every feature PR adds a script, so the run keeps getting longer. On main after PR #113 the smoke test and 16 scripts took 776 s of a 900 s budget. PR #114 adds verify/16.sh, and the last two scripts, verify/95.sh and verify/96.sh, were no longer started, so verify failed.

The budget is checked before each script starts, assuming the script could take its full 120 s. So a script needs 120 s of budget left to start at all, even if it usually takes 20.

Step by step (numbers match the diagram)

① How verify spends its time (unchanged)
  1. Tests run in turn. The verify job's step "Smoke test and verify/*.sh" calls .github/scripts/verify-proof.sh run. It runs the smoke test, then each verify/<digits>.sh, one at a time, each with its own Xvfb, window manager and D-Bus session and a 120 s limit (TIMEOUT).
  2. Budget check. Before each script, the run checks SECONDS - begin + TIMEOUT <= BUDGET: the time used so far plus the script's 120 s limit must fit in the budget. This PR doesn't change the check.
  3. Run or skip. A script that fits runs. One that doesn't is reported as "not run (time budget)" in the verify comment, and the job fails, because a script that never ran proves nothing.
② The new limits (this PR)
  1. Budget: 25 min. verify-proof.sh's default BUDGET goes from 900 s to 1500 s. With today's 776 s of tests, that leaves about 724 s, roughly 12 more minutes of scripts.
  2. Run step: 30 min. In .github/workflows/build.yml, the run step's timeout-minutes goes from 20 to 30. It must be longer than the budget plus the last script's 120 s, 27 minutes, or GitHub would cancel the step before the budget runs out.
  3. Job: 45 min. The verify job's timeout-minutes goes from 30 to 45. It also covers installing the debs, the cache, and uploading the screenshots and writing the verify comment after the tests.

Trade-offs

Slower CI

Scripts run one after another, so every new one adds its time to every code PR's verify run.

Slow scripts hide

A bigger budget no longer pushes back on a script that gets slow. Nothing flags it until the budget fills again.

Not done here

The issue's optional extras: a warning for a slow script, and a "budget left" line in the summary.

Code review

Before the first push, a fresh agent reviewed the branch against origin/main at the high level. It fixed nothing and skipped 5 findings:

  • S1, tests run in turn: by the review's estimate the budget fills again at about 30 scripts. Running them in parallel goes into a follow-up issue.
  • S2, every script on every PR: each code PR reruns all verify scripts and can hold a runner up to 45 minutes. Running only the changed ones goes into a follow-up issue.
  • S3, no explainer: the branch had none when it was reviewed; this page is it.
  • S4, local runs cut off: build-verify's local run is stopped by the Bash tool at 10 minutes, which the old 900 s budget already passed. It goes into a follow-up issue.
  • S5, job headroom: 45 minutes leaves about 15 beyond the 30-minute step for install and upload. Raise it to 50 only if installs without the cache prove slow.

CI's first review of PR #116 found four low, plausible findings, reported in its code review comment. The owner accepted all four, closed with a Review-accept trailer on this explainer-only commit:

  • R1, job headroom (build.yml:167): the 45-minute job leaves about 15 beyond the 30-minute run step. Accepted: the worst case is about 43 minutes, and this PR widens the margin.
  • R2, budget check (verify-proof.sh:145): it ignores the 5 s kill grace and the time to build the shots. Accepted: that's seconds, and the margin predates this PR.
  • R3, local runs cut off (verify-proof.sh:26): build-verify and /visual-verify run: stop at the Bash tool's 10 minutes. Accepted here: the suite already took about 13, so it predates this PR. Same as S4; it goes into the follow-up issue.
  • R4, treats the symptom (verify-proof.sh:26): scripts still run one after another. Accepted: #115 asks for exactly this; parallel runs (S1) go into the follow-up issue.

Glossary

Verify job
The CI job that installs the built Thunar and runs the smoke test and every verify script.
verify/<issue>.sh
A feature PR's test: it drives Thunar with xdotool and takes screenshots.
Smoke test
The first test: Thunar is still running 10 s after launch.
Budget
The total time all tests in one verify run may take, now 1500 s.
TIMEOUT
The most one script may take, 120 s; the budget check assumes it takes all of it.
"not run (time budget)"
A script skipped because it could end after the budget; it fails the job.
timeout-minutes
GitHub's own limit on a step or job; past it, GitHub cancels it.
Xvfb
A virtual screen with no monitor, so Thunar can run in CI.
