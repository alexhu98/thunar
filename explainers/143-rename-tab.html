Part 1

What this PR adds

The name entry's key handler in thunar-standard-view.c now handles Tab and Shift+Tab, and verify/143.sh tests them.

new in this PR existing in-place rename code from #16, reused you

The big picture

Since #16, F2 in the Details view turns a file's Name cell into a text box where you type the new name. Renaming a run of files meant pressing F2 on each one. Nemo and Dolphin let you press Tab to save and jump straight to the next name; this PR adds the same to Thunar, with Shift+Tab for the file above.

The next file is picked before the name is saved. The rename runs as a job, and the renamed file may sort to a different row, so asking “what's below it?” afterwards could skip or repeat a file.

Step by step (numbers match the diagram)

① Tab in the name entry: save this name
  1. You press Tab. While the name entry is open, thunar_standard_view_rename_key_pressed now catches Tab and the keypad Tab. Shift+Tab, which X sends as ISO_Left_Tab, or Tab with Shift held, goes the other way. Tab with any modifier other than Shift held (Ctrl, Alt, Super, Hyper or Meta) is left to GTK, as before.
  2. Check the name. The handler checks the typed text the way Up and Down already do. If it's invalid, such as a/b, the entry shows its error icon, stays open on the same file, and nothing is saved or moved.
  3. Pick the row. The new thunar_standard_view_rename_neighbour walks the rows in the order you see them: into an expanded folder's children, and back out to the parent's next row. It skips .desktop launchers, because F2 renames those in a dialog, not in place, and rows Thunar reports as not renameable: only when the file info carries access::can-rename and it's false. When the info doesn't say, it skips a row whose folder isn't writable, as F2's rename would refuse it. If you changed the name of an expanded folder, Tab skips its children, whose paths change with the rename, and goes to the folder's next sibling; an unchanged expanded folder still steps into its first child. “Changed” compares with the name the entry opened with.
  4. Save the name. Editing ends through the cell's normal path: editing_done and remove_widget, then rename_edited and rename_finish, exactly as Return does. A name you didn't change saves nothing, and Tab still moves on. Both the save and the move judge “unchanged” against the name the entry opened with, so they always agree. The handler returns TRUE, so GTK doesn't move the keyboard focus elsewhere.
② Then: edit the next name
  1. Next entry opens. thunar_standard_view_rename_in_place queues the next edit through the idle callback F2 already uses. It selects the row and opens its entry with the name selected without its extension.
  2. Type, Tab again. You type the next name and press Tab again, or Return to save and stop, or Escape to stop without saving that one. On the last row, Tab saves and closes the entry; on the first row, Shift+Tab does the same. There's no wrap-around.

Code review

Before the first push, a fresh agent ran /code-review at high with --fix on the branch against origin/main. It reported 4 findings and fixed 3 of them in commit a754168:

  • Launchers: Tab could open an in-place entry on a .desktop launcher, which F2 renames in a dialog. Tab and Shift+Tab now skip launchers.
  • Ctrl and Alt: Tab with Ctrl or Alt held is now left to GTK, as it was before.
  • Test: verify/143.sh now fixes the invalid a/b to a and presses Tab, proving the entry stayed open with its text.
  • Skipped: the missing explainer, which this page resolves, and an xdotool check that no entry is left open after Tab on the last row. That test's screenshot shows it instead.

CI then reviewed each code push at high, in the code review PR comment. Its first review, of 93386ae, found 3:

  • R1, high, confirmed: after you changed an expanded folder's name, Tab stepped into its children, whose paths change with the rename. CI fixed it in c80a3a6: Tab goes to the folder's next sibling.
  • R2 and R3, low: Tab could open an entry on a row Thunar reports as not renameable, and Super, Hyper or Meta+Tab were caught. The agent fixed both in d7c5d31.

Its second review, of d7c5d31, found 4:

  • R4 and R5, medium: the renameable check also skipped rows whose file info lacks the attribute, and the changed-name check should compare with the name the entry opened with. CI fixed both in ea7eadc.
  • R6, low, accepted by the owner: if renaming an expanded folder fails, Tab has already skipped its children, because the next row is chosen before the background rename job finishes. A narrow case, accepted rather than waiting for the job.
  • R7, low, accepted by the owner: verify/143.sh doesn't test skipping non-renameable rows, Super+Tab, or Tab after renaming an expanded folder. xfwm4 may grab Super+Tab, and a read-only row needs extra setup, so it was accepted with no new tests.

The owner's decision on R6 and R7 is recorded on the PR.

Its third review, of ca4ac65, also covered CI's fix commit ea7eadc, and found 3:

  • R8, medium: Tab's “was the name changed” check used the name the entry opened with, while the save compared with the file's current name, so the two could disagree. CI fixed it in 8a04821: the save now compares with the name the entry opened with too.
  • R9, low: when the file info has no access::can-rename, Tab now also skips a row whose parent folder isn't writable, as F2's rename would refuse. CI fixed it in 8a04821.
  • R10, low, plausible, not confirmed: the renameable check no longer skips a row whose file has no info at all. Accepted: the review found no path that puts a file without info into the view, and CLAUDE.md accepts unconfirmed low findings from later reviews.

Glossary

Rename in place
F2 turns the file's Name cell into a text box, instead of opening a popover (#16).
access::can-rename
A file info attribute that says whether the file can be renamed.
Details view
Thunar's list view with columns; the only view with in-place rename.
Popover
The small rename bubble the icon and compact views still use (#15).
Launcher
A .desktop file that starts an app; F2 renames it in a dialog.
View order
The rows top to bottom as shown, after sorting, with expanded folders' children.
Expandable folders
A Details view option that shows a folder's files under it, as a tree.
ISO_Left_Tab
The key name X sends for Shift+Tab.
Idle callback
Work GTK runs once it has nothing else to do, here opening the next entry.
Rename job
The background task that renames the file on disk.
Xvfb, xdotool
A screenless X server, and a tool that sends it clicks and keys.
