PR #104: CI's code review waits for its checking agents

Branch 103-review-wait-agents → main, closes #103. Once merged, a review answers every finding it checks, or fails and is re-run, instead of leaving them half-checked.

Part 1

What this PR adds

The reviewer's prompt now says to start all its checking agents at once and wait for every one, and to mark each answer checked. The review job fails, saying why, when the answer or the job's execution log shows it didn't wait. All of it lives in .github/scripts/review-proof.sh.

the reviewer, following its prompt the script's new checks you or the agent, when a check fails

The big picture

CI reviews every code push. The reviewer finds problems, then starts a fresh agent for each one to confirm or disprove it, and another for each finding still open from earlier reviews to see whether it is fixed now. On PR #102 the reviewer handed in its answer before those agents had reported. R21, a confirmed medium, was never re-checked and stayed "not fixed" for three rounds, and dozens of new findings stayed PLAUSIBLE. #102 needed six review rounds.

It wasn't a timeout: reviews took 3–5 minutes of a 30-minute limit. The agents run in the background by default, and nothing told the reviewer to wait for them.

Step by step (numbers match the diagram)

① Review step — the reviewer's prompt
  1. Review the diff. The reviewer runs the code-review skill on the pushed diff, which reports new findings. Unchanged.
  2. Check new ones. Prompt step 2 now starts one agent per new finding and all of step 4's agents together, in one message, each with run_in_background: false, and doesn't go on to step 3, the fix, until every one has reported. A finding is CONFIRMED only when its agent confirms it.
  3. Re-check open. Prompt step 4's agents, one per finding in open.json, are the ones started in step 2, so both batches run at the same time and step 3 already has their verdicts. Each decides from the code at HEAD whether its finding is resolved.
  4. Return output. Prompt step 5 returns the findings only after every step 2 and step 4 agent has reported, with an entry in previous for every id in open.json. A new required checked field on each finding and entry is true only if its agent reported.
② collect — checks the output
  1. Every id answered. collect fails the job with an ::error:: when an id in open.json has no entry in previous, naming the ids. String ids are upper-cased and stripped of spaces first, so r21 still matches R21.
  2. All checked. It also fails when any new finding, or the entry for an id in open.json, has checked missing or false. collect doesn't read the wording of reasons or notes.
  3. Log agrees. collect then reads the job's execution log, claude-execution-output.json, written by the Claude action; the review artifact uploads the file collect read. It fails the job when a top-level Agent call's report didn't arrive before the reviewer's last top-level StructuredOutput call, the one that hands in its output (a call the schema rejects is retried), or before its result when there is no such call. Agent calls in that same message count, and can't have reported in time. A report is a foreground call's tool result, or for a background launch its completed <task-notification> in a user turn, which the reviewer sees; a system notification alone doesn't count. So agents started together with the output, or reporting after it, fail. A background launch is told by its tool result starting with "Async agent launched", so a call that leaves out run_in_background, which runs in the background by default, counts too. An Agent call whose result is an error, such as an API overload, still counts as reported, since the reviewer can retry it. It also fails when the log shows fewer Agent calls than findings plus open findings to check, a lower bound only, since the code-review skill's own reviewer agents count too, and when the log is missing or unreadable. The log's path comes from the review step's execution_file output, passed as EXEC_LOG, with $RUNNER_TEMP/claude-execution-output.json as the fallback. Each run prints "execution log: N agent calls, B in the background, L not reported before its output" to the job log.
  4. Re-run review. collect still saves findings.json and fix.patch for the run's artifact, and writes the reason to collect-error.txt: an open finding with no result, answers returned before their checking agents reported, or the execution log missing, unreadable, or showing agents not reported before the review returned or fewer agents than its findings to check. The code review comment then says "The review of <sha> is not recorded: <reason>. Re-run the review job (run)." Nothing shows as an unchecked "not fixed", and re-running the review job retries.

The three new checks in collect

  local missing unchecked err=
  missing=$(jq … '[.[].id] - [$f[0].previous[]?.id] | join(", ")' "$OUT/open.json")
  unchecked=$(jq … '[every new finding, previous entries for open.json ids
    | select(.checked != true)]
    | length' "$OUT/findings.json")
  [[ -z $missing ]] || err="it returned no result for open finding(s) $missing"
  (( unchecked == 0 )) || err+="${err:+, and }it returned before the checking agents of $unchecked finding(s) reported"
  local log=${EXEC_LOG:-${RUNNER_TEMP:-}/claude-execution-output.json} counts calls background late needed
  if [[ ! -s $log ]]; then
    err+="${err:+, and }it left no execution log at $log to check its agents against"
  elif ! counts=$(agent_log "$log"); then
    err+="${err:+, and }its execution log at $log could not be read"
  else
    read -r calls background late <<< "$counts"
    echo "execution log: $calls agent calls, $background in the background, $late not reported before its output"
    (( late == 0 )) || err+="${err:+, and }the execution log shows $late of its $calls agents not reported before it returned"
    needed=$(jq … '(.findings | length) + (open findings | length)' …)
    (( calls >= needed )) || err+="${err:+, and }the execution log shows $calls agents for its $needed findings to check"
  fi
  if [[ -n $err ]]; then printf '%s\n' "$err" > "$OUT/collect-error.txt"; echo "::error::the review is not recorded: $err; …"; exit 1; fi
collect never reads the wording. A note that quotes an agent not reporting, such as "the step 2 agent hadn't reported.", passes as long as its answer is checked and the execution log shows its agent reported in time.

Glossary

Code review job
CI's job that has Claude review every code push and report findings R1, R2, ….
Checking agent
A fresh agent the reviewer starts to confirm or disprove one finding.
run_in_background
An agent setting: when true, or left out, the agent runs in the background and the reviewer carries on without its answer.
open.json
The findings from earlier reviews that are still open, written before each review.
previous
The part of the review's output that says, for each open finding, whether it is now resolved.
CONFIRMED / PLAUSIBLE
A finding's verdict: confirmed by its checking agent, or not (yet) confirmed.
collect
The step of review-proof.sh that saves the review's output and fix after the review.
checked
A new field on each finding and previous entry: true only if its checking agent reported.
Execution log
claude-execution-output.json: every message and tool call of the review, written by the Claude action.
::error::
A GitHub Actions log line that shows as an error on the failed job.
