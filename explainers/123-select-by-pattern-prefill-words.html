Part 1

What this PR adds

The Select by Pattern dialog keeps the last pattern and a new “Match words” checkbox in memory until Thunar quits, all in thunar-standard-view.c and its view model.

you new code in this PR what you see

The big picture

Edit → Select by Pattern (Ctrl+S) selects every file in the folder whose name matches what you type. It used to open empty every time, and it only took wildcard patterns, so cp-detail-tx-w 2post, which works in Search, matched nothing. Now the dialog remembers your last pattern, and by default reads it as words, the same way Search does.

Both memories are plain variables in the running Thunar program. Nothing is written to Thunar's settings (xfconf), so they are gone when Thunar quits, which usually means when the last window closes.

Step by step (numbers match the diagram)

① #123 Last pattern
  1. Press Ctrl+S. In any folder of any Thunar window, thunar_standard_view_select_by_pattern builds the dialog, as before.
  2. Prefilled. If a pattern was saved, the box is filled with it. The text is highlighted only after the dialog is shown and the box has focus, so GTK doesn't clear the highlight. Enter reuses it; typing replaces it.
  3. Select saves it. Only Select saves, and only a non-empty pattern. It saves the text as you typed it, before a bare word is wrapped as *word*, so reuse never adds extra stars. Cancel saves nothing.
  4. Next dialog. The pattern is one file-level static variable, so every folder and window shares it, and it survives closing a window. Thunar already keeps app-wide memory this way, in thunar-file.c and thunar-notify.c.
② #124 Match words
  1. Match words. A third checkbox, “Match words, like Search (Ctrl+F)”, sits below Case sensitive and Match diacritics. It is on the first time, and Select saves its state the same way as the pattern. The info icon's tooltip switches to explain the mode that is ticked.
  2. Split into words. The new thunar_standard_view_model_get_paths_for_words normalizes the text and splits it with Search's thunar_util_split_search_query. !word excludes a word and \! is a literal !. A pattern with * or ? is matched as a wildcard pattern instead, so a habit like *.png still works, and the tooltip says so. A box of only spaces, Unicode ones included, selects nothing.
  3. Every word in. The same loop over the folder's rows that the wildcard mode uses now calls Search's thunar_util_search_terms_match when it has words. Case sensitive and Match diacritics still apply, which Search itself never does.
  4. Files selected. The rest is unchanged: unselect all, put the cursor on the first match, select every match. With the box unticked, the old wildcard pattern runs exactly as before.

Built on 3 known-good references

Search (Ctrl+F)

Word mode calls Search's own split and match functions from thunar-util.c, so it reads a query exactly as Search does.

The wildcard mode

The new function copies the setup of get_paths_for_pattern and shares its loop over the rows, so both modes see the same files.

Static app memory

The file-level static variables follow thunar-file.c and thunar-notify.c, which keep app-wide state the same way.

Glossary

Select by Pattern
Edit menu item (Ctrl+S) that selects every file whose name matches what you type.
Wildcard pattern
? is any one character and * any run of characters, e.g. *.txt.
Word mode
The text is split at spaces; a name must contain every word, in any order. With * or ? it is a wildcard pattern.
!word
In word mode, leaves out names that contain that word.
Diacritics
Accents on letters, like the é in Résumé.
static variable
A C variable kept for the life of the program, shared by every window.
xfconf
Xfce's settings store; things saved there survive a restart.
gtk-doc
The tool that builds API docs from special comments; it warns about incomplete ones.
verify script
verify/<issue>.sh: drives Thunar on a virtual screen, checks the result, takes screenshots.
debs
Debian packages built from this branch and installed to test it.
