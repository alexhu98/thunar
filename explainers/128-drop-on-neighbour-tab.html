PR #130: Alt+Page Up and Alt+Page Down drop the selection on the neighbouring tab

Branch 128-drop-on-neighbour-tab → main, closes #128, in PR #130. Two new keys send the selected files to the previous or next tab's folder, exactly as dragging them there would. In split view the tab order runs through the left pane and on into the right, so the keys cross the split.

Part 1

What this PR adds

Two new window actions, Drop on Previous Tab and Drop on Next Tab, bound to Alt+Page Up and Alt+Page Down and listed in the Edit menu. They reuse Insert's code from #95, which now takes any tab as its target instead of only the other pane.

new in this PR Insert's code from #95, now shared you

The big picture

Insert (#95) already sends the selection to the other pane in split view. But a window often has several tabs in each pane, and getting files into a tab next to the current one still took a drag. Now Alt+Page Up and Alt+Page Down do it, mirroring Ctrl+Page Up and Ctrl+Page Down, which switch to those same tabs.

The new keys don't have a transfer of their own. Insert's two helpers were changed to take the target tab as an argument, so Insert, the two new keys and their menu items all go through the same checks and the same move-or-copy rule as a drop.

Step by step (numbers match the diagram)

① Alt+Page Up / Down
  1. You press a key. Alt+Page Down drops on the next tab, Alt+Page Up on the previous one. Files are selected in the current tab and keyboard focus is in its file view. In a text field, such as the location bar or a rename entry, or outside the file view, nothing moves and the key goes on.
  2. Find the tab. The new thunar_window_neighbour_tab_view in thunar/thunar-window.c takes the current tab's position in its pane and adds or subtracts one. In split view, next from the left pane's last tab is the right pane's first, and previous from the right pane's first is the left pane's last. Past the very first or last tab there is nothing: no wrap-around.
  3. Which files? thunar_window_view_drop_files, Insert's file-list helper renamed and given the target tab, takes the folder that tab shows now, which must be loaded and writable. Selected files already in that folder are skipped, so a tab showing the same folder gets nothing, and a drop's refusals apply.
  4. Drop, as Insert. thunar_window_drop_on_view, Insert's old action body, keeps its keyboard check and calls thunar_file_drop_copy_or_move: move on the same filesystem, copy across filesystems, always move into the Trash. The transfer is a normal job with progress and undo, and focus stays on the tab you started from.
② Same pieces, other ways in
  1. Edit menu items. Drop on Previous Tab and Drop on Next Tab sit right after Drop on Other Pane, each greyed out unless it would really move something. Both keys can be changed in accels.scm or the shortcuts editor, like any other action.
  2. Insert, as before. Drop on Other Pane now asks thunar_window_other_pane_view for its target, then runs steps 3 and 4. Its behaviour is unchanged: the review's new text-field check below never stops it, because a text field uses Insert itself.

The key change

static gboolean
thunar_window_action_drop_on_other_pane (ThunarWindow *window)
{
  return thunar_window_drop_on_view (window, thunar_window_other_pane_view (window));
}
… drop_on_previous_tab: drop_on_view (window, neighbour_tab_view (window, -1));
… drop_on_next_tab:     drop_on_view (window, neighbour_tab_view (window, 1));

Each of the three actions is now one line: pick a target tab, then hand it to the shared drop. Only the way the target is found differs.

Glossary

Tab
One folder view among several in a pane, picked by its label at the top.
Split view
F3: two panes side by side in one window, each with its own tabs.
Notebook
GTK's name for a row of tabs and the pages behind them; each pane has one.
Neighbouring tab
The tab just before or after the current one, in the order left pane then right pane.
Wrap-around
Going from the last tab back to the first; these keys don't.
Drop
Letting go of dragged files over a folder.
Drop rule
Thunar's choice between move and copy when you drop with no modifier key.
Same filesystem
On the same disk or partition, so a move is just a rename.
Window action
An entry in Thunar's action table: a name, a default key and a handler.
accels.scm
The file where Thunar keeps your changed keyboard shortcuts.
Keyboard focus
The one widget that gets key presses, such as the file view or the location bar.
Text field
A box you type into: the location bar, a rename entry or the search box.
verify/128.sh
The test script CI runs: it drives Thunar with xdotool and takes screenshots.
Pair
A before and after screenshot around one action in a test.
xfwm4
Xfce's window manager, which the tests run under.
