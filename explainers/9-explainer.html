Part 1

What this PR adds

A skill that writes the page, a CI job that requires it and posts it into the PR as an image, and an optional script that narrates it as a video.

you, or the agent writing the PR runs on every PR, in CI

The big picture

A pull request's “Files changed” tab shows what changed, line by line, but not what it means, how it was checked, or what it leads to. PR #8 came with a hand-made page that did: a diagram, numbered steps, the checks that were run, and the issues that come next. This PR makes that page part of every issue PR. A skill tells whoever writes the PR, you or a cloud agent, how to write it. CI refuses a PR without one, and shows it inside the PR.

GitHub shows an HTML file in a private repo as source code, not as a page. So CI takes a picture of the page and puts the picture in a PR comment, where it reads on github.com and on the phone.

Step by step (numbers match the diagram)

① On the branch: write the page
  1. Skill writes the page. The explainer skill in .claude/skills/explainer/ starts from template.html, a copy of PR #8's page with the content taken out. It says what goes in each of the three parts, and the rule that matters most: claim only what was actually run. The new root CLAUDE.md tells every session, including cloud ones, that each issue PR needs this page.
  2. Check it locally. .github/scripts/explainer-proof.sh render makes the same image CI will make, so the writer can look at it before pushing.
  3. Push, open the PR. A PR into main starts build.yml. Next to the build job from PR #8, it now runs a second job, explainer, which needs neither the build nor Thunar.
② explainer job: require, render, post
  1. Require it. If the branch is named <n>-<slug>, the job lists the files the PR adds or changes (git diff --name-only origin/main...HEAD) and fails unless one is explainers/<n>-*.html. Other branch names, such as a dependency bump, are exempt. Deleting an explainer doesn't count as having one.
  2. Render it. Headless Chrome, already installed on GitHub's Ubuntu 24.04 machines, opens the page in dark mode, 1200 pixels wide. It measures how tall the page is, then takes one screenshot exactly that tall, so the whole page fits in one image with nothing to trim. It also checks the page at phone width (390 pixels) and warns if it scrolls sideways.
  3. Upload to shots. The image is committed to the shots branch as pr-10/explainer-9.png through GitHub's contents API. The comment links the image by that commit, not by the branch, so every push shows its own image, never a cached older one.
  4. One PR comment. The job looks for its comment by a hidden <!-- pr-proof --> marker. If there's none, it creates one. Otherwise it replaces only the text between <!-- explainer:start --> and <!-- explainer:end -->, so whatever else is in the comment stays.

The PR comment, with room for #7

One comment collects all the proof a PR gets. This PR writes the explainer section. Issue #7's verify job will later add its own section to the same comment instead of posting a second one.

Who can write what

Only this job may write

The workflow stays read-only. Only the explainer job gets contents: write (to commit images to shots) and pull-requests: write (to comment). The build job is unchanged.

Only the last step gets the token

The checkout keeps no credentials, and the check and render steps run without GH_TOKEN. Only the upload-and-comment step gets it.

Fork PRs are skipped

A PR from a fork runs with a read-only token, so this job couldn't upload or comment. It is skipped, the check included.

The optional video

  • The narration file is the script: for each spoken line, the caption shown on screen, the words actually spoken (respelled where the voice gets them wrong), the part of the page to show, and what to highlight. It also remembers the page text each line was written from.
  • When the page changes, make-video.py status names exactly the lines whose page text changed. Only those are rewritten, so the video never describes an older page.
  • Each line is voiced by Kokoro, a speech model that runs on the desktop. Clips are cached by their words, so an unchanged line is never voiced again.
  • The page is the slides. The script opens a temporary copy of the page with a 1920×1080 video mode added: one section at a time, the rest of it dimmed around the highlight, a caption, and a chapter bar. The committed page never changes.
  • ffmpeg joins the frames and the voice. Frame times come from counting audio samples, so picture and sound stay in step.

What it was built from, what was checked and how, and what wasn't checked.

Built on three references

PR #8's page

explainers/1-ci-build.html, made by hand: three parts, colours for dark mode, inline diagrams, tables. The template keeps its styles and layout, and adds the ids and keys the video needs.

PR #8's video

A one-off script made 1-ci-build.mp4 with slides and narration written into it. make-video.py keeps its voice, timing and ffmpeg steps, and replaces the hand-made slides with the page itself.

PR #8's scripts

explainer-proof.sh follows the release scripts: a short header, set -euo pipefail, DRY_RUN=1, and the token only on the step that calls GitHub.

Code review

A medium code review of the whole diff, before the first push, found 10 issues. 8 are fixed in this PR; 2 are kept as decided in #9.

  • CI script: a page list left by an earlier local run could be reused; a missing image would have been uploaded empty; a failed first upload could garble the image link.
  • Video script: paths with spaces or quotes broke it; chapter names containing # weren't escaped for ffmpeg; a caption containing </script> would break video mode; every render checked the page twice.
  • Kept as decided: fork PRs skip the whole job, the check included; two pages for one issue in one PR would share one image name.

Glossary

Explainer
The page every issue PR adds in explainers/: what it adds, how it was checked, what comes next.
Skill
A folder of instructions (and helper files) that Claude Code loads when a task matches it.
CLAUDE.md
Instructions every Claude Code session in this repo reads first, cloud sessions included.
Job
One part of a GitHub Actions workflow, run on its own fresh machine; build and explainer run side by side.
Headless Chrome
Chrome running without a window, used here to take a picture of the page.
shots branch
A branch that holds only images, one folder per PR, so they never mix with the code.
Contents API
GitHub's way to commit one file to a branch over the web, without a git checkout.
Marker
An HTML comment such as <!-- pr-proof -->: invisible in the PR, but a script can find it.
Token
GH_TOKEN: the job's short-lived key to the repo; only the step that posts gets it.
Fork PR
A PR from someone else's copy of the repo; its token can't write here.
Kokoro
A small text-to-speech model that runs on the desktop; af_heart is the voice.
Phonemes
The sounds a voice will say for a word, written out; how pronunciation is checked without listening.
Chapters
Named points in an mp4 that players show as a list to jump to.
