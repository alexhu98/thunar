The big picture

Every PR's verify job saves its screenshots on the shots branch, one commit per file. On PR #51, six of about ten runs failed with images missing although every test passed: GitHub answered some uploads with an empty body or a server error, and the script only retried clashes. Separately, the verify job had no gvfs, so the per-folder "Include subfolders" setting from #21 was never checked on disk. And every green PR waited on you for a merge.

An upload can succeed even when its answer is lost. Retrying blindly would commit the file twice or clash with itself, so after a hiccup the script first checks whether the file is already on shots.

Step by step (numbers match the diagram)

① One upload (#59)
  1. Commit the file. verify-proof.sh or explainer-proof.sh calls shots.sh with one file, and one Contents API PUT commits it. On success it prints the commit's sha, as before.
  2. Sort the error. HTTP 409 or 422 is a clash with another writer: retry. Any other 4xx, such as 401, 403, 404 or 413, is a real problem: fail at once. Everything else is a hiccup and is retried: 5xx, 429, a rate-limit answer, an empty body or a dropped connection.
  3. Did it land? After a hiccup, each new attempt first reads the file's blob on shots. If it equals the local file's git hash-object, the upload went through, so the script prints the latest commit for that path and stops.
  4. Wait, then retry. The same backoff as before: 2, 4, 8, 16 and 30 seconds plus random jitter, 6 attempts in all. After the last one it checks once more whether the upload landed. If not, it fails, and the run's later uploads get 1 attempt each, so an outage can't push the job past its time limit.
② The verify job (#48)
  1. Install gvfs. gvfs and gvfs-daemons join the test tools in verify-proof.sh. The cached debs lack them, so the first run installs them with apt and caches the new set.
  2. Metadata on disk. Each test already runs in its own D-Bus session. GIO's first metadata write starts gvfsd-metadata there, which keeps its store in that test's fresh data folder.
  3. 21.sh runs it all. verify/21.sh sees the metadata namespace as writable, so its on-disk and restart checks run instead of being skipped.
③ Merging a PR (#60)
  1. Check the gate. On the head commit: build, verify, explainer, review and summary green and their steps actually run; every finding fixed, none accepted by the agent; the latest visual-verify verdict PASS; no comment of yours unanswered; the narration stamped.
  2. Agent merges. It squash-merges its own PR with the repo's usual title, the issues then the PR number.
  3. Or asks you. A finding that needs a decision, a FAIL or INCONCLUSIVE verdict, CI failing twice on the same thing, or a surprise ends the turn with a question. Upstream merges and PRs the agent didn't open stay yours.

Part 3

What comes later: cutting CI minutes

This is the first of four PRs for the CI issues filed after Actions ran out of minutes on 7 November. Each opens after the one before it merges, and the agent merges each under this PR's rule.

built by this PR not built yet

Review costs: #52, #53, #54 (next)

  1. Skip the bot's own fixes. CI stops reviewing its own fix commits (#52).
  2. Skip superseded heads. A review whose head a newer push replaced stops early (#53).
  3. A lighter review. high instead of xhigh, with a 30-minute cap (#54).

Build costs: #55, #57

  1. Skip what isn't code. Build and verify skip PRs that change only explainers, skills or Markdown (#55).
  2. Cache the compiler. ccache keeps the last build's objects, so a small change compiles in seconds (#57).

Fewer jobs: #56, then maybe #58

  1. Fold small jobs. review-report into review and release into build, since each job is rounded up to a whole minute (#56).
  2. Reuse the PR's debs. A push to main reuses its merged PR's build, if the version stamp allows it (#58).

Glossary

shots branch
A branch with no code, holding every PR's screenshots under pr-<n>/.
Contents API
GitHub's web API that commits one file per call.
Hiccup
A passing GitHub failure, such as a server error or an empty answer, that a later try gets past.
Blob sha
Git's id for a file's content; the same bytes always give the same id.
gvfs
GNOME's add-on to GIO that, among other things, stores per-file metadata such as Thunar's folder settings.
D-Bus session
The message bus that starts helper services, such as the metadata store, when a program first asks for them.
Squash merge
Merging a PR as one commit on main.
