PR #88: a 5 px gap between the search entry and the Include subfolders toggle

Branch 68-toggle-margin → main, closes #68. While you search, the Include subfolders toggle no longer touches the search entry: it sits 5 px from it, the same as from the search button.

Part 1

What this PR adds

One line in thunar/thunar-location-entry.c gives the toggle a 5 px start margin, and verify/68.sh measures both gaps on the screen in three toolbar layouts.

already in Thunar (#21) new in this PR

The big picture

Issue #21 added an Include subfolders toggle to the right of the search entry. Its right side had a 5 px gap to the search button, but its left side was glued to the entry's border, so it looked like part of the entry. Issue #68 measured 0 px on the left and 5 px on the right, and asked for 5 px on both sides.

The 5 px on the right was never the toggle's: it is DEFAULT_LOCATION_BAR_MARGIN (thunar/thunar-window.c:70), the margin around the whole location bar. The toggle itself had no margin, so the fix gives it the same 5 px on its start side.

Step by step (numbers match the diagram)

① Searching in Thunar — the fix
  1. Press Ctrl+F. The location bar turns into a search entry, and typing a word starts a search in the current folder.
  2. Toggle appears. The Include subfolders toggle shows at the entry's right end only while a search runs, and hides again after Escape. That behaviour comes from #21 and is unchanged.
  3. 5 px margin. In thunar_location_entry_init, where the toggle is created, the PR adds gtk_widget_set_margin_start (…subfolders_button, 5). The box that holds the entry and the toggle has no spacing, so this margin is the whole gap.
  4. Entry gives 5 px. The entry stretches to fill the space, so it is the one that gets 5 px narrower. The toggle keeps its size, and the gap from the toggle to the search button stays as it was.
② verify/68.sh — how it is checked
  1. Search, capture. The script opens Thunar at 1000×700 in a folder with match-top.txt and sub/match-sub.txt, presses Ctrl+F, types match, and takes the after shot of the window. The gaps are measured on that shot file itself, before it is cropped for the comment.
  2. Measure gaps. On each pixel row of the toolbar it marks pixels bright or dark and looks for the pattern shown below. It keeps only the rows where the toggle is at full width and fails unless both gaps are 5 px ±1.
  3. Three layouts. It restarts Thunar with the menu bar hidden, then in the header bar (client-side decorations on), and measures again. In the header bar the location bar has 15 px margins, so the gap to the search button is expected to be 15. Each restart first waits for the old Thunar to leave the session bus (org.xfce.Thunar).
  4. Still works. Before the search and after Escape, some row through the toggle's place, found while searching, must be one colour from 4 px inside the entry's border to 2 px inside the toggle's right end: the entry reaching over that place. A shown toggle, pressed or flat, breaks that run with the border, the gap and the toggle. Clicking the toggle must change a 30×20 patch around it and re-run the search: the results are copied and pasted into a folder, and only match-top.txt may arrive.

The pattern step 6 looks for on one pixel row

dark run: every channel below 64 bright run: any channel 64 or more

The row comes from convert … txt:-, which prints one line per pixel, and awk groups it into runs. The awk sticks to what mawk, Ubuntu's default awk, understands.

Why a margin: the gap on the toggle's right, from the location bar to the search button, is also a margin, gtk_widget_set_margin_end (window->location_bar, DEFAULT_LOCATION_BAR_MARGIN) (thunar-window.c:7034). The toggle's left gap is built the same way. You kept this line over CI's R6 and R7 (Part 2).
In the header bar the toggle is 5 px from the entry but 15 px from the search button, because the header bar puts 15 px around the whole location bar as a window drag area. This PR keeps the 15 px, as reported on the PR.
To undo it, revert this PR. Nothing is stored in settings; the margin is set each time the search bar is built.

Code review

A fresh general-purpose agent, given only the diff and the issue, reviewed the PR in this session. It found 3 things, all in verify/68.sh and none in Thunar's code, and all 3 were fixed before the first push.

  • Medium, idle check: the check that the toggle is hidden before a search could never notice a toggle that is always shown. It now needs a row where the entry reaches over the toggle's place (reworked after CI's R3 and R4, below).
  • Low, paste wait: the wait for the pasted results could end while the copy was still running. It now waits for the paste to settle.
  • Low, compare error: an error from compare counted as "the toggle changed". Only a pixel count above zero counts now.

CI's first review (run 42747354049, level high, on head 953fb6d) found 8 things, R1 to R8: 6 are fixed, and you accepted R6 and R7. Every finding is listed in the code review comment on PR #88.

  • R1, medium, confirmed: no explainer. The PR had no explainer page yet. This page, added in commit 429c69e, fixes it.
  • R2, medium, plausible: compare on ImageMagick 6. compare -crop might not work there. It passed locally on noble, but the click check now crops both images to 30×20 first and compares those.
  • R3 and R4, low: idle colour. The entry's inside colour was sampled while the entry had focus. The new idle check samples no colour, so both are fixed.
  • R5, low: restart race. A restarted Thunar could start before the old one left D-Bus. The restart now waits for that.
  • R8, low: extra captures. The gaps were measured on separate captures, not on the shots. They are now measured on the shot files, before cropping.
Accepted, by your decision: R6 (low) suggested box spacing 5 instead of the toggle's margin, and R7 (low) said the literal 5 copies DEFAULT_LOCATION_BAR_MARGIN. The PR keeps the issue's gtk_widget_set_margin_start (…, 5): the gap to the search button is also a margin (thunar-window.c:7034), the box's spacing is 0 on purpose (thunar-location-entry.c:191), and DEFAULT_LOCATION_BAR_MARGIN is private to thunar-window.c. Your decision is recorded in a comment on PR #88.

Glossary

Include subfolders toggle
The button at the end of the search entry that switches searching in subfolders on and off (#21).
Search entry
The location bar's text field while you search, after Ctrl+F.
Location bar
The path field in the toolbar; it holds the search entry, the toggle and the search button.
Margin
Empty space GTK keeps around a widget; a start margin is on its left.
Header bar
The window's title bar drawn by Thunar itself (client-side decorations), with the toolbar inside it.
misc-use-csd
The Thunar setting that turns on client-side decorations, so the header bar is used.
Xvfb
A virtual screen with no monitor, where the tests run Thunar and take screenshots.
ImageMagick txt:
An output format that prints every pixel's position and colour as one text line.
mawk
Ubuntu's default awk, which lacks some GNU awk features.
Shot pair
A before and an after screenshot that CI joins into one image in its verify comment.
Review-accept
A commit trailer that closes the CI review findings it lists as accepted, kept on purpose.
Shot-auditor
An agent that looks at each screenshot and says whether it shows what its caption claims.
