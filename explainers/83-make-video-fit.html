Part 1

What this PR adds

Two changes to how make-video.py picks each frame's zoom, and one to what its status command reports. No page is edited.

new in this PR unchanged

The big picture

videos-all.sh on main failed to render 3 videos. Page 23's 24-line file tree is too tall to fit at the minimum zoom of 1.55. On pages 55 and 64, the checks table is wider than its column, because its result cells don't wrap, so its rows ran off the right edge. And only render, which runs on your machine, noticed.

The zoom only goes lower than before when content would otherwise be cut off. On every other frame of all 23 narrated explainers, it is exactly what it was.

Step by step (numbers match the diagram)

① Each frame: build() picks the zoom
  1. Widen the box. Video mode lays a screen out in a 1060 px box. build() now finds the largest overflow inside it, the most any element's content is wider than its own box, and widens the box by that much, so a wide table fits across.
  2. Pick the zoom. Unchanged: the largest zoom that fits the stage, up to 1.9 for a subsection, and at least 1.55 when the width allows it. It now uses the widened box's width.
  3. Fit highlights. New: the highlighted elements' combined height, plus room for their outline, must fit the 733 px stage. If not, the zoom goes down until it does, even below 1.55.
  4. Check the frame. Each highlighted element must be fully on screen and the caption at most 2 lines, as before. New: a zoom below 1, too small to read, is also a problem.
② Who sees a problem
  1. status reports. make-video.py status already probed every frame but threw the problems away. It now prints each as video mode problem: line 25: … and exits 1. CI runs it on every narration when make-video.py changes.
  2. render refuses. render still stops on the same problems, through the same shared function.

Also folded in: #85, no more manual crash check

CLAUDE.md said the split-view crash regression test stays a manual check after an update, so sessions asked you for it in every explainer and upstream-merge PR. You ran it on +local23 with no crash; 4.20.10 earlier had 0 crashes in 65 runs.

  • CLAUDE.md: the line in the Verify section is deleted.
  • upstream-merge/SKILL.md: the check is dropped from the merge issue's Done-when list and from the merge PR's body.
  • Older explainers still mention it: they describe their PRs as merged, and editing them would make their narrations stale.

Code review

After the code was pushed, a fresh general-purpose agent reviewed the diff against the issue. It re-ran the before-and-after zoom comparison on its own and found no significant bugs, and 4 low findings, 3 fixed in a second push:

  • Widening that doesn't help: a box with a fixed width would be widened, and its zoom lowered, with nothing gained. Now the widening is undone when the overflow remains.
  • Highlights far apart: two keys at opposite ends of a tall screen could push the zoom too low to read. A zoom below 1 is now a problem too.
  • stamp was silent: it now lists the video mode problems, so they show up before CI's check fails.
  • Kept: the 16 px outline margin could lower a zoom that fit within 16 px. No current frame does, as the comparison shows.

CI's review of each push is in the code review comment on PR #84.

Glossary

Video mode
How make-video.py shows a page: one screen at a time, zoomed, highlighted keys lit, others dimmed.
Stage
The 1760 × 733 px area of each 1920 × 1080 frame that shows the page, above the caption.
Probe
One headless Chrome run that lays out every frame and returns its zoom and problems.
Highlight
An element named in a narration line's keys; it must be fully on screen.
Kokoro
The local text-to-speech model that voices the narration; only on your machine.
