Part 1

What this PR adds

A new Step 0 in the skill, before its preflight, for pr:<n>, fed by the pr-digest agent, which now names the No code changed step in its checks line.

new check unchanged audit what you see when it stops

The big picture

Since #55, a PR that changes only explainers, agent setup or Markdown builds nothing: build and verify each run a No code changed step instead of their real steps, and no shots reach the shots branch. CLAUDE.md already says no audit is needed then, but the skill still said to run after every verify run. Run anyway, it found no manifest for the head and returned INCONCLUSIVE, which sends the PR to the owner.

The skill can't call the GitHub API itself, so it gets the step names from pr-digest, which already reads the build run's jobs.

Step by step (numbers match the diagram)

① /visual-verify pr:<n>: the new Step 0
  1. Ask the digest. Before reading any manifest, the skill takes the checks: line of a pr-digest digest whose head is the PR's current head: the caller's, or a new one it starts.
  2. Read the steps. pr-digest now writes, for build, verify and explainer, whether each ran its steps, ran No code changed, or skipped them all, from the build run's job list. While build or verify is still running or queued, the skill stops with NOT YET and runs again on CI's next event.
  3. Both no code? The skill stops only when build and verify both ran No code changed. A missing or stale manifest alone never counts, so a verify run that skipped by mistake still gives INCONCLUSIVE.
  4. Not needed. It ends with VERDICT: NOT NEEDED (build and verify ran No code changed) and posts no PR comment. The summary already shows “not needed” for that head, and pr-digest now says so too.
② Otherwise: the audit as before
  1. Preflight. Step 1's existing checks follow unchanged: the manifest exists, every shot has its intent, and its SHA is the head's.
  2. Audit, verdict. shot-audit reads every PNG, and the skill prints the table and its verdict for the PR comment, as before.

Code review

Before the first push, a fresh general-purpose agent reviewed the diff against the issue and found 6 problems, all fixed:

  • Ambiguous wording in pr-digest: “ran only its step” is false for build, which also checks out and checks what changed; and which of job or step must succeed. It now says the job and the step both succeed.
  • Contradictions in the skill: Step 1 says every failure is INCONCLUSIVE, and the contract says the last line is always VERDICT:. The check moved to its own Step 0, and the contract names the exception.
  • Gaps: a caller's old digest could be reused, and a run still in progress fell through to INCONCLUSIVE. The digest must now match the head, and an unfinished build or verify no longer falls through.

CI's first review found 9 low findings, 2 of them confirmed. All are fixed in one push, except R7, which the owner accepted:

  • Docs out of step: the skill and its README said pr:<n> needs only git, and the README's contract never mentioned the new exit (R1, R3).
  • One output shape: the stop is now a verdict, NOT NEEDED, so the last line is always VERDICT:, with no ambiguous quoted message (R6, R9).
  • No waiting: instead of waiting with no limit, a queued or running build or verify ends with NOT YET (R4, R5; a missing one goes on, after R10).
  • Digest wording: only build and verify can show No code changed, and the digest's audit line now says “not needed” (R2, R8).
  • CI's second review: R10, medium, confirmed: a check the digest reported as missing gave NOT YET forever. Now only a running build or verify does, and a missing one goes on to the preflight. Also fixed: the skill's description names the new verdicts (R12), and the digest says when to print “not needed” (R13).
  • Accepted with a trailer: R11, since the callers already skip the audit on no-code runs by CLAUDE.md's rule, so nothing posts the new verdicts; and R14, since build and verify always skip together.
  • Accepted by the owner: R7, a full digest where one jobs call would do, because CLAUDE.md routes every read of a PR's checks through pr-digest. All findings are in the code review comment on PR #77.

Glossary

No code changed
The step build and verify run, instead of their real steps, on a PR that changes no code, packaging or CI files.
/visual-verify
The skill that audits CI's screenshots and posts a PASS, FAIL or INCONCLUSIVE verdict.
NOT YET
The unposted verdict while build or verify hasn't finished; the skill runs again later.
pr-digest
A read-only agent that sums up a PR's CI state in about 20 lines.
INCONCLUSIVE
The verdict when the audit can't be trusted; it sends the PR to the owner.
verify.tsv
The manifest of shots CI writes to the shots branch, one row per shot.
