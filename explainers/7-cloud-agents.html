Branch 7-cloud-agents → main, refs #7 (sections 1–3). Every PR now gets a verify job: it installs the PR's Thunar under a virtual display, checks that it starts, runs the PR's own test script and posts the screenshots in the PR comment. new in this PR already on main the agent and you

The big picture

Issue #7 hands features to Claude Code sessions in the cloud. Such a session writes the code and opens a PR, but its sandbox may not be able to build or run Thunar, and a report saying "it works" proves nothing. So the proof has to come from CI: a job that installs exactly the debs the PR built, runs Thunar on a virtual screen, drives it like a user and photographs the result. The cloud session also can't see the owner's personal Claude settings. So the rules it must follow, and the skill that checks screenshots, have to live in the repo.

The PR comment's verify section is the proof: CI ran the script, and the screenshots are what it saw. An agent's own report is not proof, and neither is a green check whose pictures nobody looked at. Before you merge, look at the shots.

Step by step (numbers match the diagram)

① verify job
  1. Build (#1). The existing build job makes the PR's 5 debs and uploads them as the debs artifact. verify waits for it (needs: build) and downloads them into dist/.
  2. Install. verify-proof.sh install installs thunar, thunar-data and libthunarx-3-0, plus Xvfb, xfwm4, xdotool, ImageMagick and Zorin's GTK themes. It first tries the debs cached for this runner image with one dpkg -i. If any of them doesn't install, or a tool is missing, it uses apt with ppa:zorinos/stable, which repairs what dpkg left. It then saves the installed versions as a new cache entry.
  3. Smoke test. verify-proof.sh run gives the test its own Xvfb, xfwm4 and D-Bus session, and launches Thunar on a folder of 2 folders and a file. It checks that Thunar is still running after 10 s and photographs its window (import -window).
  4. Feature tests. Then each verify/<issue>.sh runs the same way, with its own Xvfb, D-Bus session, HOME and XDG folders, for at most 120 s. A script with any other name fails the job unrun. The script drives Thunar with xdotool and checks the result (window title, files on disk). It saves before/after shots, each with a sentence saying what it proves, and exits non-zero on failure.
② publish
  1. Shots branch. verify-proof.sh publish commits each PNG to the orphan shots branch as pr-<n>/verify-<test>-<shot>.png, through the new shots.sh, which the explainer job now shares. It also commits the manifest verify.tsv, with each shot's file, result, caption and commit.
  2. PR comment. It writes the verify section of the comment marked <!-- pr-proof -->, beside the explainer and review sections. The section has a results table, the log tail of any failed test, and each screenshot under its caption. It runs even when a test failed, so a broken feature still shows its pictures.
  3. Audit, merge. The agent runs /visual-verify pr:<n>. That skill fetches the shots and the manifest from the shots branch with git alone. A read-only auditor reads every PNG and checks its caption. You review the shots and merge only when build and verify are green.

A closer look at the pieces

Repo CLAUDE.md

Branches <issue>-<slug> into main, with Closes or Refs; never upstream, master or xfce-4.20. It also has the build lessons, the verify/<issue>.sh contract and the explainer and review rules. Two of the owner's own rules come along: no new explanatory comments, and audit every screenshot.

visual-verify, shot-audit, shot-auditor

Ported from nx-connect-ui. They keep the gate (PASS, FAIL, INCONCLUSIVE), the read-only auditor, the BLANK and MISMATCH verdicts and the mandatory before-to-after section. Storybook and Playwright give way to Xvfb, xdotool and import, and Figma, the 403 tripwire and the clip check are gone.

verify-lib.sh

What a feature script sources: open_thunar, focus, wait_title, shot, fail. focus exists because GTK ignores xdotool key --window, which an early test run showed.

The deb cache

Keyed by the runner image (ImageOS, ImageVersion), so a new image starts fresh. A hit skips the PPA, apt-get update and the downloads. A miss saves a new entry. The run on main warms the cache for every PR on the same image, because a PR can't read another PR's cache.

Theme

Zorin's GTK theme is in the PPA (zorin-desktop-themes, 0.6 MB), so shots use ZorinBlue-Dark, the owner's theme. Adwaita-dark is the fallback if it's missing. The 46 MB Zorin icon theme is left out, because screenshots prove behavior, not pixels.

Pinned image links

The issue writes blob/shots/…. The comment links each image by the shots commit that added it (blob/<sha>/…), as the explainer already does, so a later push can't show an old picture under new results.

Code review

A fresh general-purpose agent was given only the diff (at 7d054baf3) and issue #7. It found 6 issues: 1 medium, 3 low and 2 in the docs. All 6 were fixed and re-run in the container. It also reproduced the cache-fallback bug on the earlier commit and confirmed the fix. Then CI's review of the first push (Opus 5.5 at xhigh, 20 min) found 15 more, 5 of them medium. It may not change .github/ or .claude/, so they were fixed by hand: 13 fixed, 2 low ones accepted. Its verdicts on each push are in the PR comment's review section.

  • Isolation (medium): GitHub's runner sets XDG_CONFIG_HOME, so Thunar's settings would have leaked from one test to the next despite the fresh HOME. Each test now gets its own XDG folders.
  • Second window: a second open_thunar hands off to the running Thunar and exits, so it found no window. It now waits for that instance's new window.
  • Captions: a caption with a tab or line break split the manifest and stopped publish. shot now refuses it.
  • Failed uploads: one failed upload skipped the whole comment, so it kept the last push's results. The shot is now marked and the job still fails.
  • Docs: two lines on this page described the cache wrongly. They are fixed.
  • CI R3 (medium): tests shared one X server, so the next test's window-manager check could see the last test's xfwm4. Each test now starts its own Xvfb.
  • CI R2 (medium): a failing test's log, pasted into the shared comment, could fake the review state line that review-proof.sh reads. Log lines are now indented, with backticks replaced.
  • CI R1, R4, R5 (medium): the manifest now marks a lost upload as file -. The skill fetches shots with an explicit refspec, which works in single-branch clones. Scripts get 120 s each, under a 20-minute step limit, so a hang can't stop the comment.
  • CI, low: duplicate shot names and scripts not named verify/<issue>.sh now fail. A killed test is reported as a timeout. No sleep after the last failed upload, and no apt-get -f on a plain cache miss. The dry run moved into shots.sh, an explanatory comment was removed, and an empty cache folder can't stop install.
  • CI, accepted: R11, one commit per screenshot, is fine at a few shots per PR. R14, releases don't wait for verify, is by design, because the owner's merge is the gate.

#7 section 4: the sandbox check (next)

  1. An agent implements #3. A web session implements double-click on blank space to open the parent folder, from branch 3-…. It adds verify/3.sh with before/after shots, which is the first real feature test in this job.

Glossary

Xvfb
An X server that draws into memory instead of a screen, so GUI apps run on a CI machine.
xfwm4
Xfce's window manager. It gives windows focus and frames, as on the desktop.
xdotool
A command that finds windows and sends them clicks and keys, like a user.
import
ImageMagick's screenshot command. import -window <id> saves one window as a PNG.
dbus-run-session
Runs a command with its own private D-Bus, so each test gets its own Thunar and settings service.
Smoke test
The cheapest check that the build isn't broken: it starts and stays up.
shots branch
An orphan branch, sharing no history with the code, that only stores CI's images.
verify.tsv
The list of a run's shots: test, result, shot, file and what it proves.
Deb cache
The .deb files apt downloaded, saved by GitHub between runs so the next run can skip apt.
Runner image
The VM image GitHub runs jobs on. ImageVersion changes about weekly.
PPA
A Launchpad package archive. ppa:zorinos/stable has the Xfce 4.20 libraries and Zorin's themes.
BLANK, MISMATCH
Audit verdicts: the frame shows nothing useful, or it shows the wrong state.
Claude Code web session
Claude Code running in a cloud sandbox on claude.ai/code, working on a GitHub repo.
