Part 1

What this PR adds

The explainer skill and CLAUDE.md now require a stamped narration, CI's explainer job checks it, pages 1, 3 and 7 get theirs, and videos-all.sh renders every video locally.

runs in the cloud session or in CI (Chrome only) runs on your machine (needs Kokoro)

The big picture

Each PR's explainer page can become a narrated video, but only if it has a narration file: the spoken lines, and which part of the page each line shows. Until now the narration was optional, so only pages 9 and 11 had one. Work now happens in cloud sessions, which can write and check a narration but can't make the voice. This PR splits the job: the session that builds the PR writes and stamps the narration, CI checks it, and your machine only renders.

A narration is tied to its page by content, never by file dates. stamp saves a hash of the text each line was written from and of the whole page, so status can tell which lines went stale with Chrome alone, without any audio.

Step by step (numbers match the diagram)

① Every issue PR — in the cloud session and CI
  1. Write the page. explainers/<n>-<slug>.html with the explainer skill, unchanged.
  2. Write narration. explainers/<n>-<slug>.narration.json, written from the final page: one spoken line per diagram box, step and table row, with say respellings for numbers and versions. SKILL.md moves this from "Optional video" into the steps every PR follows, and CLAUDE.md's Explainers rule now names both files.
  3. Stamp. make-video.py stamp <n>, then status must say "narration matches the page". After any later page edit, including a review fix: status, rewrite the stale lines, stamp again. In the cloud container, CHROME points at the Playwright headless shell, and make-video.py now adds --no-sandbox when it runs as root or under CI.
  4. CI checks it. A new step in the explainer job, explainer-proof.sh narration, runs make-video.py status for the branch's issue and for every explainer page or narration the PR adds or changes, and for every narration when the PR changes make-video.py. A missing narration, a stale line, or a key the page no longer has turns the step red. Rendering and the comment still run, and the explainer section of the PR comment gets a Narration list with each result. PRs from forks skip the job, as before.
② Your machine — videos-all.sh, any time
  1. Fetch, gallery. git fetch origin --prune, then a worktree, by default ~/thunar-explainers, detached at origin/main, so make-video.py and the pronunciation table are current. Your own checkout is never touched.
  2. Collect pages. From main and every <digits>-<slug> branch, with git show. A branch provides the explainer files it changed since it left main, and that issue's page and narration both come from it. Two branches changing one issue are a conflict, reported and not rendered. SOURCES.tsv lists each page's branch and commit.
  3. Decide by hash. No narration: "needs narration". status fails: "needs re-narration". Page and narration hashes, and one of make-video.py with the pronunciation table, equal to the last render's <stem>.mp4.sha: "skipped". Otherwise it renders.
  4. Render, report. make-video.py render <n>, then the new hashes are saved. A table of page, branch, commit and result is printed and saved as REPORT.tsv, and the script exits 1 if any render failed.

Code review

A fresh general-purpose agent, given only the diff and issue #25, reviewed it at high level and ran videos-all.sh on its own scratch clone: 8 findings, 1 high, 4 medium and 3 low. 6 are fixed, 1 was already handled, and 1 is accepted.

  • Fixed, high: a --gallery pointing at your own checkout, or a folder in it, passed the worktree check, and the reset would have thrown away uncommitted work. The gallery must now be a detached linked worktree other than the checkout.
  • Fixed, medium: a branch that was squash-merged and never deleted still overrode main. A branch now provides only files that still differ from main's.
  • Fixed, medium: any two branches touching one page counted as a conflict. Now the issue's own <n>-<slug> branch wins, and only two of those conflict.
  • Fixed, medium: make-video.py now passes --no-sandbox under CI too, as explainer-proof.sh does. Already handled: the missing page was in the pushed commit, and the narration was held back on purpose for the failing run.
  • Fixed, low: --open-prs asks origin's repo, not upstream; stale doc lines updated. Accepted, low: a non-issue branch that changes only a narration reports a failure in the log, not in the comment.

CI's own review of the first push (Opus at xhigh) found 13: 1 high, 5 medium and 7 low. R1, R3, R8 and R9 were the same as local findings, already fixed. R13, the usage headers in the scripts, is accepted: the existing scripts have the same. Its review of the next push raised R14 to R23, all but two of them low or plausible. What comes later: your first local run

No open issue says "Depends on #25". What remains is yours: render the gallery once, listen, and correct any word Kokoro gets wrong.

After the merge (next)

  1. Run it. .claude/skills/explainer/videos-all.sh from your checkout. Expect "rendered" for every narrated page, then run it again and expect "skipped". Add --open-prs if old branches such as 9-explainer-review-fixes would otherwise override main's page.

The next run re-renders the pages whose narration changed, and every page after a table row changes; the voice of unchanged lines comes from the cache.

Glossary

Narration
The .narration.json beside a page: each spoken line, its caption, and which part of the page it shows.
Stamp
Hashes of the page text each line was written from, and of the whole page, saved in the narration.
Stale
A line whose page text changed after the stamp.
Kokoro
The text-to-speech model on your machine that voices the lines.
Phonemes
The sounds Kokoro will say for a line, printed by make-video.py phonemes.
Headless shell
A cut-down Chrome with no window, which Playwright installs in the cloud container.
Worktree
A second working folder of the same git repo, on its own commit, so your checkout stays as it is.
Gallery
~/thunar-explainers: the worktree whose explainers/ holds every page and video.
Merge-base
The commit where a branch left main; what changed since then is the branch's own.
Stub
A stand-in for a command, used to test the steps around it.
