PR #108: CI edits its PR comments only when a result changes

Branch 105-cheap-pr-comments → main, closes #105. A session watching a PR gets far fewer and far smaller comment edits, so its context stops filling up with "still running" copies of the same tables.

Part 1

What this PR adds

The summary comment skips edits that change no result, the big shots tables live only in the verify comment, and settled review findings take less room. Four CI scripts make it.

how the summary decides to edit what the other comments carry now

The big picture

CI keeps four comments on every PR: the summary, the code review, verify and the explainer. A Claude session watching the PR is sent the whole comment every time CI edits one. On PR #102 that was about 50 edits of 3 to 5 thousand tokens each, mostly "still running" rewrites of the summary, which repeated the key screenshot pair and an 84-row shots table every time. This PR cuts both the number of edits and their size.

The summary now carries a hidden results marker. If the marker it would write is the same as the one already in the comment, nothing changed that matters, so CI doesn't edit the comment at all.

Step by step (numbers match the diagram)

① The summary: edit only on a result
  1. A job finishes. Every job that writes a comment calls pr-summary.py, the summary job calls it last, and the pr-summary workflow calls it when a screenshot audit is posted. It builds the summary: heading, checks table and one line about the shots.
  2. Compare results. The new summary starts with <!-- pr-proof:results {...} -->: the head commit and a short hash of every check that isn't running (its text and link), the verify note and the run link. The script compares it with the marker in the summary already on the PR.
  3. Edit on a result. When the markers match, it prints "the summary is unchanged" and stops. Otherwise it writes the comment once. So a run posts "running" once per head, then edits only when a check passes or fails. Instead of the tables, the summary links to the verify comment, and says when its shots are from an older head.
② The other comments: smaller
  1. Verify comment. verify-shots.py comment now puts "The key result" and the "Shots" table near the top of the verify comment, which is written once per run. The key pair's own test section says "shown above". Its hidden pr-proof:data copy of both is gone; nothing else read it.
  2. Review state. review-state.py cuts closed findings from earlier reviews to 80 characters of summary and of reason (it was 120 and 120). Open, accepted, unconfirmed and new findings stay whole, so pr-digest and the review job lose nothing they use.
  3. Size in the log. pr-comment.sh now logs each edit as "updated <url> (<n> characters)", so the issue's test can count edits and their size from the job logs.

What the summary looks like now

Before

Heading, checks table, the key before/after pair and the full shots table, rewritten on every job, even when only "running" changed.

After

Heading, checks table and one line linking the verify comment, one tap away on a phone. Edited only when a result changes.

Markers other tools read are kept: pr-proof:NAME on each comment's first line, pr-proof:status in review, verify and explainer, review:state, and the #shot-N anchors.

Code review

Before the first push, a fresh general-purpose agent got only the diff and the issue. It found 3 low findings, all fixed in the second commit. It ran before that commit, so the fixes were checked by re-running the stub DRY_RUN pass, not by a second review.

  • Dead links could stay: the skip compared only results, not the links and run, so it now compares those too.
  • Old shots unmarked: the summary now says when the verify comment's shots are from an older head.
  • A silent dry run: DRY_RUN printed nothing on a skip; it now prints the message and the body.

Glossary

Watching session
A Claude session subscribed to a PR; it gets each comment edit with the whole body.
Summary comment
CI's first PR comment: overall state and a table of checks.
Verify comment
CI's third comment: test results and every screenshot.
Key result
The one before/after screenshot pair that best shows the PR's change.
Shots table
A table listing every screenshot by number and what it proves.
Marker
A hidden HTML comment in a PR comment holding data scripts read, e.g. pr-proof:results.
review:state
The hidden JSON in the review comment listing every finding and its status.
Closed finding
A review finding that was fixed, resolved or dismissed in an earlier review.
pr-digest
The agent that reads CI's comments and reports only what changed.
DRY_RUN=1
Makes the script print the comment instead of posting it.
Stub gh
A fake GitHub command that returns canned data, for testing without GitHub.
