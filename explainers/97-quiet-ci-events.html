PR #98: No messages on routine CI events while you're in the session

Branch 97-quiet-ci-events → main, closes #97. Once merged, an agent stops replying to every CI event and stops repeating its open question, so the thread stays readable while you're in it.

Part 1

What this PR adds

Three new rules in CLAUDE.md's "Working with the owner", two old lines pointed at them, and a new first step in the build-verify agent that hides build outputs from git.

the agent, under the new CLAUDE.md rules the build-verify agent's new step you

The big picture

An agent that opens a PR watches it, so every CI event wakes it up. In session 74 (PR #94) each wake-up, and each Stop hook warning about untracked build files, got a reply that repeated the open "What I need from you" question. The thread kept scrolling and you couldn't read the explanation you had asked for. This PR writes down when to stay quiet, so every session follows it.

"Quiet" means one short line, not an empty turn: a turn with no text makes the harness ask the agent for a reply, which would wake it again.

Step by step (numbers match the diagram)

① A CI event wakes the agent
  1. Routine event. A PR activity event arrives that changes nothing: a CI comment edited with no new result, a check still running, an event for an older head, or an echo of the agent's own post.
  2. One short line. The agent reads the event as delivered (CI's comments still only through the pr-digest agent) and ends the turn with one short line at most, without repeating "What I need from you".
  3. Real news: post. Only a result (pass or fail), a blocker, a merge, a new question or a comment from you gets a real message.
② A question waits for you
  1. Ask once. The "What I need from you" section appears once per question, and is repeated only when you ask for it.
  2. Pause the watch. In an interactive session (any session where you answer in its chat, batch group sessions included), the agent unsubscribes from the PR's activity and schedules one send_later check-in, so a CI result or your answer isn't missed. The check-in acts only on a result or your answer; if neither has come, it schedules the next check-in.
  3. You answer. The agent subscribes to the PR again and checks its state for anything that landed meanwhile. The watch-the-PR line in "Branches and PRs" now names this exception.
③ The build-verify agent builds
  1. Hide outputs. Before building in a cloud container, where the Stop hook runs, .claude/agents/build-verify.md step 0 appends each build output path to the clone's exclude file (git rev-parse --git-path info/exclude, which also works in a linked worktree), unless that exact line is already there: /dist/, /ar-lib, the policy file, the thunarx ABI-check files, and the debian/ build files, with one folder per package in debian/control. A cloud build outside build-verify runs step 0 first ("Building" in CLAUDE.md).
  2. Stop hook quiet. Git no longer lists those files as untracked, so the Stop hook stops re-prompting after every turn.

A closer look at two choices

Why .git/info/exclude, not .gitignore

A .gitignore change is a code change, so CI would run a full build and verify instead of "No code changed", and it changes ignore rules for everyone. The exclude file is per clone, which is where build-verify runs.

Why a check-in, not silence

The PR-watch rule wants something to catch a result while the agent waits. A send_later check-in does that without a wake-up for every event, and is rescheduled until a result or your answer comes.

The new CLAUDE.md lines (shortened)

## Working with the owner
- … end it with a short multiple-choice "What I need from you" section …,
  once per question (see below).
- Don't post a message for a routine event: a CI comment edited with no
  new result, … Post only for a result (pass or fail), a blocker, a merge,
  a new question or a comment from the owner.
- Ask a pending question once. Repeat it only when the owner asks.
- While a question waits for the owner in an interactive session,
  unsubscribe from the PR's activity and schedule one send_later check-in …;
  if neither has come, schedule the next check-in.
## Building
- In a cloud container, a build run outside build-verify first runs its step 0 …

Code review

A fresh general-purpose agent, given only the diff and issue #97, reviewed at level high. It found 8 issues: 7 were fixed and 1 was partly addressed.

  • Exclude list gaps (high): it missed debian/autoreconf.*, the thunarx ABI-check outputs, org.xfce.thunar.policy.in and ar-lib. All added.
  • Contradicting lines (2, medium): the old "What I need from you" and "watch without asking" lines said the opposite of the new rules. Both now point to them.
  • Wording (3, low): a vague "safety net", an undefined "interactive session" and an unanchored dist/. Reworded, defined, and anchored as /dist/.
  • Dead entry (low): debian/*.debhelper.log matched nothing, so it was removed.
  • Check-in delay (partly addressed): no send_later delay is named. The check-in now acts only on a result or your answer; the delay is left to the agent.

CI's review of the first push (run 43093403082, level high) found 9 more. One fix commit (review round 1) fixed R1 to R8; R9 was left as is. Every finding is in the code review comment on PR #98.

  • R1, R2 (medium, confirmed): the one check-in was never rescheduled, and resubscribing didn't look for events missed meanwhile. Now the check-in is rescheduled until a result or your answer comes, and the agent checks the PR's state when it subscribes again.
  • R3 to R5 (low): "CI comment edited" was too broad, since CI edits its comments to report results; your comments weren't on the post-worthy list; "Read it" clashed with the pr-digest rule. Now it says "with no new result", your comment is post-worthy, and CI comments are still read only through pr-digest.
  • R6 to R8 (low): a hard-coded .git/info/exclude breaks in a linked worktree, hand builds weren't covered, and step 0 would edit your own machine's clone. Step 0 now asks git for the path, runs only in a cloud container, and CLAUDE.md's "Building" runs it before a hand build there.
  • R9 (low), not changed: it said the exclusion step is unrelated to #97, but the issue itself asks build-verify to add the exclusions.

Glossary

Routine event
A PR event that changes nothing: a CI comment edited with no new result, a check still running, an older head, an echo.
"What I need from you"
The multiple-choice block that ends a turn blocked on you.
Interactive session
Any session where you answer in its chat, batch group sessions included.
PR activity subscription
What makes CI results, comments and reviews on a PR wake the agent.
send_later
A one-off message the session schedules to itself, waking it once at a later time.
Stop hook
A check that runs when a turn ends; it warns about untracked files.
.git/info/exclude
Like .gitignore, but local to one clone and never committed.
build-verify agent
The subagent that builds the debs and runs the verify tests.
No code changed
What CI's build and verify run instead of their steps when a PR changes only docs and agent files.
