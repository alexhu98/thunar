PR #101: Insert drops the selection on the other pane

Branch 95-insert-other-pane → main, refs #95. In split view, pressing Insert moves or copies the selected files into the other pane's folder, exactly as dragging them there would.

Part 1

What this PR adds

One new window action, Drop on Other Pane, bound to Insert and listed in the Edit menu. Its move-or-copy rule and its refusal check are shared with drag and drop, and it hands the files over the way a drop does.

new in this PR Thunar's existing code, reused you

The big picture

Split view (F3) shows two folders side by side. Until now, getting files from one side to the other took a drag with the mouse, or Cut, a click on the other side and Paste. Now one key does it, and it makes the same choice a drag would: move when it can, copy when it must.

Insert doesn't have its own rule. The code that decides "move or copy?" for a drag was pulled out into one function, and both the drop and the Insert key call it, so they can't drift apart.
Smaller than the issue: #95 also asked for Shift+Insert to copy and Ctrl+Insert to move. The review found those keys are already Thunar's second Paste and Copy shortcuts, so you asked to drop them. They keep pasting and copying, and this PR only refs #95.

Step by step (numbers match the diagram)

① Insert key
  1. You press Insert. Split view is on, files are selected in the active pane, and keyboard focus is in its file view. Pressed anywhere else, such as the side pane, Insert does nothing and the key goes on. If a text field has focus, such as the location bar, rename or search, the window gives the field the key first, so Insert stays a text key there.
  2. Window checks. The new action in thunar/thunar-window.c finds the other pane's current folder, which must be writable. Selected files already in that folder are skipped, and the rest go. It refuses them all when the folder is inside one of the files, or when it is one of them or both are in the Trash, the same check a drop makes (thunar_file_drop_refused). If nothing would transfer, the key goes on.
  3. Move or copy? thunar_file_drop_copy_or_move in thunar/thunar-file.c moves when every file is on the same filesystem as the target and in a writable folder, or comes from the Trash. Otherwise it copies. A drop on the Trash itself always moves.
  4. Transfer. The files go to thunar_dnd_perform, the function a real drop calls, so they take Thunar's usual move or copy job, with progress and undo, into the other pane's folder. Focus stays in the pane you started from.
② Same pieces, other ways in
  1. Edit menu item. Drop on Other Pane sits in the Edit menu below Delete, greyed out unless it would really transfer something: split view on, files selected, and a folder that takes them. It works from anywhere, also when the menu is opened from the keyboard. It has no underlined letter, because every letter of its name is already taken in that menu.
  2. Drag and drop. thunar_file_accepts_drop now calls the two shared functions, the move-or-copy rule and the refusal check, instead of its own copies, so its decisions are the same as before. The move also fixes a small memory leak on the copy path.

Code review

A fresh general-purpose agent, given only the diff and the issue, reviewed it three times. Round 1, on the three-key version, found 7 problems: 1 high, 1 medium, 5 low. Round 2, on Insert only, found 4 low: 1 fixed, 3 accepted. Round 3, after CI's first review was fixed, found 2 low, both now fixed.

  • High, round 1: Shift+Insert and Ctrl+Insert would have taken over Thunar's existing Paste and Copy keys. That led to the scope change: only Insert remains.
  • Medium, round 1: folders inside the Trash and read-only folders were accepted where a drop refuses. Fixed: the target must be writable, and only the Trash itself forces a move.
  • Low, round 1: files already in the target, as in search results, would be copied onto themselves. Fixed with a parent-folder check. Also noted: the leak fix, and test coverage.
  • Low, round 2: the underlined O clashed with Redo. Fixed: no underlined letter.
  • Accepted, round 2: Insert acts on the main view's selection even when the side pane has focus, like other window actions; the menu item stays active when the target would refuse; the copy, Trash and same-folder cases aren't tested. CI's review later raised the first two again, and both are now fixed.
  • Low, round 3: the focus rule also blocked the Edit menu item; fixed in ada247b. The menu item could stay active where the action refuses; left here, and CI's R11 fixed it.

Glossary

Split view
F3: two folder panes side by side in one window.
Active pane
The side with keyboard focus; its selection is what Insert sends.
Drop
Letting go of dragged files over a folder.
Drop rule
Thunar's choice between move and copy when you drop with no modifier key.
Same filesystem
On the same disk or partition, so a move is just a rename.
Trash root
The top of the Trash, as opposed to a folder inside it.
Mnemonic
The underlined letter that picks a menu item with Alt or from the open menu.
Window action
An entry in Thunar's action table: a name, a default key and a handler.
paste-2, copy-2
Thunar's second shortcuts for Paste (Shift+Insert) and Copy (Ctrl+Insert).
Reference leak
An object never released, so its memory is never freed.
verify/95.sh
The test script CI runs: it drives Thunar with xdotool and takes screenshots.
Keyboard focus
The one widget that gets key presses, such as the file view or the side pane.
Type-ahead search
Typing in the file list to jump to a name; GTK shows a small search popup.
thunar_dnd_perform
The function that carries out a drop: it starts the move, copy or link job.
R1, R2 …
The IDs CI's code review gives its findings, kept across rounds.
Symlink
A file that points to another file or folder, so one folder can have two paths.
Pair
A before and after screenshot around one action in a test.
