Search Enter focus: Enter in the search box jumps to the results

Branch 135-search-enter-focus → main, closes #135. After Ctrl+F and a search word, Enter puts the keyboard in the file list, so Down selects the first match, just like Enter, Down in the location bar.

Part 1

What this PR adds

Enter in the search box now moves the focus to the search results and leaves the search as it is. The change is seven lines in thunar/thunar-location-entry.c, tested by verify/135.sh.

new in this PR existing Thunar behaviour, unchanged you

The big picture

Before, after Ctrl+F and a search word, Enter did nothing and the keyboard stayed in the search box. Down did nothing either: you had to press Tab twice to reach the results. In the location bar, Enter on a folder already moves you into the file list. Now the search box does the same.

Search and the location bar are the same text box. The search runs on every keystroke, so in search mode Enter had nothing left to do. Its only new job is to move the keyboard to the results.

Step by step (numbers match the diagram)

① Enter in the search box
  1. You search. Ctrl+F opens the search box and each letter you type updates the results, as before.
  2. Enter. thunar_location_entry_activate is the box's Enter handler. It finds no file for the text, and now checks thunar_util_is_a_search_query: if the text is a search, it takes the new branch.
  3. Keep the bar. The branch disconnects the box's pending “edit done on focus-out” handler. Without that, with the path-buttons style of location bar, moving the focus away would swap the bar back to buttons in the middle of the search.
  4. Focus to list. It finds the window and calls gtk_widget_grab_focus on thunar_window_get_view, the same call the location bar already makes after selecting a file (#93).
② After Enter, and what stays the same
  1. Down: 1st match. With the file list focused and nothing selected, the list's own Down key selects the first match. The search and its results stay on screen.
  2. Path Enter. Enter on a folder or file path takes the old branch, before the new one, so it is unchanged.

The change (names shortened)

else if (is_a_search_query (text))
  {
    disconnect (path_entry, edit_done);
    window = get_toplevel (location_entry);
    if (THUNAR_IS_WINDOW (window))
      grab_focus (get_view (window));
  }
Not as the issue assumed: the issue says Ctrl+F should bring you back to the search box with the query intact. In Thunar, Ctrl+F while a search is open turns the search off, before and after this PR. Clicking the search box does return to it. This PR leaves Ctrl+F alone; it is an open question for you (Part 3).

Glossary

Focus
The widget that receives your key presses.
Location entry
The text box at the top of the window; it holds a path, or a search after Ctrl+F.
Path-buttons bar
The location bar style that shows the path as buttons and swaps in a text box only while you type.
Edit done
The signal that tells the buttons bar the typing is over, so it swaps back to buttons.
View
The file list: icons, details or compact list.
Xvfb
An invisible X display, used to run Thunar for tests without a screen.
verify script
verify/<issue>.sh: drives Thunar with xdotool, checks the result and takes screenshots.
