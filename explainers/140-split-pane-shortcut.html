What this PR adds

The action behind “Switch Focused Split View Pane” now tells GTK whether it used the key. The change is one new function in thunar/thunar-window.c, tested by verify/140.sh.

The big picture

Split view (F3) shows two folders side by side, and one of them is the active pane. Thunar has an action, “Switch Focused Split View Pane”, with no key of its own; you can give it one in Edit → Configure Keyboard Shortcuts. On the owner's machine F6 was bound to it, and pressing F6 did nothing visible, while Shift+F6 (GTK's own pane cycling) did switch.

A keyboard shortcut's callback returns TRUE to tell GTK “I used this key”. All the other callbacks in Thunar's window action table do; this one was the only one that returned no value. GTK then passed F6 on, and the split view's own F6 binding moved focus straight back.

Step by step (numbers match the diagram)

① F6 in split view — with this PR
  1. You press F6. F6 is bound to “Switch Focused Split View Pane”, and split view is open. The binding lives in Thunar's accels.scm, which the shortcut editor writes.
  2. New callback. The action entry now points at the new thunar_window_action_switch_focused_split_view_pane. It notes which pane is selected, then calls thunar_window_paned_notebooks_switch.
  3. Panes switch. thunar_window_paned_notebooks_switch is unchanged: it makes the other pane the selected one, so the window title, location bar and keyboard follow it. Its other callers inside Thunar keep using it as before.
  4. Returns TRUE. The new callback returns whether the selected pane changed. After a switch that is TRUE, so GTK treats F6 as handled and gives it to no other widget.
② Before this PR (main)
  1. Old callback. The action called thunar_window_paned_notebooks_switch directly. It switched panes but returned no value, so GTK didn't see F6 as handled and passed it on to the focused widget.
  2. F6 undoes it. The split view's GtkPaned has GTK's own F6 binding, which moves focus between the two halves, so focus went back to the pane you started in. That last part is read from the code; the test below shows the net effect.
③ Split view off — with this PR
  1. Returns FALSE. With one pane, thunar_window_paned_notebooks_switch changes nothing, so the selected pane is the same and the callback returns FALSE. F6 then keeps whatever GTK does with it there, such as moving focus to the side pane. The callback returns FALSE whenever no switch happened, not only with split view off. This was the more natural choice the issue's Risks section suggested.

A closer look at the change

static gboolean
thunar_window_action_switch_focused_split_view_pane (ThunarWindow *window)
{
  GtkWidget *notebook_selected;

  _thunar_return_val_if_fail (THUNAR_IS_WINDOW (window), FALSE);

  notebook_selected = window->notebook_selected;
  thunar_window_paned_notebooks_switch (window);
  return window->notebook_selected != notebook_selected;
}

Glossary

Split view
Two folder panes side by side in one window, toggled with F3.
Active pane
The pane the title, location bar and keyboard follow.
Action
A named Thunar command that a menu item or a shortcut can run.
Callback
The function GTK calls when the action's shortcut is pressed.
TRUE / FALSE
A shortcut callback's answer to GTK: TRUE means “I used the key”, FALSE lets others have it.
GtkPaned
GTK's two-part container with a draggable divider; split view is one.
accels.scm
Thunar's file of custom keyboard shortcuts, written by the shortcut editor.
R1, R2, R3
The IDs CI's code review gives its findings on this PR.
Xvfb, xdotool
A screenless X server, and a tool that sends it clicks and keys.
