Part 1

What this PR adds

Ctrl+F used to list names that contain every word you type. Now a word that starts with ! works the other way: the name must not contain it. One function changed, so every search in Thunar follows the new rule.

changed by this PR existing Thunar code, unchanged you

The big picture

You keep files with and without a dash in their names and wanted to list only those without one. Until now the only way was Select by Pattern *-* and then Invert Selection. A ! word does it in the search itself, and it combines with ordinary words.

The prefix is !, not -, so that a search for - still finds the names that contain a dash.

Step by step (numbers match the diagram)

  1. You type. Ctrl+F opens the search field, and each word of the query is one condition.
  2. Split in words. thunar_g_utf8_normalize_for_search folds case and strips accents, and thunar_util_split_search_query splits on spaces. Neither touches ! or \, so both are unchanged.
  3. Check each word. thunar_util_search_terms_match in thunar-util.c still needs every word to pass. A word that starts with ! and has more after it now passes when the name does not contain the rest; a lone ! and a \! word are searched as text.
  4. Every view agrees. The search through subfolders (thunar-io-jobs.c), the list and icon views (thunar-list-model.c) and the tree view (thunar-tree-view-model.c) all call that one function, so none of them changed.

What a query lists

In a folder holding a-b.txt, ab.txt, draft-report.txt, report.txt and bang!name.txt:

The change

  for (gint i = 0; terms[i] != NULL; i++)
    {
      term = terms[i];
      exclude = (term[0] == '!' && term[1] != '\0');
      if (exclude)
        term++;
      else if (term[0] == '\\' && term[1] == '!')
        term++;
      if ((g_strrstr (str, term) != NULL) == exclude)
        return FALSE;
    }
To undo it, revert this PR: nothing is saved anywhere, and searches go back to plain words.

Code review

A fresh general-purpose agent in this session, given only the diff and issue #22, found no high or medium bugs and 4 low findings. It checked the edge cases (! alone, \!, !!x, empty words) and that no caller treats words as plain text anywhere else.

  • Tried, then dropped (low): the test covered only the details view. An icon-view search was added, but the screenshot audit showed Thunar had switched it to the details view, so it proved nothing and was removed.
  • Kept (low): a full-width ！ typed with a Chinese or Japanese input method becomes ! when the query is normalized, so it excludes too.
  • Kept (low): \! only escapes a plain word; to exclude names containing !x, type !!x. The lone ! check is asserted without a screenshot.

Glossary

Search word
One space-separated part of the query; each is a separate condition.
!word
A search word that a name must not contain.
\!word
A backslash before ! makes the word plain text again.
Normalize
Fold case and strip accents so that names and queries compare alike.
Recursive search
A search that also looks inside every subfolder, and their subfolders.
Xvfb
A virtual X display with no screen, used to run Thunar in tests.
xdotool
A tool that moves the pointer, clicks and types into X windows from a script.
