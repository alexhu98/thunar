PR #131: The details view updates again when files in its folder change

Branch 129-tree-view-root-files-changed → main, closes #129. Once merged, rows in the folder the details view shows re-sort when a file changes, a renamed temp file appears, and Thunar stops flooding its log with “detached node” lines.

Part 1

What this PR adds

A one-line upstream fix lets file changes in the shown folder reach the details view again, and a review fix keeps search results from being re-sorted in the wrong folder. Both are in thunar/thunar-tree-view-model.c; verify/129.sh tests them.

what happens anyway changed by this PR the old behaviour this PR removes

The big picture

Upstream Thunar 4.20.10 added a safety check against renamed folders. It also stopped every file change in the folder the details view shows, and logged a line each time. In a busy folder those lines filled an unread pipe, and Thunar froze. Upstream already fixed the check on its 4.20 branch, and this PR takes that fix early.

The folder a view shows is the model's root node. It has no row of its own and no parent, so the old check took it for a detached folder and dropped all of its changes.

Step by step (numbers match the diagram)

① A file changes in the shown folder
  1. A file changes. An app writes to a file, so its size and date change, or saves under a hidden temp name like .tmp-x and renames it to x.txt.
  2. files-changed. The folder's monitor sends files-changed to its views. A rename is a remove and an add of the same file, and the add cancels the remove, so only a change arrives.
  3. Root guard. thunar_tree_view_model_dir_files_changed now drops only a missing node. This is upstream's commit c2ed7a2f6, cherry-picked unchanged.
  4. The row updates. The handler re-sorts the file's row, so a sort by size follows the new size. A file no longer hidden leaves the folder's hidden list and is added, so x.txt appears.
② Before this PR (4.20.10)
  1. Dropped. The old check also dropped a node with no row and no parent, which is always true for the root. Every change in the shown folder was lost, with Expandable Folders off or on.
  2. Log flood. Each drop logged “Caught and ignored files_changed on a detached node”. On Nov 16 at 8:48 PM PST, 633 of them filled a 64 KiB pipe nobody read, and Thunar hung.
③ Review fix: search results
  1. Search mode. While searching, the root's handler is called for each changed result. A result can sit inside a folder that is itself an expanded result, so its row is not one of the root's rows.
  2. Only its own rows. The handler now skips a file whose row has a different parent. Without this, it would re-sort the file among another folder's rows and send a reorder sized for the root.

The change

  if (node_parent == NULL || (node_parent->ptr == NULL && node_parent->parent == NULL))
  if (node_parent == NULL)

      node = thunar_tree_view_model_locate_file (model, file);

Part 2

How it was built and verified

The building session built the PR before the review fix and ran all 25 tests, including the new one. The review fix, the old build and the original freeze were not run here; CI builds and tests every push.

Built on 3 known-good references

Upstream c2ed7a2f6

“Relax tree-view sanity check”, upstream issue #1884, on the xfce-4.20 branch. Cherry-picked with -x from this fork's mirror of that branch.

The owner's reproduction

Per the issue, on 4.20.10-1~bpo24.04+local39 under Xvfb: the details view lacked the renamed file, the icon view had it.

The icon view's model

ThunarListModel already unhides a renamed file on files-changed. The tree model does the same once the guard lets the root through.

The new test, verify/129.sh

  1. Setup. Details view, sorted by Size ascending. It runs twice, with Expandable Folders off and then on, each in its own folder holding a.txt (2000 bytes) and grow.txt (1 byte).
  2. Size. grow.txt is the first row. The test appends 5000 bytes and requires the first row to become a.txt. It reads a row by pressing Home, copying it and pasting it into a second window's folder.
  3. Rename. It creates the hidden .tmp-x, waits 2 s and renames it to x.txt. Ctrl+A must then copy a.txt, grow.txt and x.txt.
  4. Log. Thunar's own output goes to a log file, which must have no “detached node” line. The test takes 8 shots: before and after pairs for size and rename, with the option off and on.

Glossary

Details view
The list view with columns such as Name, Size and Date; Ctrl+2 switches to it.
Expandable Folders
A details view option that shows a triangle to open a subfolder in place.
ThunarTreeViewModel
The code that holds the details view's rows; it is used with Expandable Folders off or on.
ThunarListModel
The rows of the icon and compact views, which this bug never affected.
Root node
The model's entry for the folder the view shows; its files are the top-level rows.
files-changed
The signal a folder sends its views when files in it change on disk.
Hidden list
Files whose names start with a dot; the model keeps them aside until Show Hidden is on.
g_message
A GLib call that writes a line to Thunar's standard output or error.
Pipe
A buffer between two programs; when it is full and nobody reads, the writer waits forever.
Cherry-pick -x
Copies one commit onto this branch and notes the original commit in its message.
xfce-4.20
Upstream's 4.20 maintenance branch; this fork keeps a read-only mirror of it.
Search mode
Typing a search in Thunar lists matching files from subfolders in one view.
Xvfb
A virtual screen that tests draw Thunar on, with no monitor.
verify script
A test that drives Thunar on a virtual screen in CI and takes screenshots.
Upstream
The original Xfce Thunar project this fork follows.
