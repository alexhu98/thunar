Part 1

What this PR adds

Two new options, -t/--tabs and -T/--tabs-right, in thunar/thunar-application.c, and one new window function in thunar/thunar-window.c that fills both panes with tabs. thunar/main.c now passes on Thunar's exit status. verify/4.sh tests them.

new in this PR Thunar or GLib, unchanged you

The big picture

Until now, thunar ~/a ~/b opened each folder in its own window, or as tabs in an existing window if "Open new windows as tabs" is on. There was no way to open a ready-made window with chosen tabs in the left pane and others in the right pane of split view. Issue #4 asks for that: -t (the same letter as in Nemo, another file manager) collects the folders as tabs in one new window, and -T is a divider: folders after it go to the right pane.

The thunar you type is usually not the Thunar that opens the window. Thunar is a GApplication: if one is already running, or runs as --daemon, your command only passes its options to that one over D-Bus and exits. Those options arrive as a plain list that has lost where each folder stood relative to -T, so the split must happen first, in your own process.

Step by step (numbers match the diagram)

① Your thunar command
  1. You run thunar. For example thunar -t ~/a ~/b -T ~/c ~/d, or the long forms --tabs and --tabs-right. Both options take no value.
  2. Split at -T. A new thunar_application_local_command_line runs in your process before GLib parses the options. It walks the arguments and rewrites every folder after -T as a hidden option, --tabs-right-uri=~/c, which may repeat. It also finds -T inside combined short flags such as -tT or -wT, and doesn't take the separate value of --sm-client-id for a folder. -T with no folder after it prints --tabs-right needs at least one location and exits with status 1, unless --help, -h, -?, -V or --version is also there: then that option does what it asks.
  3. Hand over. Unchanged GLib behaviour: GApplication parses the options and, when Thunar is already running (or as --daemon), sends them over D-Bus to that instance. With no Thunar running, your process becomes it.
② The running Thunar
  1. Read options. thunar_application_command_line reads tabs, tabs-right and the tabs-right-uri list next to the usual folder list. Without -t or -T, nothing changes.
  2. Mount, check. Each name becomes a location, relative to where you ran the command, through thunar_application_file_for_filename, which plain thunar folders now use too. One at a time, thunar_browser_poke_file mounts it if needed, the way plain thunar does, so an sftp:// location that isn't connected yet works. Only then does the window open. A missing one shows Thunar's usual "Failed to open" dialog and a line on stderr; a file that isn't a folder gets the same dialog with "Not a directory". The other folders still open, and the command exits with status 1. When every location fails, nothing opens; but if only the left ones all fail and right ones open, the left pane gets the current directory. With -T and nothing before it, the left pane gets the current directory too.
  3. New window. It calls thunar_application_open_window (…, TRUE), the same forced new window as -w, so it never adds tabs to an existing window, even with "Open new windows as tabs" on. It also skips restoring the last session's tabs.
  4. Fill both panes. A new thunar_window_open_pane_tabs in thunar-window.c opens the left folders as tabs, turns split view on only when there are right folders (and off for -t alone, even with "always enable split view" on), then opens the right folders as tabs in the right pane. Thunar's split view toggle was split into thunar_window_split_view_add and thunar_window_split_view_update_toggle, so the right pane's first tab opens straight on its folder instead of first loading the left one. Its Back history still comes from the left pane, as with F3 and Ctrl+T.
  5. First tab, left. Thunar normally selects the last tab opened, so it selects tab 1 in each pane explicitly and switches back to the left pane, which gets the keyboard focus.

Side effect: thunar/main.c used to exit 0 whatever happened. It now returns g_application_run's status, so thunar -T exits 1, and so do Thunar's existing usage errors, thunar /missing and a failed -B bulk rename, which all exited 0 before.

Code review

A fresh general-purpose agent, given only the diff and issue #4, reviewed the PR twice in this session. Before the first push it found 6 things: 5 were fixed and 1 was kept on purpose. After CI's review round it found 4: 2 were fixed and 2 kept.

  • Test script: a loop in verify/4.sh never ran (a -z test inside arithmetic), a check could never fail and was dropped, and -t alone had no window-count check. All three are fixed.
  • Messages: thunar -T --help printed the error instead of help, and the stderr line didn't name the folder. Both are fixed.
  • Kept: -t alone turns split view off even with "always enable split view" on, because the issue says -t without -T gives one window with the left pane only.
  • Second review, fixed: right-pane tabs were dropped when every left location failed, and a failed -t location exited 0.
  • Second review, kept: main() returning the exit status, which is intended and noted in Part 1, and -t alone turning split view off, as above.

CI's review at level high (run 43080404038, on 4043a11) found 10 findings, R1–R10, listed in the code review comment on PR #92. All 10 were fixed in one round:

  • The split at -T (R1, R4, R5, R9): -tT and -wT count as -T, --sm-client-id's value is no longer a right-pane folder, and -V, --version and -? with -T do what they ask.
  • Remote locations (R2): locations are mounted before the window opens, so sftp:// works as with plain thunar.
  • Exit status (R3): main.c returns g_application_run's status, so thunar -T exits 1.
  • Opening the panes (R6, R7): the right pane opens straight on its folder, and when every location fails nothing opens.
  • Tidying (R8, R10): one shared file lookup function, and section comments removed from verify/4.sh.

CI hasn't reviewed these fixes yet; it does on the next push.

What comes later: #41, a --split option

No open issue says "Depends on #4", but #41 was split out of it: a --split percentage for a new window. Whichever of #4 and #41 lands second makes -T windows honour it.

built by this PR not built yet

#41 --split command-line option (next)

  1. The option. thunar --split 60 ~/a opens one new window, split view on, the left pane taking 60% of the width, without changing any saved setting.
  2. With -T. thunar -t ~/a ~/b ~/c -T ~/d --split 60: the split that this PR's -T turns on opens at 60/40.
  3. With -t alone. thunar -t ~/a ~/b --split 30: the left pane holds the tabs and the right pane opens on ~/a, split 30/70. That changes this PR's "split view off for -t alone" only when --split is given.

Glossary

Pane, split view
Split view (F3) shows two folder views side by side; each side is a pane with its own tabs.
argv
The list of words on the command line, as the program receives them.
GApplication
GLib's application class: it keeps one running instance and forwards later launches to it.
Primary instance
The Thunar that is already running and actually opens the windows.
D-Bus
The desktop's message bus, which carries the options from your command to the running Thunar.
--daemon
Thunar running in the background with no window, waiting for commands.
GOption
GLib's option parser; it puts all plain folder names in one list.
Hidden option
An option --help doesn't list, used here only to carry the right-pane folders.
Open new windows as tabs
The misc-open-new-window-as-tab setting; -t and -T ignore it and always open a window.
Mount
Connect a location, such as a server folder, so its files can be listed.
sftp://
A folder on another computer, reached over SSH.
Exit status
The number a command returns when it ends: 0 for success, anything else for failure.
Xvfb
A virtual screen with no monitor, where the tests run Thunar.
