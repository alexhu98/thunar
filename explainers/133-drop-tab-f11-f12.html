This PR for #133: F11 and F12 drop the selection on the previous and next tab

Branch 133-drop-tab-f11-f12 → main, closes #133. F11 now does what Alt+Page Up does, and F12 what Alt+Page Down does: send the selected files to the previous or next tab's folder, as a drop there would. The Alt keys keep working.

Part 1

What this PR adds

Two extra window actions with no menu label, bound to F11 and F12. They call the same handlers as #128's Drop on Previous Tab and Drop on Next Tab, so nothing about the drop itself changes.

new in this PR already there from #128, unchanged you

The big picture

#128 added Drop on Previous Tab and Drop on Next Tab on Alt+Page Up and Alt+Page Down. Those are two-key chords; F11 and F12 are single keys that Thunar didn't use at all, so they make the same drops quicker to reach.

A GTK shortcut path holds only one key. So, as Thunar already does for F5 (a second key for Reload), each action gets a second entry in the action table, with its own path, its own key and the same handler.

Step by step (numbers match the diagram)

① F11 / F12
  1. You press a key. F12 drops the selected files on the next tab, F11 on the previous one. In split view the order runs through the left pane's tabs and on into the right pane's, so both keys cross the split, exactly as the Alt keys do.
  2. Second entry. thunar/thunar-window.c gains drop-on-previous-tab-alt-1 with F11 and drop-on-next-tab-alt-1 with F12, and thunar/thunar-window.h their two ids. They have no label, so they add nothing to the Edit menu. The window connects every entry of the table to its shortcuts, so no other wiring was needed.
  3. Same handler. Each new entry points at #128's existing thunar_window_action_drop_on_previous_tab or _next_tab. No handler code changed.
  4. Drop, as before. The handler finds the neighbouring tab and calls thunar_window_drop_on_view, which moves or copies as a drop would. Its keyboard check still applies: with the focus in a text field, such as the location bar, F11 and F12 move nothing.
② The old keys
  1. Alt+Page keys. Alt+Page Up and Alt+Page Down keep their own entries, keys and Edit menu items. Each of the four keys can be changed on its own in accels.scm or the shortcuts editor.

The key change

{ …DROP_ON_PREVIOUS_TAB, ".../drop-on-previous-tab", "<Alt>Page_Up", …, drop_on_previous_tab },
{ …DROP_ON_PREVIOUS_TAB_ALT_1, ".../drop-on-previous-tab-alt-1", "F11", …, NULL label, drop_on_previous_tab },
{ …DROP_ON_NEXT_TAB, ".../drop-on-next-tab", "<Alt>Page_Down", …, drop_on_next_tab },
{ …DROP_ON_NEXT_TAB_ALT_1, ".../drop-on-next-tab-alt-1", "F12", …, NULL label, drop_on_next_tab },

Each new line copies its neighbour, with a new path, a new key, no label and the same handler. That is the whole code change.

Code review

Before the first push, a fresh general-purpose agent ran /code-review at level high on the branch against origin/main: 4 findings, 2 fixed, 2 skipped. Both fixes are in verify/133.sh; the code itself drew none.

  • Fixed: the Alt+Page Down and Alt+Page Up check was one pair whose before and after shots looked the same. It is now two pairs, alt-next and alt-previous, and each checks that the tab you started on stays active.
  • Fixed: the location-bar step pressed only F12. It now presses F11 too.
  • Skipped: the PR had no explainer yet. This page is it.
  • Skipped, for a separate issue: an older bug outside this diff. The handler for shortcuts typed in a tab gets the count of action ids rather than the table's real length, so it never checks the last entry, F10. It doesn't touch F11 or F12.

Glossary

Tab
One folder view among several in a pane, picked by its label at the top.
Split view
F3: two panes side by side in one window, each with its own tabs.
Drop on Previous / Next Tab
#128's actions: send the selection to the neighbouring tab's folder, as a drop would.
Window action
An entry in Thunar's action table: a path, a default key, a label and a handler.
Shortcut path
The name GTK stores a key under; each holds one key.
-alt-1 entry
A menu-less copy of an action with another key, such as F5 for Reload.
accels.scm
The file where Thunar keeps your changed keyboard shortcuts.
Keyboard focus
The one widget that gets key presses, such as the file view or the location bar.
Text field
A box you type into: the location bar, a rename entry or the search box.
verify/133.sh
The test script CI runs: it drives Thunar with xdotool and takes screenshots.
Pair
A before and after screenshot around one action in a test.
xfwm4
Xfce's window manager, which the tests run under.
