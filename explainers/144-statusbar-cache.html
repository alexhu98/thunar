PR #152: the status bar keeps folder totals and free space instead of re-reading every file

PR #152, branch 144-statusbar-cache → main, closes #144. Moving the cursor no longer reads every file in the folder from disk; the status bar text stays the same.

Part 1

What this PR adds

The status bar's Total, Free space and Selection parts now come from file data Thunar already holds, kept per view in thunar-standard-view.c, and the background job that re-read the folder is gone.

runs when the folder changes runs on each status bar update, no disk reads removed by this PR

The big picture

Since #74, every cursor move started a background job that asked the disk about every file in the folder, and asked for free space, just to redraw numbers that hadn't changed. In a folder of thousands of files, or on a network share where each question is a round trip, that is a lot of work per key press.

Thunar already holds every file's size, type and hidden flag in memory once a folder is loaded. Counting from that is a loop with no disk access, so it can run on the main thread, and it only needs redoing when the folder's files change.

Step by step (numbers match the diagram)

① Folder opens or its files change
  1. Watch the folder. When the view's folder is set, the view keeps a reference to it and listens for its files-added, files-removed and files-changed signals. A file that grows, like a download, sends files-changed.
  2. Drop the Total. Any of those signals clears the cached Total text and the cached search size, then asks for a status bar update. A signal that lists no files is ignored. The count itself waits until the text is needed.
  3. Free space. Asked once when the folder opens, without blocking the window, using the async lookup #74 added for search. While files change it is asked again, at most every 2 seconds.
② Cursor moves or results change
  1. Selection text. One file shows its name and size as before. Several files are now counted from the selected files in memory, including the last-modified date, instead of being read from disk again.
  2. Total or search. With no cached Total, or after the hidden-files, size-format or status-bar settings change, the folder's files are counted once in memory. In a search, the results' size is added up again only when the result count changes or a result row changes.
  3. Status bar. The selection goes on the left, and Total (or the search count) with Free space on the right, the same layout and words as before.

A closer look at the pieces

One counting helper

The helper in thunar-util.c now counts Thunar's own file objects instead of asking the disk. Hidden still means hidden or backup, the same two flags as before.

One cache per view

The view keeps the Total text, the settings it was made with, the search size and the free space. No new caching layer.

Dead code removed

The status bar job in thunar-io-jobs.c, 149 lines, and its callbacks in the view are gone, so there is one path, not two.

Glossary

Status bar
The line at the bottom of the window: selection on the left, Total and Free space on the right.
Total
The viewed folder's counts and size, e.g. "Total: 2 folders, 30 files: 4.1 MiB".
stat
The system call that asks the disk for a file's size, type and dates.
strace
A tool that logs every system call a program makes; the test counts stat calls with it.
Cache
A result kept to reuse, here the Total text, until the folder's files change.
files-changed
The signal a Thunar folder sends when one of its files changes on disk.
Async
Started now, answered later, without freezing the window meanwhile.
Network share
An smb or sftp folder, where each file question is a round trip over the network.
Xvfb
A virtual screen with no monitor, where the tests run Thunar.
R1 to R6
The numbers of CI's review findings, as in its code review PR comment.
