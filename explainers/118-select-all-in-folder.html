PR #119: Ctrl+A selects everything inside the current expanded folder

Branch 118-select-all-in-folder → main, closes #118. In the detailed list with Expandable Folders on, Ctrl+A now selects just the contents of the folder you're in. From a top-level row it still selects every row.

Part 1

What this PR adds

Ctrl+A, and Edit › Select All Files, now pick the folder from the cursor row and select that folder's rows in one go. Only thunar-details-view.c changes.

new or changed in this PR unchanged Thunar code

The big picture

With Expandable Folders on, the detailed list shows a folder's contents as indented rows under it, like a tree. Ctrl+A used to select every row in the view, opened folders included, so selecting just one folder's files meant Shift+click or holding Shift+Down. Ctrl+A now selects the folder you're in.

The folder comes from the cursor, the row with the keyboard focus outline, not from the selection. The selection is replaced, and the cursor itself never moves.
This differs from issue #118, which asked for a new action, Select All in Folder, on Ctrl+Shift+A. In the building session the owner chose to give that behaviour to Ctrl+A instead. So no action, menu item or shortcut is added, and GTK's own Ctrl+Shift+A, which unselects everything, keeps working.

Step by step (numbers match the diagram)

① Ctrl+A — select one folder's rows
  1. Press Ctrl+A. Ctrl+A and Edit › Select All Files call the view's Select All, as they always did. In the details view that is thunar_details_view_select_all in thunar-details-view.c, the one code file this PR changes.
  2. Pick the folder. The details view reads the cursor row, only while Expandable Folders is on. If that row is an expanded folder, it is the folder. Otherwise its parent folder is, so a file inside a, or a collapsed folder inside it, picks a.
  3. Find the range. The range starts at the folder's first child. It ends at the last visible row inside the folder, found by stepping into the last child as long as it is expanded. In the list's order, everything between those two rows is the folder's contents, and nothing else.
  4. Select at once. It clears the selection and selects the whole range with one select_range call, so a folder with thousands of rows is one call, not thousands. It then unselects any Loading… rows inside expanded subfolders, and tells the rest of Thunar about the new selection once. The folder row itself is outside the range, so it isn't selected.
② Other cases
  1. Other views. The icon and compact views have their own Select All, which this PR doesn't touch, so Ctrl+A there still selects everything.
  2. Whole view. With the cursor on a top-level row that isn't an expanded folder, with no cursor, or with Expandable Folders off, Ctrl+A selects every row as before. It now also unselects any Loading… rows, and tells Thunar about the change once.
  3. No change. A folder that was just expanded shows a Loading… row until its files arrive. If that row is the folder's first child, Ctrl+A leaves the selection as it was, instead of clearing it.

Code review

Before the first push, a fresh agent ran /code-review at level high on the whole branch, which then held the first, Ctrl+Shift+A design. It found 7 problems. 4 are fixed: 1 by the reviewer, 2 by the building session, and 1 by this page and its narration. The owner's switch to Ctrl+A settled 2 more, and partly fixed the last.

  • Fixed, loading folders: an expanded folder whose only child was still the Loading… row made the new selection clear everything. It now leaves the selection alone.
  • Fixed, tidier code: the Loading… row check no longer looks up plain rows that have no children, and a condition that changed the cursor path halfway through is now plain steps.
  • Fixed, S4: the branch had no explainer page or narration yet, so CI's explainer job would have failed. This page and its narration fix it.
  • Settled, S1: Ctrl+Shift+A would have replaced GTK's built-in unselect-all key in the list and icon views. With Ctrl+A chosen instead, that key keeps working.
  • Partly fixed, S2: Ctrl+A and Invert Selection could select Loading… rows, before this PR too. Ctrl+A no longer does; Invert Selection still can, and the owner was offered a separate issue for it.
  • Settled, S6: the new Edit menu item would have shown in every view. No menu item is added now.

CI reviews every code push at level high and reports in the code review comment on this PR. It hadn't run when this page was written.

Glossary

Expandable Folders
A setting of the detailed list view: folders get a triangle that shows their contents as indented rows.
Detailed list view
Thunar's view with one row per file and columns for size, type and date.
Cursor row
The row with the keyboard focus outline. Arrow keys move it; it can differ from the selection.
Loading… row
A stand-in row shown under a just-expanded folder until its files are read. It is not a file.
select_range
GTK's call that selects every row between two rows in one step.
Edit › Select All Files
The Edit menu item for Ctrl+A. It runs the same Select All.
Ctrl+Space
Toggles whether the cursor row is selected, without moving the cursor.
Verify script
verify/<issue>.sh: drives Thunar with simulated keys and clicks on a virtual screen, checks the result and takes screenshots.
Xvfb
A virtual screen with no monitor, so Thunar can run in CI.
Smoke test
CI's basic check that Thunar is still running 10 seconds after it starts.
/visual-verify
A check in which a separate agent looks at every screenshot and says whether it shows what it claims.
S1, S2, S4, S6
Review findings, numbered in its report, that the reviewer didn't fix itself.
