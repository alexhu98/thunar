PR #35: faster video runs, videos in your checkout, a clean gallery, fair re-checks in CI review

Part 1

What this PR adds

Each page is now checked against its last render before anything else runs, finished videos land in your checkout, the gallery's own files are ignored by git, and CI's review judges open findings by the code at HEAD.

a step the script runs what you see in your checkout and in git

The big picture

Most of this PR is about videos-all.sh, which renders every explainer's narrated video into a gallery folder, ~/thunar-explainers, a separate git worktree. Three things got in the way: a run with nothing to render still took about 12 s, because every page started Chrome; the videos never reached the checkout you look in; and the gallery's logs and hash files showed up in VS Code as 14 uncommitted changes.

Separately, on PR #33 CI's review kept two fixed findings open through two reviews, because it judged them by the latest commits only, and the fix was in an earlier one.

The .mp4.sha written after a render already hashes everything status reads: the page, the narration, make-video.py and the pronunciation table. So when it matches, status has already passed for exactly these inputs, and running it again tells nothing new.

Step by step (numbers match the diagram)

① Decide, for each page
  1. Compare hashes. The page, narration and tool hashes are computed first. If <stem>.mp4 exists and <stem>.mp4.sha holds the same hashes, the page is "skipped" right away: no Chrome, and its render log is no longer overwritten by status output.
  2. Run status. Only for a changed page. With CHROME unset, status uses the newest Playwright headless shell under ${PLAYWRIGHT_BROWSERS_PATH:-~/.cache/ms-playwright}, and google-chrome when there is none. A failure still means "needs re-narration".
  3. Render. Unchanged: make-video.py render with your CHROME, by default google-chrome, so frames look the same as before. The new hashes go into .mp4.sha.
  4. Copy to checkout. A skipped or rendered video is copied with cp -p into the explainers/ of the checkout the script lives in, only when cmp says it differs. A failed, partial or conflicting page is never copied. --no-copy and --dry-run copy nothing; REPORT.tsv gains a copied column, and the run ends with "videos copied to:" and the folder.
② The gallery stays clean
  1. Ignore output. explainers/.gitignore now ignores *.mp4.sha, *.log, REPORT.tsv and SOURCES.tsv next to *.mp4. The two TSVs are named, so a future tracked TSV isn't hidden. The gallery's git clean runs without -x, so ignored files survive its reset, as the videos already did.
③ CI review, open findings
  1. List the fixes. When plan writes open.json, each open finding gets commits_since: every commit since it was found, in any file, or null when its commit is gone after a force-push. That points the reviewer at the fix.
  2. Check at HEAD. Step 4 of the review prompt now gives each open finding to one fresh agent, as step 2 does for new ones; in auto-fix mode, step 3 fixes only what that agent finds still there. It reads the finding's file and the code its claim depends on at HEAD, and "not changed in this diff" is no longer a reason to keep it open. Its note names the code at HEAD that resolves the finding or still shows it.

Nothing re-renders, and how to undo

SKILL.md's pronunciation table and make-video.py are unchanged, so every existing .mp4.sha stays valid and your current videos are skipped, not re-rendered. To undo, revert the PR. To force a fresh status check of one page, delete its .mp4.sha; that also re-renders it.

Code review

Two fresh general-purpose agents, each given only the diff and its issues, reviewed it at medium level: the video script had 3 low findings, 2 fixed; the review change had 1 medium and 3 low, all fixed.

  • Fixed, a failed copy: a cp that fails, say on a full disk, stopped the whole run before the report. Now that row says "failed" and the run exits non-zero.
  • Fixed, an empty CHROME: CHROME= set but empty broke every render. Render now gets google-chrome then.
  • Fixed, a fix in another file: commits_since first listed only commits to the finding's own file, so a fix in a helper would still look absent. It now lists every commit, and the agent reads the code the claim depends on.
  • Fixed, small ones: null instead of an empty list when the finding's commit is gone; one agent per open finding, not one in step 3 and another in step 4; a jq error now fails the step.
  • Left as is: a tab inside a status error would add a column to REPORT.tsv. That predates this PR.

What comes later: your first real run

No open issue builds on this one. What's left is a real run on your machine, after the merge.

built by this PR you

Your run (next)

  1. Back up the gallery's logs. The first run after the merge keeps your videos and their .mp4.sha files; only changed pages run status.
  2. Run it twice. The second run should show every page skipped and finish a few seconds after git fetch, with nothing copied.
  3. Check the folders. Every gallery video is in your checkout's explainers/, git status there is clean, and VS Code shows no changes for thunar-explainers.

Glossary

Gallery
The folder ~/thunar-explainers, a git worktree where videos-all.sh renders every video.
Checkout
Your own working copy of the repo, the one the script lives in.
Decide
The part of the run that works out, per page, whether to skip, re-narrate or render.
.mp4.sha
A small file next to each video with the hashes of what it was rendered from.
status
make-video.py status: loads the page in Chrome to check the narration still matches it.
Headless shell
Playwright's stripped-down Chrome, which starts faster than full Chrome.
Worktree
A second folder checked out from the same git repo.
Open finding
A problem CI's review reported that isn't fixed or accepted yet; medium or high ones fail the job.
Incremental review
A CI review of only the commits since the last reviewed one.
cmp
A command that tells whether two files are byte-for-byte the same.
