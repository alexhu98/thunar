PR #13: an independent code review on every push

Branch 11-ci-review → main, closes #11. Once merged, every push to a PR gets a fresh Claude review in CI: by default it fixes what it confirms in a claude[bot] commit, or it suggests the fixes, and it reports every finding in the PR comment.

Part 1

What this PR adds

Two new jobs in .github/workflows/build.yml: review reviews the push with no token that can write, and review-report pushes the fix, posts suggestions and writes the report. Three scripts in .github/scripts/ do the work.

review job (reads only) review-report job (can push) you

The big picture

Until now the only code review ran inside the same session that wrote the code, so it shared that session's assumptions, and it ran before the last fixes were pushed. Now CI reviews exactly the commit that was pushed, from a clean checkout, with no memory of how the code was written. Cloud agents (#7) will open PRs that nobody has read yet, so they need this from their first push.

The reviewer never holds a token that can push. Claude only edits the working tree of a read-only job; a second job takes that edit as a patch, checks it, and pushes it with its own token.

Step by step (numbers match the diagram)

① review job
  1. You push. Any push to a PR from this repo starts the workflow. The head commit's trailer picks the mode: none means auto-fix, Review: suggest means suggested changes only. PRs from forks skip the review, since they get no secrets.
  2. Plan. review-proof.sh plan waits up to 30 minutes for an earlier run's report, then reads the saved state from the PR comment. It reviews only the commits since the last reviewed one, skips a push that changed nothing but explainers/, and writes the diff, the issue, the still-open findings and the prompt.
  3. Review. anthropics/claude-code-action runs Claude Opus 5.5 with read-only tools. It runs the built-in /code-review skill at xhigh, then hands each finding to a fresh agent that tries to disprove it. Only findings that agent confirms are CONFIRMED. In auto-fix mode Claude then fixes those in the working tree.
  4. Collect. review-proof.sh collect saves the findings (the action's structured output) and the edit as fix.patch, leaving out paths the push can't or mustn't touch, and uploads both as the review artifact.
② review-report job
  1. Push the fix. If every fixed finding is confirmed and fully in the patch, it commits the patch as claude[bot] with the trailer Review: suggest and pushes it with REVIEW_PUSH_TOKEN. That push starts a follow-up review of the bot's own diff, which only reports, so the loop ends there. If the branch moved meanwhile, nothing is pushed.
  2. Suggest. Findings that weren't pushed and sit on lines the PR changes become one-click suggested changes in one PR review.
  3. Report. review-state.py merges the findings into the saved state and pr-comment.sh writes the review section of the PR comment, beside the explainer. The job fails while a confirmed medium or high finding is unresolved; low ones are only reported.
  4. You decide. Pull the bot's commit before pushing again, click "Commit suggestion", or close a finding you keep on purpose with a Review-accept: R23 trailer. A red review never blocks the merge.

A closer look at the controls

Trailers on the head commit

None: auto-fix. Review: suggest: suggestions only. Either one on an empty commit forces a review of the whole PR.

Review-accept

Review-accept: R23, R32 on any commit closes those findings as kept on purpose. An accept-only empty commit skips the review, so it costs nothing.

The saved state

A hidden JSON line in the PR comment holds every finding with its R number and status: fixed, suggested, not fixed, resolved, accepted or unconfirmed.

What the fix never touches

.github/ workflows and scripts (the report runs the scripts with the push token, so their fixes are only suggested), explainers/, and CLAUDE.md, .claude/ and similar files, which the action resets.

What fails the job

Only a confirmed medium or high finding still open. A zero-finding bar never converged on this PR, so low ones are reported, and fixed in auto-fix mode, without failing it.

Don't re-run the report alone

Re-running review-report by itself after a good review has no guards: it can report a pushed fix as not pushed. Push a fix or an accept instead.

Code review

After the last code fix of the review logic, a fresh general-purpose agent given only the diff and #11 reviewed the branch at d12ce0ed6, at about medium depth. It found 4 issues: 1 is fixed in this PR, 3 are left open.

  • Fixed: the bot could push a fix to the review scripts, which the report job then runs while holding the push token. Fixes to .github/scripts/ are now only suggested.
  • Left open: a Review: trailer on an explainer-only commit forces a whole-PR review; GitHub's "Update branch" makes the next review cover the whole PR; and in an auto-fix round, suggestions for unfixed findings land on the pre-fix commit.

CI's own review ran on every push of this PR, 34 CI runs in all. It reported 230 findings: the bot fixed 88, 32 were resolved by later commits, 14 were accepted as kept on purpose, and 83 were never confirmed; 13 low or unconfirmed ones are still listed. The full list is in the PR comment's review section.

  • It doesn't converge on its own code. Each fix to these scripts, even two lines, brought about five new confirmed edge cases. That is why the loop was stopped by hand and why only medium or high findings now fail the job.
  • Kept on purpose: re-runs of the report alone aren't guarded; a force-push back to an older commit isn't reviewed again; the PR comment has no size cap (22.7 KB after 200 findings, of 65 KB).

Glossary

Finding
One problem the review reports, numbered R1, R2, … across the whole PR.
CONFIRMED / PLAUSIBLE
Confirmed: a second, fresh agent reproduced the failure. Plausible: it couldn't, so nothing is fixed for it.
xhigh
The second-deepest level of /code-review; deeper finds more and takes longer.
Trailer
A Key: value line at the end of a commit message, like Review: suggest.
Auto-fix
The default mode: confirmed findings are fixed and pushed as one claude[bot] commit.
Suggested change
A PR comment with a code block GitHub can apply with one click, "Commit suggestion".
Follow-up review
The review of the bot's own fix commit; it only reports, which ends the loop.
Review-accept
A trailer that closes findings you keep on purpose, so they stop failing the job.
REVIEW_PUSH_TOKEN
A repo secret: a fine-grained GitHub token that may push to this repo's branches, used only by review-report.
Artifact
Files one CI job uploads for a later job to download; here the findings and the fix patch.
Structured output
The action's answer as JSON that matches a schema, instead of free text.
PR comment
The one comment CI keeps on each PR, marked <!-- pr-proof -->, with an explainer section and a review section.
