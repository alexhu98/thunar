PR #76: release only when packaged files changed

Branch 73-release-if-packaged → main, closes #73. A push to main that changes only CI, agent setup or explainers no longer builds, verifies or publishes a new +localN release.

Part 1

What this PR adds

The build job's change check, which ran only on PRs, now also runs on a push to main and compares it with the latest release tag. One file changes: .github/workflows/build.yml.

new check on push unchanged release path what you see when it skips

The big picture

Every push to main built, verified and published a release, even when nothing that goes into the debs had changed. The last four releases, local17 to local20, held the same Thunar as local16. Each one cost about 95 Actions minutes, made the auto-deploy reinstall an identical Thunar on both machines, and added a release to read past.

The push is compared with the latest release tag, not with the previous commit. So changes from a skipped push still count at the next push, and the next release includes them.

Step by step (numbers match the diagram)

① Push to main: the change check
  1. Find last tag. The build job's changes step lists the repo's v* tags and picks the one with the highest +localN, the same way publish-release.sh does.
  2. Diff with it. The checkout is one commit deep, so the step fetches only that tag, one commit deep, and runs git diff --name-only between the tag and the pushed commit.
  3. Anything packaged? It removes the paths that never reach the debs: .github/, .claude/, .gitlab/, explainers/, verify/, deploy/, .gitlab-ci.yml, CLAUDE.md, .clang-format and .gitignore. Everything else counts, so a new top-level file counts by default.
  4. Nothing: skip. The step sets skip=true and writes “No release: no packaged files changed since <tag>” to the run summary. Every later build step, the version stamp and the whole verify job, which holds publish and prune, are skipped.
② Something packaged, or no tag: as before
  1. Build. When any packaged file changed, or there is no release tag, or the fetch or diff fails, skip is false and the job stamps the next +localN and builds as before.
  2. Verify, release. The verify job installs the debs, runs the smoke test and the verify scripts, publishes the release and keeps the last 10, unchanged.

What counts as packaged

Doesn't count

CI and agent setup, explainers, verify scripts, deploy scripts, CLAUDE.md and editor config. None of them goes into a deb.

Counts

Sources, build files, debian/, po/, icons/, docs/, and README.md, NEWS and the other docs the packaging installs.

PRs unchanged

On a PR the old rule stays: a PR that changes CI scripts still builds and verifies, so those scripts get tested before they reach main.

Part 3

What comes later: #58

This PR removes the push runs that need no release. #58 then shortens the ones that remain, by reusing the merged PR's debs.

built by this PR not built yet

#58 Reuse the merged PR's debs (next)

  1. Find the merged PR's build. On a push that does change packaged files, look up the PR and its last good build run.
  2. Reuse its debs. When the trees match, download its debs and skip the rebuild and verify. Its open question is the version stamp, which is written at build time.

Glossary

+localN
The suffix of this fork's release versions; N goes up by one each release.
Release tag
The git tag, like v4.20.10+local21, that marks the commit a release was built from.
Packaged file
Any file that can end up in, or change, the thunar, thunar-data or libthunarx debs.
skip output
The build job's true/false flag that the later steps and the verify job read.
Run summary
The text a workflow run shows on its page in the Actions tab.
Shallow clone
A checkout with only the latest commit, which is why the tag is fetched separately.
