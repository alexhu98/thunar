PR #114: Rename files in place, like Nemo

Part 1

What this PR adds

A new preference, Rename files in place, on by default: F2 on one file in the details view edits its name in the list, through the same rename job as the dialog.

new in this PR existing behavior, kept

The big picture

Thunar always renamed a single file in a separate box: a dialog, and since #15 a popover under the name. Nemo and most file managers instead let you edit the name right where it's shown. This PR adds that as an option, on by default, in Preferences → Behavior.

Thunar already had the code to start editing a file's name in its row; nothing ever asked for it. This PR switches it on for the details view and handles what the user types.

Step by step (numbers match the diagram)

① Details view — edit the name in place
  1. F2 or Rename…. In thunar-action-manager.c, a rename of one file first checks the misc-rename-in-place preference, that the file isn't a .desktop launcher, and that the current view is the details view; then it calls the new thunar_standard_view_rename_in_place.
  2. Scroll into view. If the file's row isn't on screen, the view scrolls to it at once, as #15's popover does. Editing then starts in a low-priority idle callback, after the scroll has been drawn, so the entry lands on the row and not where it used to be.
  3. Entry in Name. The name cell is made editable just for this call and GTK opens a text entry in it. The entry goes in the Name column wherever it is, not in the first column. The name is selected without its extension (all of it for a folder), with the same function as the dialog.
  4. Enter renames. Enter, or a click elsewhere in the window, renames through thunar_application_rename_file_start: the one function the dialog, the popover and the in-place rename now share, so Ctrl+Z, the operation log and the "Failed to rename" error dialog work as before. Escape, closing the tab or switching to another window cancels. An empty name, one with /, or one longer than 255 bytes keeps the entry open with an error icon.
② Everything else — as before
  1. Popover (#15). The icon and compact views, the preference turned off, or editing that couldn't start (the folder was still loading, say) open #15's rename popover instead, but only while the view is still on screen and showing the file's folder.
  2. Dialogs as now. A .desktop launcher still asks Rename Launcher Options first, a rename asked for over D-Bus still opens the dialog, and F2 on several files still opens Rename Multiple Files.

What each key does in the entry

You doWhat happens
Type a new name, press EnterThe file is renamed; Ctrl+Z renames it back.
Click elsewhere in the windowRenames too, like Enter.
Press EscapeNothing is renamed; the old name comes back.
Enter on an empty name, one with /, or one longer than 255 bytesThe entry stays open with a red error icon; nothing is renamed.
Enter on a name that's takenThunar's "Failed to rename" dialog; the old name stays.
GTK closes the entry itself (the row changes or is re-sorted)Editing starts again on that row, with what you typed kept.
Switch window (Alt+Tab) or close the tabTreated like Escape: a half-typed name is never saved.

Why only the details view

Details view: in place

A GTK tree view. Its entry sits exactly in the Name cell, and a long name scrolls inside it.

Icon and compact: popover

Their grid comes from libexo's ExoIconView, which puts the entry one row too high once the view is scrolled and clips the name's first letter.

The issue allows it

#16 says those views fall back until ExoIconView editing works. They fall back to #15's popover, which points at the file.

The scroll-into-view check copies the popover's, and the popover is where every case this PR can't edit in place goes.

Code review

A fresh agent ran /code-review high --fix against origin/main before the first push: 6 findings. It fixed 1 and skipped 5; the building session then fixed 2 of those, and this page answers 1.

  • Fixed by the review: it removed an explanatory code comment the PR had added, as this repo's rules ask.
  • Fixed after: a cancel started by GTK itself, such as a thumbnail loading, would have saved a half-typed name. Now a cancel renames only when the entry lost focus to a click elsewhere.
  • Fixed after: Rename… from the context menu wasn't tested; verify/16.sh now does it.
  • Left as is: the entry doesn't check a name's length itself; the rename job's error dialog reports a name that's too long.
  • Left as is: Ctrl+Z while typing runs Thunar's file undo, as it does in #15's popover; that's outside this issue.
  • Answered: the missing explainer is this page.

Then CI reviewed the first push, head 60d59c5, in run 43293478571 (Opus at high, 12 minutes): 8 findings. CI fixed R1–R6 in its own commit, d9fa615; the building session fixed R7 and R8 in the next push, which CI hasn't built or run yet.

  • R1, medium, fixed by CI: switching window (Alt+Tab) or closing the tab mid-edit saved a half-typed name. Now only a click elsewhere in the active window renames; Escape, closing the tab and leaving the window don't.
  • R2, medium, fixed by CI: when GTK cancelled the edit itself, because the row changed or was re-sorted, the typed name was silently dropped. Editing now restarts on the row with the typed text kept.
  • R3, low, fixed by CI: the idle fallback could open the popover after the view was hidden or showed another folder; it now checks both.
  • R4, low, fixed by CI: the details view's scroll still used the first column; now the Name column.
  • R5, low, fixed by CI: the rename job's create-and-launch steps were written twice; the dialog, the popover and the in-place rename now share thunar_application_rename_file_start.
  • R6, low, fixed by CI: an explanatory reason in a doc comment, removed.
  • R7, low, fixed in the next push: the pending rename idle is now removed when the view is disposed, beside the drag timers.
  • R8, low, fixed in the next push: a name longer than 255 bytes now keeps the entry open with an error, like an empty name; the dialog's filename box refuses it too. This replaces the local review's "left as is" on length.

Glossary

In-place rename
Editing a file's name right where the list shows it, with no separate box.
Entry
A one-line text box you type into.
Details, icon and compact views
Thunar's three ways of listing files: a table, a grid of icons, and columns of small icons.
ExoIconView
The grid widget from the libexo library that draws Thunar's icon and compact views.
Tree view
GTK's table widget, which draws the details view.
Idle callback
Code GTK runs once it has nothing more urgent to do, such as drawing.
Popover
A small bubble inside a window, pointing at what it belongs to; #15's rename box.
.desktop file
A launcher: a text file describing an app, with its own display name.
D-Bus
The message bus other programs use to ask Thunar to do things, such as rename a file.
Operation log
Thunar's record of file operations, which Ctrl+Z undoes.
Xvfb
A virtual X display with no screen, used to run Thunar in tests.
