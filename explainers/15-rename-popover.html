Part 1

What this PR adds

F2 in a Thunar window now asks for the new name in a popover attached to the file, not in a dialog the window manager places on its own. Renames requested over D-Bus keep the dialog, which now opens over a Thunar window. The code is in thunar-dialogs.c, thunar-application.c, thunar-action-manager.c and the views.

changed by this PR you

The big picture

The rename dialog had no parent window, so the window manager put it wherever its own rules chose, often on another monitor. It also never grew past 500 px, so long names were cramped.

A popover is drawn inside its window, so it can't land on another monitor. And because it needs a widget to point at, it is used only when the rename comes from a view; everything else keeps the dialog.

Step by step (numbers match the diagram)

① F2 on one file in a Thunar window
  1. You press F2. The window's action manager now passes its current view to thunar_application_rename_file, instead of only the screen. The side pane and the location bar pass themselves, so they still get the dialog.
  2. Find the row. The new thunar_view_get_file_rect asks the view where the file's name is. The details view takes the row's Name cell and, if the row is partly or fully out of view, scrolls it in first. The icon and compact views can't say where an item is yet, so the popover points at the middle of the view.
  3. Popover. thunar_dialogs_show_rename_file builds the same icon, label, entry and Cancel / Rename buttons as the dialog, in a GtkPopover placed below the name; GTK flips it above when it doesn't fit. Its width fits the whole name, at least 300 px and at most 90% of the window; longer names scroll inside the entry.
  4. You answer. The name is selected without its extension. Enter renames, Escape or a click outside cancels, and Rename is greyed out while the name is invalid. The popover doesn't block anything while it waits: the rename starts when you answer, through a callback that sets up the same error handling as before, and the keyboard focus goes back to the file list. Each window can have its own popover open, and a second F2 in the same window is ignored.
② The cases that keep a window
  1. .desktop file. The "Rename Launcher Options" question used to open on its own; it is now a dialog of the Thunar window, centered over it. Rename File then opens the popover.
  2. D-Bus rename. A rename asked for over D-Bus has only a screen. It now looks for a Thunar window on that screen and opens the dialog over it, with the 90% width cap; with no window it opens as before.

Code review

A fresh general-purpose agent in this session, given only the diff and issue #15, reviewed it at high effort: 1 medium and 2 low findings, all fixed. The build and the tests were run again afterwards.

  • Fixed (medium): F2 pressed while the popover was open opened a second popover on top of it, because the window's shortcuts still work under a popover. A second F2 is now ignored, and verify/15.sh presses it.
  • Fixed (low): the dialog, now tied to a window, could be destroyed with it and leave a stale handler on the file; the handler now goes away with the dialog.
  • Fixed (low): closing the window while the launcher question or the popover is open could free the file or the view; the rename now holds both until it ends.

CI's review of f79a85a (level high) reported 9 findings, in the code review PR comment, the second of CI's comments. The fixes are in the next commit, and verify/15.sh was run again on it.

  • Fixed (high): for a D-Bus rename, the reference taken on the screen was released on the window instead (R1).
  • Fixed (medium): an open popover blocked F2 in every Thunar window (R2). A folder's name is now selected whole (R3).
  • Fixed (low): a Name column scrolled out sideways is scrolled back in (R4), and the new comments are gone (R9).
  • Accepted (low), as you decided: scrolling by hand, because GTK's own scroll is animated (R5); the window search, which nothing else does (R6); the middle of the icon views, as the issue asks (R7); the width fit, which jumps straight to the right size (R8).

CI's review of fbd4ada reported 6 more findings. The fixes are in the next commit, and verify/15.sh was run again on it.

  • Fixed (medium): with one popover per window, two windows could each wait on the other's popover (R10). That first closed the open popover when F2 was pressed in a second window; the next round replaced this.
  • Fixed (medium): the window found for a D-Bus rename is held while the launcher question is open (R11).
  • Fixed (low): a Name cell starting at the right edge is scrolled fully in (R12); a second F2 on a launcher no longer asks its question again (R13); the name selection lives in one function (R14).
  • Accepted (low): the selection is made again each time the entry gets the focus (R15), like GTK's own select-on-focus.

CI's review of af9a56e confirmed 4 findings: the close-and-retry of step R10 lost a name you were typing and could retry before the first popover was gone (R16, R17, R19), and the two-window test couldn't tell (R18). You chose to drop the nested main loop instead.

  • Fixed, as you decided: the popover no longer waits in a nested main loop, so each window renames on its own and nothing is cancelled (R16, R17, R19, and R20 and R21, whose code is gone). The test now types a name in both popovers and checks both renames (R18).
  • Accepted (low): the rename popover's name selection skips the create dialog's extension rules on purpose, since a folder or a name without an extension is selected whole (R22).

Glossary

Popover
A small bubble drawn inside a window, with an arrow pointing at the thing it belongs to.
Nested main loop
Running GTK's event loop again inside a function, so it can wait for an answer; this PR stopped using one for the popover.
Transient dialog
A dialog tied to a parent window; the window manager keeps it over that window.
D-Bus
The message bus other programs use to ask Thunar to do things, such as rename a file.
.desktop file
A launcher: a text file describing an app, with its own display name.
Details, icon and compact views
Thunar's three ways of listing files: a table, a grid of icons, and columns of small icons.
Xvfb
A virtual X display with no screen, used to run Thunar in tests.
