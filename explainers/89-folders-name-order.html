PR #91: Folders listed first always sort by name

Branch 89-folders-name-order → main, closes #89. With Sort folders before files on, the folders at the top always stay in natural name order, A to Z (Alpha, dir2, dir10), whatever column or direction you sort by. The files below them still follow your sort.

Part 1

What this PR adds

A few added lines in each of Thunar's two sort functions compare two folders by name first, and verify/89.sh checks the order of every row under six different sorts.

already in Thunar, unchanged new in this PR

The big picture

With Sort folders before files on, Thunar already put every folder above every file. But inside the folder group it used the same column and direction as the files, so sorting by Size or Date, or going Z to A, reshuffled the folders too, and a folder you know was hard to find. Issue #89 asks for the folders to stay in name order, A to Z, always.

Thunar sorts by asking one function, again and again, "which of these two rows comes first?". The fix is in that question: when both rows are folders, the answer is now always their names, A to Z.

Step by step (numbers match the diagram)

① How Thunar orders two rows — the fix
  1. Pick a sort. You click a column header in the detailed view, or choose View → Arrange Items. Thunar re-sorts the folder's rows with its compare function: thunar_list_model_cmp_func for the icon and compact views, thunar_tree_view_model_cmp_nodes for the detailed view.
  2. Folder vs file. When Sort folders before files is on and one row is a folder and the other a file, the folder comes first. This check was already there and is unchanged.
  3. Two folders. New: when both rows are folders, the function returns thunar_file_compare_by_name and skips the sort direction (sort_sign). That is Thunar's own natural name compare, so dir2 comes before dir10, and the case-sensitivity setting still applies. When two folders have the same name, for example in search results from different places, it falls back to the chosen column and direction rather than calling them equal.
  4. Two files. Files still go through the chosen column's compare times the direction, as before. With Sort folders before files off, steps 2 and 3 never run, so nothing changes.
② verify/89.sh — how it is checked
  1. Test files. The script makes folders Alpha, dir2 and dir10 and files a.txt (2000 bytes), b.txt (100) and c.txt (3000), with dates and contents chosen so that no other column gives the name order.
  2. Relaunch sorted. For each sort it quits Thunar, sets last-sort-column and last-sort-order with xfconf-query, and opens the folder again in the detailed list view.
  3. Check each row. It clicks each row in turn, copies it, pastes it into a fresh folder in a second window, and checks that the pasted name is the one expected for that row. It waits until the pasted folder's contents match the original, so a slow copy isn't misread. A wrong order fails the test.
  4. Six sorts. Name ascending, Size descending, Date Modified ascending, Name descending, Size descending in the icon view, and Name descending with Sort folders before files off, which must look as before. Each ends with a screenshot.

The same lines go into thunar/thunar-tree-view-model.c, with model in place of store, so all views agree.

Worth knowing: in the detailed view the column header's arrow still shows the column and direction you chose. That now describes only the files. Sorted by Name descending, the folders read A to Z while the files read Z to A. You confirmed both in the issue.
The location bar's path completion uses the same list with folders first, so its folder suggestions are now also in name order.
To undo it, revert this PR. No setting is added or stored. Upstream merges (#30) will meet a small local change in two compare functions.

Code review

A fresh general-purpose agent, given only the diff and the issue, reviewed the PR in this session. It found no correctness problems and raised one risk, which was kept as is.

  • Correct sorting: the compare still gives one consistent order, which Thunar's sorted insert and re-sort rely on. sort_sign elsewhere only reports the chosen direction.
  • Also affected: path completion in the location bar uses folders first too, and now lists folders by name.
  • Risk, kept: 30 row checks might get near the test's 120 s limit. The local run took 70 s, so it stays as is.

CI's own review, at high, on the first push found six possible issues, none confirmed: R1 medium, R2 to R6 low. They are listed in the code review comment on this PR.

  • Fixed, R1: two folders with the same name now fall back to the chosen column instead of counting as equal.
  • Fixed, R3, R4, R6: the test now checks the icon view, says the folders were reversed before #89, and waits for each copy to finish.
  • Waiting on you, R2: with folders first, folders ignore Date Deleted in Trash, Recency in Recent and Location in search results.
  • Waiting on you, R5: the folders-first lines are copied in the list and tree models rather than shared in one helper.

Glossary

Sort folders before files
Thunar's preference (misc-folders-first) that lists all folders above all files.
Natural order
Name order that reads numbers as numbers, so dir2 comes before dir10.
Compare function
The function a sort calls to decide which of two rows comes first.
sort_sign
1 for ascending, −1 for descending; Thunar multiplies a compare's answer by it to flip the order.
Tree view model
The list behind the detailed view, which can also show expanded subfolders.
xfconf-query
The command that reads and sets Xfce settings, such as Thunar's last sort column.
Xvfb
A virtual screen with no monitor, where the tests run Thunar and take screenshots.
Shot pair
A before and an after screenshot that CI joins into one image in its verify comment.
