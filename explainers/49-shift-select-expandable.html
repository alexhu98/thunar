Part 1

What this PR adds

The list view's own Up/Down handling still moves the cursor, so it still steps into expanded folders and skips their "Loading…" rows. Afterwards it now looks at Shift and Ctrl and fixes up the selection. All of it is in thunar/thunar-details-view.c.

added by this PR existing Thunar code, unchanged you

The big picture

With Expandable folders on, Thunar's list view handles the arrow keys itself instead of leaving them to GTK, so that the cursor can step into an expanded folder and skip the "Loading…" row a folder shows while it reads. That code ignored Shift and Ctrl: every press moved the cursor and selected only the new row. You use list view with Expandable folders on, so Shift+arrows never worked for you.

GTK's own key handling was not switched back on for Shift and Ctrl, because it would stop on "Loading…" rows. Thunar can't hold a selected row without a file, so the range is selected file by file instead.

Step by step (numbers match the diagram)

  1. You press. Up or Down in list view, with Expandable folders on, plain or with Shift, Ctrl or both. Before moving, the key handler notes where the cursor was, and with Ctrl, which rows were selected.
  2. Move the cursor. thunar_details_view_key_up_set_cursor and …_key_down_set_cursor run unchanged. Like any cursor move in GTK, this leaves only the new row selected.
  3. Read modifiers. With no modifier nothing more happens, so plain arrows behave as before. With Ctrl, thunar_details_view_select_after_move puts the saved selection back, so Ctrl+Space can then add the cursor row.
  4. Shift: a range. The anchor is the row the cursor last reached any way other than a Shift or Ctrl arrow: a click, a plain arrow, Home, End or typing a name. thunar_details_view_select_files_between walks the visible rows from the anchor to the cursor and selects each one that has a file. With Ctrl too, the range is only added to what was selected, as #49 asks. Ctrl+Space also moves the anchor to the row it toggles.

Code review

A fresh general-purpose agent in this session, given only the diff and issue #49, found no leaks or crashes, 1 medium and 3 low findings. Three were fixed; the build and tests were run again afterwards.

  • Fixed (medium): a Shift run could reuse an old anchor after plain arrows came back to the same row. verify/49.sh checks it.
  • Fixed (low): the status bar was updated once per selected row; it is now updated once per key press, as Invert Selection does.
  • Fixed (low): the range could run past an anchor hidden inside a collapsed folder; the walk now stops at the anchor.
  • Kept (low): Shift+End, Shift+Page Down and Shift+click are still handled by GTK, which starts them from the cursor, not from this anchor. GTK has no way to set its anchor.

CI's review of 942653b (level xhigh) reported 12 findings, 3 of them medium, and pushed fixes for 10 of them as commit 0ad37fa. The build, verify/49.sh and the screenshot audit were run again on it. Its findings are in the code review PR comment, the second of CI's comments.

  • Fixed (medium): the anchor now follows every cursor move except a Shift or Ctrl arrow, through GTK's cursor-changed signal, so Home, End, Page Up and typing a name also reset it (R1, R7).
  • Fixed (medium): Ctrl arrows keep the anchor, as GTK does, and selection updates are held back for the whole move, so the status bar never shows only the cursor row first (R2, R5).
  • Fixed (low): a right-click on a selected row keeps the anchor (R3), plus tidy-ups to helpers, alignment and comments (R9–R12). Its R6, Shift+Ctrl shrinking on reverse, was taken back in the next round.
  • Not fixed: R4 is the GTK anchor limit above; R8, copying the selection on each Ctrl arrow, was not shown to be slow.

CI's review of 0ad37fa confirmed 2 more medium findings, fixed in a8b6809 and checked in verify/49.sh:

  • Fixed (medium): Ctrl+Space toggles a row without moving the cursor, so the anchor stayed behind; it now moves to that row (R13).
  • Fixed (medium): R6's shrink step also unselected rows chosen before the range began. Shift+Ctrl now only adds, as #49 asks (R14). A right-click on a row that isn't selected resets the anchor (R16).
  • Left as is (low): R21 and R22 are bugs in the Right key's existing code, outside this PR; the rest are minor or unconfirmed.

CI's review of a8b6809 confirmed 1 more medium finding, fixed in 777188a:

  • Fixed (medium): the R16 change also dropped the anchor on a right-click on a selected row, which R3 had fixed; it is kept again, and verify/49.sh checks it (R27). Ctrl with the keypad's Space key moves the anchor too (R28), and a middle-click, which opens the row, still resets it (R32).
  • Kept as #49 asks (low): GTK's own Ctrl+Shift arrows only move the cursor; here Shift+Ctrl adds the range, as the issue specifies (R29).

Glossary

Expandable folders
A list view option that shows a folder's contents under it, as a tree.
Loading row
A placeholder row with no file, shown in a folder while Thunar reads it.
Cursor
The outlined row that the arrow keys move; it need not be selected.
Anchor
The row a Shift range starts from: where the cursor last landed other than by a Shift or Ctrl arrow.
GTK
The toolkit Thunar's windows are built with; it has its own arrow-key handling.
Xvfb
A virtual X display with no screen, used to run Thunar in tests.
xdotool
A tool that moves the pointer, clicks and presses keys in X windows from a script.
