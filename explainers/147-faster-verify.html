Part 1

What this PR adds

CI's verify job now picks which tests to run, numbers and posts shots only for the tests a reader needs, uploads them in one commit, and runs four tests at a time. The changes are in build.yml, verify-proof.sh, verify-shots.py, shots.sh and the rules in CLAUDE.md.

CI, on every run the agent, once before the merge

The big picture

Every push to a PR runs the whole test suite in CI's verify job, takes about 274 screenshots and uploads each one as its own commit. A full run took about 25 minutes: 3.5 for the build, then about 12 for the tests and 9.5 for the upload and comment. Most runs are early pushes, such as review fixes, and about 3 in 10 are cancelled by a newer push anyway. This PR makes those early runs short and keeps one full run for the head that merges.

Nothing is dropped, only moved: early pushes run the smoke test and the PR's own verify/<issue>.sh, and the merge rule now needs a run of all tests on the head, which the agent starts with a Verify: full trailer.

Step by step (numbers match the diagram)

① Each push to a PR — run and upload
  1. Pick the tests. A new step in build.yml's verify job, “Pick the tests”, lists the files the PR changes. It runs every test on a push to main, when the head commit has the trailer Verify: full, or when the PR changes .github/scripts/verify-*, shots.sh, debian/ or build.yml. Otherwise it runs the smoke test and the verify/<n>.sh scripts the PR adds or changes, and says which in the job summary.
  2. 4 at a time. verify-proof.sh run now takes the tests to run (no names means all), and JOBS goes from 2 to 4. It writes scope (“all 33” or “partial 3 33”) and own, the tests whose shots are posted.
  3. Number shots. verify-shots.py build numbers only the shots of the smoke test, the PR's own tests and any test that failed. Every other test that passed gets its result only; its shots stay in the run's verify artifact.
  4. One commit. shots.sh was rewritten to take a list of files and commit them all to the shots branch at once through GitHub's Git Data API: one blob per file, eight at a time, then one tree, one commit and one move of the branch. When another run moved the branch first, it makes the commit again on the new tip. Every shot's link pins that one commit.
② Report — and a full run before the merge
  1. Verify comment. Its heading says “3 of 3 passed; 3 of 33 tests (partial)” or “all 33 tests”. A partial run adds a sentence on how to run them all, and the tests that passed without posted shots get one line: “28 other tests passed: 3, 4, 5, …”.
  2. Summary, digest. The verify status now carries full. While it is false, pr-summary.py titles the summary “⏳ verify ran only some tests” instead of “ready for review”, and the pr-digest agent prints a “verify scope” line.
  3. Verify: full. Once review is clean and the PR is otherwise ready, the agent pushes a commit with Verify: full in its message's last paragraph, an empty one if nothing is left. CLAUDE.md's merge rule now needs verify to have run all tests on the head.

The upload, before and after

Before: one commit per file

Each shot and pair image was its own contents-API commit, with 2–4 calls each. Two runs committing at once raced, which caused 9 of the 16 infra failures in #147's history.

After: one commit per run

All files, the manifest included, go in one commit. A clash on the branch (HTTP 409 or 422) makes the commit again on the new tip, up to 8 times.

A file that can't be uploaded

It is printed with - and its older copy is removed from the branch in the same commit, so no stale shot stays at its path. The comment marks it missing and the job fails.

Code review

Before the first push, the building session reviewed the branch at high with /code-review --fix: 7 findings. The review fixed 4; of the 3 it skipped, the session fixed 2 by hand and kept 1. CI's own review of each push is in the PR's code review comment.

  • Counting a run as passed: an empty commit result counted as a pass, and the manifest counted as a missing image. Both fixed.
  • Wording: retry messages named the wrong argument, and the pr-digest wording was unclear. Both fixed.
  • Fixed by hand: a failed upload's older copy is now removed from the shots branch, and OWN unset versus empty is documented.
  • Kept: the comments naming a function's arguments follow the existing test_one() { # name, command... pattern.

Part 3

What comes later: the trial PR, then a full run before each merge

No open issue depends on #147. What follows is the rest of its test plan: a trial PR that shows a partial run and a full one, then every PR ending on a full run.

built by this PR not run yet the agent, from then on

This PR's CI run, then the trial PR (next)

  1. Measure four at a time. This PR's own CI runs all tests, because it changes build.yml. Its “Smoke test and verify/*.sh” step is timed against 730–748 s at two; if a test slows by more than 5 s or fails, JOBS goes to 3 or back to 2.
  2. Compare the upload. Its verify comment, verify.tsv and shot links are checked against a run on main; every link should pin one commit.
  3. Trial PR, early push. A throwaway PR adds a trivial verify/<n>.sh. Its first run should run only the smoke test and <n>, post only their shots, and show the ⏳ summary title.
  4. Trial PR, full run. An empty commit with Verify: full should run every test and turn the scope into “all”.
  5. A failing other test. One other test is broken on purpose on that branch; its shots and log tail should be posted.

Every PR after that

  1. Early pushes stay short. Review-fix pushes run the smoke test and the PR's own test, and /visual-verify pr:<n> audits only their shots instead of about 274.
  2. The last push is full. The agent pushes Verify: full once review is clean, and merges only when verify says “all M tests” on that head.

Glossary

verify job
The CI job that installs the built Thunar and runs the screenshot tests.
smoke test
Checks Thunar is still running 10 s after launch; always runs.
the PR's own tests
The verify/<n>.sh scripts the PR adds or changes.
trailer
A Key: value line at the end of a commit message, such as Verify: full.
partial run
A verify run of only the smoke test and the PR's own tests.
shots branch
An orphan branch that holds each PR's screenshots under pr-<n>/.
Git Data API
GitHub's API for making blobs, trees and commits directly, without a checkout.
blob, tree
Git's stored file contents, and the folder listing that points at them.
verify artifact
The run's downloadable bundle of every shot and log, kept by GitHub Actions.
JOBS
How many tests run at once, each with its own Xvfb.
manifest
verify.tsv: one row per shot, with its number, test and what it proves.
