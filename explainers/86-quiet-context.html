PR #87: keep PR sessions' context small

Branch 86-quiet-context → main, closes #86. Noisy commands write to a log and show only their exit code and its end, heavy steps run in subagents that return a few lines, and large files are read in slices, so a PR session re-reads less on every turn and costs less.

Part 1

What this PR adds

A short “Context” section in CLAUDE.md with three rules, a new build-verify agent, and quiet log reading in the visual-verify and explainer skills. No Thunar code changes.

the session does it a subagent does it what reaches the session's context

The big picture

Every turn re-reads the session's whole context, so its cost grows with the context's size. Batch #78's group B session (PR #82) reached about 567k of 1M context tokens, with compaction at 784k, and cost about $33.6; the tooling-only session of #83 sat at about 247k. The likely fillers: build and test output printed straight in, whole-file reads of large sources such as the 7.4k-line thunar-window.c, and heavy steps run inline.

The batch skill's brief now tells each group's session to keep its context small as CLAUDE.md's Context section says, so the rules reach every batch session.

A redirect keeps a command's exit code; a pipe into tail replaces it with tail's own 0. So output goes to a file first, and the exit code is echoed before any of the log is read.

Step by step (numbers match the diagram)

① Logs: every noisy command
  1. Log to a file. dpkg-buildpackage, verify-proof.sh, explainer-proof.sh and make-video.py run as cmd > "$LOG" 2>&1; echo "exit=$?", with LOG a file outside the repo, such as the explainer's ${TMPDIR:-/tmp}/make-video.log, so none of their output lands in the context yet.
  2. Check exit=. The echoed exit code is read first. That's why the rules forbid piping the command into tail, which would show tail's 0 instead.
  3. Tail or grep. On success, tail -n 30 "$LOG". On a failure, the grep that its skill or agent gives (table below): build-verify's for builds and test runs, and the explainer skill's for make-video.py.
  4. In context. The session holds the exit code and a few lines, never a build log of thousands of lines.
② Heavy steps: in subagents
  1. build-verify. The new agent .claude/agents/build-verify.md, modeled on pr-digest, builds the debs from the working tree, installs all three only when $CLAUDE_CODE_REMOTE is true through verify-proof.sh install, which puts them in even over the same version, and runs the smoke test and every verify/<issue>.sh. It has no options to skip a step, so the tests always run against the build it just made; /visual-verify run: captures its shots with that full run, in a cloud container only. It never edits, commits, pushes or reads a PNG.
  2. Local review. The fresh-agent review of the diff runs in a general-purpose agent that returns only its findings list.
  3. Explainer. The explainer skill's new “In a subagent” section hands the page, its render check and the narration to a general-purpose agent, which does the work itself rather than handing it on. A later page fix goes to a subagent too, which renders the page again before stamping. This page was written and updated that way.
  4. Short answer. Each returns a short fixed result, such as page written, narration stamped, with any failing lines copied from the log as they are, so confident wording can't hide a failure.
③ Reads: narrow
  1. Grep first. Before opening a large source file, grep for the function to find its line.
  2. Read a slice. Read only those lines with offset and limit, and don't re-read a file already edited this session.
  3. PNGs elsewhere. The main session never reads a PNG: screenshots go to the shot-auditor, and the explainer's render check runs in its subagent.

Code review

A fresh general-purpose agent, given only the diff and the issue, reviewed it at high and found 7 problems (2 high, 1 medium, 4 low). All 7 are fixed in the PR's second commit:

  • Greps that missed or matched the wrong lines: the build-failure grep matched every -Werror= compile command; CLAUDE.md's one shared grep didn't fit its commands, so each skill or agent now gives its own; and reading make-video.py status with tail could drop stale lines, so a grep now keeps every one.
  • The owner's machine: build-verify could run verify-proof.sh install there; now it installs only when $CLAUDE_CODE_REMOTE is true.
  • Smaller gaps: the render command didn't say to read its log on a failure; the changed-files list for warnings used origin/main's tip and full paths, so it now uses the merge base and basenames; and “never Read PNGs in the main context” clashed with the explainer's render check, which now always runs in its subagent.

CI's first review (run 42726284611, Opus at high, 5 minutes) found 8 findings on 087afb6, all confirmed: R1 medium, R2 to R8 low. All 8 got a fix in one push, and none was accepted:

  • An unset log (R1): the quiet status and stamp command wrote to $LOG, which nothing set, so bash would fail and print exit=1. It now writes to a log file of its own, and CLAUDE.md says LOG is a file outside the repo.
  • The cloud guard (R2): it covered only install, while CLAUDE.md promised it for the tests too. CLAUDE.md now promises it for install only; the tests had their own guard for two rounds, until always building replaced it.
  • The explainer subagent (R3, R4): it could hand the work on again, and later page fixes weren't render-checked. It now does the work itself, and a later fix goes to a subagent that renders the page again.
  • The build grep (R5, R6): it missed linker and Python errors, and the warnings filter left out untracked files. It now also catches undefined reference and Traceback, falls back to the last 30 lines, and counts untracked files.
  • One verify path (R7, R8): two different greps read the same verify output, and /visual-verify run: was a second way to run the tests. run: then captured through build-verify only run, with one grep.

Glossary

Context
Everything a session has seen so far; the model re-reads all of it on every turn.
Compaction
When the context nears its limit, older parts are summarized away, and details are lost.
Cache-read tokens
Context tokens re-read from the cache each turn; cheaper per token, but most of a long session's cost.
Subagent
A helper agent with its own context; only its final answer comes back to the session.
build-verify
The new agent that builds, installs and tests Thunar and returns about 10 lines.
pr-digest
A read-only agent that sums up a PR's CI comments and checks in about 20 lines.
shot-auditor
The subagent that reads every screenshot and reports OK or a problem per shot.
Exit code
The number a command ends with: 0 for success, anything else for a failure.
Merge base
The commit where the branch left main; diffing from it shows only the branch's own changes.
CLAUDE_CODE_REMOTE
An environment variable that is true in a Claude Code cloud container; build-verify installs only then.
No code changed
The step build and verify run, instead of their real steps, on a PR that changes no code.
