Part 1

What this PR adds

One line in thunar/thunar-standard-view.c: a new folder view records its sort as soon as it is created, not when it is first drawn, so the next tab copies the right sort.

Thunar code, unchanged the line this PR adds you old behaviour, gone

The big picture

Each Thunar tab shows a folder in a “view”. A new tab doesn't read the saved sort itself: it copies the sort of the tab you are on. That works when you open tabs one at a time, because the current tab is already on screen. With -t and -T, Thunar opens several tabs in a row before drawing any of them, and the tab being copied hadn't recorded its sort yet.

A view kept its sort in two places: the file list itself, sorted correctly from the start, and a remembered copy that other tabs read. Only the remembered copy was late, and until then it held 0, which means Date Created.

Step by step (numbers match the diagram)

① With this PR
  1. Tab A created. The view's constructor in thunar/thunar-standard-view.c sorts its file list by the sort it was given: for the first tab, the saved last-sort-column and last-sort-order, here Name ascending.
  2. Stores its sort. The new line calls the existing thunar_standard_view_store_sort_column right after that, so the view's remembered sort is Name from the moment it exists. It runs before the view starts listening for sort changes, so it never writes last-sort-column.
  3. Tab B copies it. thunar_window_create_view in thunar/thunar-window.c reads the current view's sort-column and sort-order and passes them to the new tab. It now gets Name, even though tab A hasn't been drawn.
  4. You see Name. Every tab opened by -t or -T lists its files in name order, and the Name column header shows the sort arrow.
② Before this PR
  1. Tab A not drawn. The remembered sort was first stored in thunar_standard_view_realize, which runs when the view is first drawn. With -t, the next tab is created before that.
  2. Reports 0. Until then the remembered column was 0, the first entry of the column list: Date Created, which is hidden by default.
  3. Tab B: no arrow. Tab B sorted by Date Created, oldest first, and passed that on to tab C. No visible header had the sort arrow, so the list looked unsorted.

The change

  /* apply the default sort column and sort order */
  gtk_tree_sortable_set_sort_column_id (GTK_TREE_SORTABLE (standard_view->model), …);
  thunar_standard_view_store_sort_column (standard_view);

  /* stay informed about changes to the sort column/order */
  g_signal_connect (G_OBJECT (standard_view->model), "sort-column-changed", …);

Every new tab

The line is in the view's constructor, so it covers every way a tab is made, such as restoring tabs at startup. Only the -t and -T path was tested.

The draw-time call stays

The same call in thunar_standard_view_realize is now redundant. It is kept so the file stays close to upstream Thunar.

Part 2

How it was built and verified

The building session built the PR in a cloud container and ran all 24 tests, including the new one. The new test was not run against the old build, and three cases from the issue were not checked.

Built on 2 known-good references

The first tab and new windows

They already use the saved sort. The fix makes the tabs after them get the same sort, as the issue asked.

Files created in reverse order

The test creates z.txt, then m.txt, then a.txt, 1.1 s apart. Sorted by Name, a.txt is first; sorted by Date Created, z.txt is.

The new test, verify/126.sh

  1. Folders. Six folders, alpha to zeta, each with z.txt, m.txt and a.txt made in that order. The test stops early if the filesystem doesn't record distinct creation times, since then the two sorts would look the same.
  2. Saved sort. It sets last-sort-column to Name, ascending, then runs thunar --split=50 -t alpha beta gamma -T delta epsilon zeta: three tabs in each pane.
  3. Each tab. For all 6 tabs it clicks blank space, presses Home to select the first row, copies it, pastes into a check folder, and requires that the pasted file is a.txt.
  4. Shots. It screenshots the last tab of each pane, gamma and zeta, showing the files in name order and the Name header's sort arrow.

Glossary

-t / -T
Command-line options that open the folders after them as tabs, in the left or the right pane.
--split=50
Opens the window split into two panes of equal width.
View
The part of a tab that lists a folder's files; its code is in thunar-standard-view.c.
Constructor
The code that runs once when a view is created, before it is shown.
Realize
GTK's step that prepares a widget to be drawn on screen for the first time.
last-sort-column
Thunar's saved sort, updated when you click a column header; new windows start with it.
Date Created
A column, hidden by default, holding each file's creation (birth) time.
Directory-specific settings
An option that remembers a sort per folder, overriding the saved sort.
verify script
A test that drives Thunar on a virtual screen in CI and takes screenshots.
Upstream
The original Xfce Thunar project this fork follows.
