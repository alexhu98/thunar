Part 1

What this PR adds

The status bar text gains "Total: …" and "Free space: …" whenever something is selected, and a size and free space while searching. The work is in thunar-util.c, thunar-io-jobs.c and thunar-standard-view.c.

what you do Thunar's code, changed by this PR what you see

The big picture

Thunar's status bar, the line at the bottom of the window, describes the folder only while nothing is selected. Select a file or start a search and the free space and the folder's counts disappear, replaced by the selection's. Sizes also came with an exact byte count nobody needed. Issue #74 asks for the folder's totals and free space to stay on screen, and for the byte counts to go.

Free space can take seconds to read on a slow network drive, so it never comes from the window's own thread: it comes from a background job, or for a search from one background query. A newer selection cancels the older job, and the job can't write once cancelled.

Step by step (numbers match the diagram)

① Folder or selection changes
  1. Selection changes. A folder finishes loading or you select something. thunar_standard_view_update_statusbar_text runs and first cancels any status bar job still running, holding the status bar text lock while it does.
  2. Pick the case. Nothing selected: a job builds the folder's own text, as before. One file: its name, size and type are shown at once, and a job is started to add the rest. Several files: a job builds "Selection: 2 files: 3.0 MiB".
  3. Background job. One job, thunar_io_jobs_load_statusbar_text, replaces the old folder and selection jobs. It counts the folder's files once and, when something is selected, adds "Total: 1 folder, 3 files: 6.0 MiB" and then "Free space: …" of the folder being viewed.
  4. Status bar. The job writes its text through thunar_standard_view_set_statusbar_text_for_job, under the same lock as the cancel, and only if it hasn't been cancelled. So a slow job can never paste its Total onto a newer selection's text.
② You search (Ctrl+F)
  1. Search starts. The view asks for the free space of the search's root folder once, with g_file_query_filesystem_info_async. The query is cancelled when the search ends, the folder changes or the view closes.
  2. Count results. "3 files found" becomes "3 files found: 6.0 MiB". The sizes are summed from the files the search results already hold, so no disk is read.
  3. Join the parts. The count and the free space are joined with the usual " | ". There's no Total while searching, since the results replace the folder's listing. A selection made during a search keeps the same free space text.

A closer look at the pieces

Count once, format twice

thunar_util_count_files counts folders, files, hidden files and size. The same counts become the nothing-selected text or the "Total: …" part, joined with ", ".

One helper per part

The size text (which honours Size in bytes), "Total: …" and "Free space: …" each come from one helper in thunar-util.c, used by the job and by the search.

Byte counts off by default

The default of misc-status-bar-active-info drops Size in bytes. The status bar's right-click toggle stays, for anyone who wants the counts back.

thunar/thunar-preferences.c, default of misc-status-bar-active-info
-  DISPLAY_NAME | FILETYPE | SIZE
-  | SIZE_IN_BYTES
+  DISPLAY_NAME | FILETYPE | SIZE

Code review

A fresh agent, given only the diff and the issue, found 5 things: 3 are fixed and 2 are kept, as the issue asks for that behaviour.

  • Fixed, medium: a cancelled job kept a reference to the view forever, because disconnecting its handlers also removed the one that released it. The job no longer takes that extra reference; it already holds one.
  • Fixed, low: the trash shot's caption now says Free space shows only if the trash reports it, and the pair captions were reworded.
  • Kept, low: each selection change counts the folder again for Total. That is the same work the nothing-selected text does today, and it runs in the background job.
  • Kept, low: the search size is summed on the window's thread. It reads sizes already loaded, with no disk access, as the issue asks.

Glossary

Status bar
The line of text at the bottom of a Thunar window describing the folder or selection.
Size in bytes
A status bar toggle (right-click it) that adds the exact byte count after each size.
misc-status-bar-active-info
The Thunar setting that stores which status bar parts are switched on.
xfconf-query
The command that reads and writes Xfce settings such as Thunar's.
Job
Work Thunar runs on a background thread so the window stays responsive.
Lock (mutex)
Lets only one thread at a time touch the status bar text, so a cancel and a write can't cross.
Reference
A count of who still uses an object; a leaked one keeps it in memory forever.
MiB / MB
Binary (1024) or decimal (1000) size units, picked by the misc-file-size-binary setting.
Xvfb
A virtual screen with no monitor, where the tests run Thunar and take screenshots.
Shot pair
A before and an after screenshot that CI joins into one image in its verify comment.
Shot audit
An agent reads each screenshot and says whether it shows what its caption claims.
