PR #122: Up, Down, Home and End select the file at the cursor after a blank-space click

Branch 120-reselect-at-cursor → main, closes #120. After you click blank space to clear the selection, these four keys now always select a file, even when the cursor can't move further, just like PgUp and PgDn already did.

Part 1

What this PR adds

One new rule in the key handler that every view shares: when nothing is selected, a plain Up, Down, Home or End selects the file at the keyboard cursor. The details view calls the same rule from its own handler.

new or changed in this PR unchanged Thunar code

The big picture

Clicking blank space in a folder clears the selection. Before this PR, pressing Up on the first file, Down on the last, Home at the top or End at the bottom then selected nothing at all, so the keyboard seemed dead until you pressed a key that could move. PgUp and PgDn always selected a file, and issue #120 asked for the other four keys to do the same.

The keyboard cursor (the row with the focus outline) and the selection are separate. A blank-space click clears the selection but leaves the cursor where it was. GTK selects a row only when the cursor moves, so at the first or last row these keys did nothing.
The issue warned that the details view's own key handler runs before the shared one and might swallow Up and Down. It does, with Expandable Folders on, so that handler calls the same helper (lane ②). One helper serves both places, and it checks the keyboard focus itself, so both paths get that check.

Step by step (numbers match the diagram)

① Every view: the shared key handler
  1. Press a key. Up, Down, Home or End, or their keypad versions, with no Shift or Ctrl, while no file is selected, for example right after a click on blank space.
  2. Shared handler. thunar_standard_view_key_press_event in thunar-standard-view.c is connected to the inner widget of every view: details, icon and compact. Its new rule fires only for those keys, unmodified, when the file view itself has the keyboard focus and nothing is selected. Anything else, such as a key on a focused column header, goes on exactly as before.
  3. View moves first. The rule runs the view's own key handler (GtkTreeView in the details view, ExoIconView in the icon and compact views). Where the cursor can move, that moves it and selects the new row, as it always did. At the first or last row it moves nothing and selects nothing.
  4. Select the cursor. The new helper thunar_standard_view_select_cursor_if_none then checks again. If still nothing is selected, it reads the cursor row and selects it, but only if that row holds a file, so a Loading… placeholder under an expanded folder is never selected. Like the rule, it does nothing unless the file view has the keyboard focus. The handler then stops the key, so it isn't handled twice.
② Details view, Expandable Folders on
  1. Details first. With Expandable Folders on, thunar-details-view.c handles Up and Down itself, so it can step into and out of opened folders. Its handler is connected before the shared one, and it stops the key, so the shared rule never sees Up or Down here. Home and End still pass through to steps 2 to 4.
  2. Edge: no move. On the first or last row, its cursor functions return without moving. That part is unchanged.
  3. Same helper. After a plain Up or Down (no Shift or Ctrl at all), the details handler now calls the same helper as step 4, so the file at the cursor is selected. The helper's own focus check covers this path too. Shift and Ctrl with Up or Down keep their own selection code from PR #51 (issue #49).

The new rule, and the focus check in the helper

  if (standard_view->accel_group != NULL && xfce_gtk_handle_tab_accels (…))
    return TRUE;

  if ((event->state & gtk_accelerator_get_default_mod_mask ()) == 0
      && gtk_widget_has_focus (view)
      && (event->keyval == GDK_KEY_Up || … GDK_KEY_KP_End)
      && !thunar_standard_view_has_selected_items (standard_view))
    {
      GTK_WIDGET_GET_CLASS (view)->key_press_event (view, event);
      thunar_standard_view_select_cursor_if_none (standard_view);
      return TRUE;
    }

  return FALSE;

Code review

Before the first push, a fresh agent ran /code-review at level high on the whole branch (origin/main...HEAD). It found 9 problems: the reviewer fixed 2, the building session fixed 2 more, and 5 are accepted as they are. The fixes are in 3ca17d4, and the tests above were run again on it.

  • Fixed, Loading… rows: the helper could select the Loading… placeholder under a just-expanded folder. It now selects a row only if the row holds a file.
  • Fixed, test focus: after each paste into the second window, the test now focuses the test window again, so its screenshots show the right window focused.
  • Fixed, compact view and tidier code: verify/120.sh now checks the compact view too, which the commit message claimed. The new helper's declaration moved next to the other helpers'.
  • Accepted, S1 and S4: hooking GTK's cursor-move signal instead would be a redesign (S1). Reading the cursor by checking the widget type is what thunar_standard_view_highlight_option_changed already does (S4).
  • Accepted, S2 and S3: the “anything selected?” check builds the list of selected rows on each of these key presses, as the selection-changed code already does, and ExoIconView has no cheaper call (S2). The rule always stops these keys, so Home and End in an empty folder no longer reach the scrolled window, which has nothing to scroll (S3).
  • Accepted, S6: an older quirk with Return and Space in the details view. It was there before this PR and is out of its scope.

CI's first code review

CI reviewed head 4110d36 with Opus at level high in 8 minutes (run 43553053572) and found 7 problems, listed in the code review comment on PR #122. It fixed 3 in its own commit 582b134; the owner accepted the other 4. CI skipped reviewing 582b134, its own fix commit.

  • Fixed, R1 (medium): verify/120.sh read the selection with Ctrl+C, but Copy does nothing with no selection, so a stale clipboard could pass a check. Each check now copies a sentinel file first, so an empty selection pastes “sentinel”.
  • Fixed, R2 (low): the blank-space click was never checked to clear the selection. deselect now checks once per window and view that nothing is selected.
  • Fixed, R3 (low): the new rule ran even when the file view lacked the keyboard focus, for example on a focused column header, swallowing the key and selecting a row out of sight. It now also needs gtk_widget_has_focus (view).
  • Accepted, R4: other keys at a view's edge, like Left and Right in the icon and compact views, may still leave nothing selected. Issue #120 covers only Up, Down, Home and End; the owner chose no follow-up issue.
  • Accepted, R5: the “anything selected?” check builds the list of selected rows on each key press. Only the first press after a large selection pays for it, and that press already runs an equal selection-changed pass.
  • Accepted, R6: the helper is called from two places. They cover separate cases: the details view stops Up and Down itself with Expandable Folders on.
  • Accepted, R7: the fixed waits in verify/120.sh could approach its 120 s limit. It took 86 s in CI, 34 s to spare.

Glossary

Keyboard cursor
The row or icon with the focus outline. Arrow keys move it; it can differ from the selection.
Blank-space click
A click in the empty area of a view, below or beside the files. It clears the selection.
Details view
Thunar's detailed list view (Ctrl+2): one row per file, with size, type and date columns.
Icon and compact views
Thunar's grid views (Ctrl+1 and Ctrl+3), both drawn by libexo's ExoIconView.
Expandable Folders
A details view setting: folders get a triangle that shows their contents as indented rows.
Loading… row
A stand-in row under a just-expanded folder until its files are read. It is not a file.
Key handler
A function GTK calls on each key press; returning TRUE stops the key there.
Keypad keys
The arrow, Home and End keys on the number pad, with Num Lock off.
Verify script
verify/<issue>.sh: drives Thunar with simulated keys and clicks on a virtual screen, checks the result and takes screenshots.
Xvfb
A virtual screen with no monitor, so Thunar can run in CI and the container.
Smoke test
CI's basic check that Thunar is still running 10 seconds after it starts.
/visual-verify
A check in which a separate agent looks at every screenshot and says whether it shows what it claims.
S1–S6
Findings of the local review, numbered in its report.
R1–R13
Findings of CI's reviews, numbered in its code review comment: R1–R7 from the first review, R8–R13 from the second.
Accepted finding
A review finding left as it is on purpose, by the owner or under CLAUDE.md's CI review rules.
Sentinel file
A file the test copies whenever the clipboard may still hold another file, so a paste of it means nothing was selected.
